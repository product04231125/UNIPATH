# AI/RAG 팀 합의 요청서

최초 작성: 2026-10-18. 갱신: 2026-10-25. 코드 기준: `develop`의 `535cd69`.
이 문서는 **합의 요청 및 제안**이다. 아래 선택지와 완료 기준을 확정된 API·DB·운영 정책으로
취급하지 않는다. 결정 전에도 RAG의 오프라인 개발·평가는 진행할 수 있다.

## 이번 변경에서 완료한 독립 작업

- 기대 문서·페이지만 맞는 검색을 통과시키던 평가를 보강했다. 실제 검색 청크에 기대
  발췌가 있어야 하며, 지정한 다른 연도 근거가 섞이면 실패한다.
- 기존 36문항과 별도로 연도 혼합을 검사하는 12문항을 추가했다. 이수경로 행도 함께
  찾지만, 표 전체가 같은 청크에 있으므로 행별 숫자 해석까지 검증한 것은 아니다.
- 모델을 호출하지 않고 저장된 답변을 평가하는 도구를 추가했다. 숫자·조건의 지정
  패턴, 상태, 누락 필드, 원문 해시, 인용 ID·본문·URL·페이지·승인·적용 범위를 검사한다.
- 코퍼스 점검 도구가 문서별 빠진 페이지, 출처·입학연도·이수경로·검토 상태를 보고한다.
- 프론트, 백엔드 API·스키마·Rule Engine·공통 설정·DB 마이그레이션은 수정하지 않았다.
- 실제 학교 문서 승인, 공급자 선택, 유료 호출, 학생 데이터 전송은 수행하지 않았다.

## 담당별로 먼저 답할 질문

**이어진(백엔드·통합)**

1. 첫 시연은 로컬 연결로 할지, 승인 DB를 먼저 만들어 Staging으로 갈지?
2. 서버의 생성기 주입과 키·비용·요청 제한 설정은 언제 연결할 수 있는지?
3. 학교 이름→UUID, 문서 적용/승인/철회, 버전·유효기간의 원본 계약은 무엇인지?

**홍요아(프론트·UX·QA)**

1. 첫 시연에서 정상 답변·근거 부족·추가 정보·시간 초과를 현재 채팅 UI로 검증할 수 있는지?
2. 독립적인 질문/정답 검토를 맡을 수 있는지? 개발자가 만든 질문과 분리할 수 있는지?
3. 관리자 화면의 문서 적용이 RAG 승인과 다르다는 표시·사용 흐름을 어떻게 정할지?

**신우철(AI/RAG)**

1. 문서별 출처·조건 검토표와 미확인 목록을 준비한다. 자동 추출을 공식 승인으로 취급하지 않는다.
2. 모델 후보가 정해지면 같은 질문으로 품질·인용·응답 시간·비용을 비교한다.
3. 계약 확정 후 어댑터를 연결하고, 기존 36문항·조건 12문항·추가 답변 평가 결과를 전달한다.

## 제안하는 첫 통합 완료 기준 — 팀 확인 필요

- 검토한 제한 범위의 문서만 사용하고, 승인되지 않은 연도·이수경로에는 답변하지 않는다.
- 현재 `POST /api/v1/assistant/queries`의 필드·상태·reason을 유지한다.
- 합성 질문으로 출처가 있는 답변, 근거 부족, 문맥 누락, 생성기 장애를 UI에서 확인한다.
- 답변에 원문에 없는 숫자·조건·졸업 확정 판정을 추가하지 않는지 사람이 검토한다.
- 연도/이수경로 혼합, 미승인·다른 학교 인용은 회귀 테스트에서 실패해야 한다.
- 응답 시간과 비용은 실제 모델로 측정한 뒤 수용 기준을 확정한다. 현재 문서에서
  특정 비용·정확도·20초 응답을 보장하지 않는다.

## 2026-10-25 프론트 답변 및 코드 대조

사용자가 전달한 홍요아의 답변(정확한 회신일 미확인):
1. 정상 답변·근거 부족·추가 정보·시간 초과 UI는 구현 완료.
2. 질문에 대한 정답/오답 QA라면 수행 가능. 독립 QA의 의미 설명 필요.
3. 문서 적용과 RAG 승인 구분을 사용 흐름에 맞게 설명할 예정.

코드에서는 상태/시간 초과 처리·관련 테스트와 관리자 안내 문구를 확인했다.
본문 검토 UI, UUID 학교 질의 화면 연결, 실제 모델·문서 기반 E2E 완료를 뜻하지 않는다.
독립 QA는 개발용 질문과 별도의 질문/기대 답·근거를 원문에서 먼저 작성하고
실제 답변을 대조하는 작업이다. 문서의 공식 승인 권한이나 책임 수락으로 해석하지 않는다.
[QA 작업 안내](evals/QA_GUIDE.md)를 사용한다.

현재 통합 우선순위: 기존 가져오기 도구로 검토 초안 준비 → 권한자의 원문 검토 →
프론트 UUID 질의 연결 + 백엔드 생성기/비용/전송 정책 연결 → 실제 답변 QA.
기존 10월 18일 독립 작업 목록은 당시 이력이며 이번 갱신은 새 합의를 임의로 확정하지 않는다.
