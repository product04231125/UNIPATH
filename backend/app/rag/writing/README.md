# 편집 가능한 자기소개서와 포트폴리오

선택한 개인 기록·자료로 한국어 초안을 만들고, 학생이 고친 본문을 실제 Word 문단과 표로 내보낸다.
`create`는 새 초안, `improve`는 붙여 넣은 원문을 다시 쓰고 변경 이유를 돌려준다. 원본 기록과 파일은
덮어쓰지 않으며 서버에 초안을 저장하지 않는다.

API 계약은 [docs/api/writing.md](../../../../docs/api/writing.md)에 있다. 앱 화면은 `자료 → 자기소개서·포트폴리오`
(`frontend/lib/features/writing/`)이다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `contracts.py` | 요청, 초안(인용 포함), 내보낼 편집본(인용 없음), 내보내기 프로필 계약 |
| `service.py` | 동의 검사, 기록 고르기·가림, 모델 호출, 인용·원문 검증(틀린 부분만 제외) |
| `docx_export.py` | A4·맑은 고딕 DOCX 생성, 외부 통신 없음 |
| `api.py` | `POST /me/writing-drafts`, `POST /me/writing-exports` |

`python-docx`는 backend 기본 의존성이다(`pyproject.toml`).

## 검증 원칙

- 문단과 표 항목마다 근거 기록의 문장을 그대로 인용해야 한다. 확인되지 않은 인용은 빼고, 남는 인용이 없는
  문단·항목은 초안에서 뺀다. 한 문장이 틀렸다고 초안 전체를 버리지 않는다.
- 인용 일치는 문장 전체의 사실성을 보증하지 않는다. 그래서 앱은 근거를 문단 옆에 보여 주고, 내보내기 전에
  검토 확인을 받는다. 학생이 고친 문장은 다시 검증하지 않으며 그렇게 표시한다.
- 지원 동기·포부·회사 정보는 지어내지 않고 `questions_for_user`로 묻는다.

### 2026년 11월 23일 실제 모델 확인

Vertex `gemini-3.5-flash`(global)로 가상 기록 4개(수업·캡스톤·동아리·어학)를 넣어 확인했다. 결과는 다음과 같다.

- 처음 지시문에서 나온 문제:
  - 기록에 없는 효과("타입 안정성 확보" 등)를 덧붙였다.
  - 기록 문장을 "~만들었다는 경험을 통해"처럼 그대로 감싸 옮겼다.
- 지시문에 좋은 예·나쁜 예와 마지막 자기 점검 규칙을 넣은 뒤 결과:
  - 앱 기록 형식(`title:`, `detail:`, `result:`)으로 4번 실행했다.
  - 이런 문장은 한 번도 나오지 않았고, 기록에 없는 성과 표현도 없었다.
  - 공고와 문항 2개, 700자 제한을 준 자기소개서는 17~20초 걸렸다.
- 기록이 적으면 글자 수를 채우지 않고 짧게 쓴다. 지원 동기 등 빠진 내용은 질문으로 돌려준다.
- 로컬 웹 앱에서 생성, 근거 보기, Word 내려받기(A4·맑은 고딕)까지 확인했다.

팀원의 첫 구현(PR #98)은 실제 모델로 자기소개서 9.5초, 포트폴리오 12.4초, 다듬기 17.0초를 기록했다.
