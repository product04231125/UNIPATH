# 직무 대분류 + 세부 검색 — 2026-11-22

## 왜 바꾸나

검색어 하나만으로 고용24를 찾고 공고 **제목**에 그 단어가 있는지로 직무를 골랐다. 그래서 일반 단어("지원")는
장애인 활동지원사·경영지원 공고까지 통과했고, 제목 표기와 다른 단어("프런트엔드")는 0건이 됐다. 팀 결정(이어진)으로
채용 사이트처럼 **큰 분류는 학생이 고르고, 세부 검색어는 그 안에서 찾는** 방식으로 바꾼다.

대분류는 고용24 자체 직종 분류(1차 13개·2차 114개)를 그대로 쓴다. 고용24가 공고마다 기업이 고른 직종으로 먼저 거르므로
분류 밖 공고는 섞이지 않는다. 표는 `data/work24_occupations.json`(출처·확인일 포함)이다.

## API

`GET /api/v1/me/job-categories` (로그인 필요)

```json
{
  "source": "고용24 채용정보 상세검색 직종 분류(type=worknet)",
  "checked_on": "2026-11-22",
  "categories": [
    {"code": "02", "name": "연구 및 공학기술", "children": [
      {"code": "024", "name": "소프트웨어"},
      {"code": "025", "name": "네트워크 시스템 및 정보보안"},
      {"code": "026", "name": "데이터 및 정보시스템·웹 운영"}
    ]}
  ]
}
```

`POST /api/v1/me/job-recommendations` 요청에 `category_codes`를 추가했다.

- `category_codes`: 위 표의 1차 또는 2차 코드, 중복 없이 최대 10개(고용24 직종 선택과 같은 상한). 목록에 없는 코드는 422.
- `keyword`: 세부 검색어. 대분류를 골랐으면 비워도 된다. 둘 다 비면 422("직무 대분류를 고르거나 세부 검색어를 입력해 주세요.").
  쉼표로 여러 개를 넣는 기존 방식은 그대로다.
- 대분류 없이 `keyword`만 보내면 지금과 같이 동작한다(제목 기준 선별).

응답 추가 필드:

- `query.occupation_codes`, `query.occupation_label`(예: `소프트웨어 · 데이터 및 정보시스템·웹 운영`)
- `category_browse_available`: 고른 대분류 안에 세부 검색어와 맞는 공고가 없을 때 `true`(`items`는 빈 목록,
  `status=no_results`). 수집 자체가 실패했을 때는 `false`다.
- `search_notice`: 위 경우의 안내 문구("고른 직종에서 ‘X’와 맞는 공고를 찾지 못했습니다. 다른 세부 검색어로 찾거나
  직종 전체 공고를 볼 수 있습니다."). 없으면 `null`.
- `ranking`: 대분류+세부어면 `keyword_then_selected_record_term_overlap`.
- `sources[]`: 직종 코드로 거를 수 없는 수집처(사람인·Greenhouse)는 대분류 검색에서 `status=skipped`,
  `reason=category_unsupported`. 스테이징은 고용24 수집만 쓴다.

## 서버 동작

1. 고용24 목록 검색에 `occupation=<코드들>`을 넘긴다. 대분류가 있으면 제목 한정(`keywordWantedTitle`)을 끄고
   세부어를 본문까지 찾는다.
2. 제목 직무 사전(`job_scope.title_matches`)은 대분류가 없을 때만 쓴다. 대분류가 있으면 분류가 범위를 정하고,
   강사·교육생 공고만 교육 분류(03)를 고르지 않았을 때 뺀다.
3. 후보 순서: 세부어가 제목에 있으면 앞, 본문에 있으면 그다음, 그 안에서는 기존처럼 학생 기록과 겹치는 단어 수.
4. 세부어로 0건이면 0건 그대로 돌려주고 `category_browse_available`와 `search_notice`를 붙인다. 서버가 다른 공고로
   바꿔 채우지 않는다. 직종 전체를 볼지는 학생이 고른다(2026-11-22 결정).

한계: 고용24 본문 검색도 글자 그대로 찾는다. 소프트웨어(024) 안에서 `프런트엔드`는 0건이라 안내와 `직종 전체 보기`가
나오고, `프론트엔드`는 해당 공고가 나온다(2026-11-22 실수집). 기업이 직종을 잘못 고른 공고는 섞일 수 있다.

## 프론트 적용 (화면 담당)

1. `내 자료로 공고 찾기`에 대분류 선택을 넣는다. `GET /me/job-categories`로 1차를 보여 주고, 1차를 고르면 2차를 고른다.
   1차만 골라도 된다. 여러 개 선택은 최대 10개.
2. 기존 `직무` 입력칸은 `세부 검색어 (선택)`로 바꾸고 고른 코드를 `category_codes`로 보낸다.
3. `search_notice`가 있으면 결과 자리에 보여 준다. `query.occupation_label`로 무엇을 찾았는지 표시한다.
4. `category_browse_available`가 `true`면 안내 아래에 `직종 전체 보기` 버튼을 둔다. 누르면 같은 요청을 `keyword: ""`로
   다시 보낸다(`category_codes`·기록·파일은 그대로). 다시 받은 결과에는 세부어가 없으므로 "세부 검색어 없이 고른 직종의
   공고"임을 표시한다. 세부 검색어 입력칸을 고쳐 다시 찾을 수도 있게 둔다.
5. 대분류 없이 세부어만 보내는 기존 요청도 계속 받으므로 화면 전환 전후 모두 동작한다.
