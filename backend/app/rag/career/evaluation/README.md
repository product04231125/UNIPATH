# 실제 공고 고정 비교 평가

이 폴더에는 합성 지원자 자료, 합성 자료의 평가 결과, 집계 요약만 포함한다. 실제 PDF 분석 전문과 실제 공고 원문은 재식별 및 원문 재게시를 피하기 위해 저장소와 PR 브랜치 이력에서 제외했다. 과거 공고 20건 평가의 집계 수치는 유지하며 원문 재실행 자료는 접근 권한이 있는 저장소 밖 경로에서 준비한다.

제목 검색과 추가 동의어 검색으로 확보한 후보의 상세 업무를 검토해 웹/서버/응용 SW 개발, 정보시스템 기획·운영, IT 유지보수 직무를 선택했다. **실제 추천 API의 제목 필터가 자동으로 고른 20개가 아니다.** 특정 학생에게 적합한 추천 20개라는 의미도 아니다. 마감 이후에는 과거 시점 회귀 테스트 자료로만 사용한다.

## 입력 방법

공고의 `text` 전체를 `posting_text`에, 지원자 자료는 `records`에 넣는다. 모델에 제목·키워드만 제공하거나 문서를 요약해서 필요한 자격을 누락시키지 않는다. 각 기록의 ID·버전·원문을 유지해 모델이 인용한 문장이 실제 자료에 있는지 검증한다.

`profiles.synthetic.json`은 실제 학생 자료가 아닌 3개 합성 사례다.

- 경력자: 학사, 정보통신기술자 중급, 정보처리기사, 서버·네트워크·보안 경력 4년 10개월.
- 다른 분야 신입: 카페 경력과 워드 활용만 제시. 없는 개발 경력을 만들어내면 실패다.
- 준비 중 지원자: 졸업예정, 정보처리기사 준비 중/미취득, 기술자 중급 미보유, 웹 프로젝트 3개월. 취득 완료나 실무 3년으로 바꾸면 실패다.

사용자 제공 실제 PDF는 저장소에 넣지 않았다. 승인받은 자료를 `--portfolio`로 추가하면 총 4개 자료 × 20개 공고 = 80건이다. 실제 PDF 결과도 저장소 밖에 쓴다.

## 재실행

기존 서버와 같은 `VERTEX_PROJECT`, `VERTEX_LOCATION`, `VERTEX_MODEL`, `GOOGLE_APPLICATION_CREDENTIALS` 환경을 준비한다. 이번 실측은 `global` / `gemini-3.8-flash`다. 비밀키는 이 폴더에 복사하지 않는다.

```sh
PYTHONPATH=backend backend/app/rag/.venv/bin/python \
  -m app.rag.career.evaluate_matching \
  --postings /private/path/authorized-postings.json \
  --profiles backend/app/rag/career/evaluation/profiles.synthetic.json \
  --output /tmp/unipath-synthetic-evaluation.json \
  --workers 3 --allow-network
```

실제 PDF를 추가하려면 `--portfolio '/절대경로/자료.pdf' --redact-name '이름'`을 추가한다. `--redact-name`은 여러 번 지정할 수 있다. 키·문서 내용은 진행 로그에 출력하지 않는다. 결과 파일은 자연어 설명을 포함하므로 개인 자료로 취급한다. 이 명령은 실제 모델을 호출하며 유료다. 모델 출력은 매번 달라질 수 있다.

## 결과 읽기

`comparisons`의 `priority`는 필수/우대, `status`는 근거 있음/부분 근거/근거 부족, `explanation`은 한국어 설명이다. 성공한 답변도 자연어 설명의 의미가 정확한지 검토해야 한다. `completed`는 입력/출력과 인용 검증을 통과했다는 뜻이며 채용 적합 판정을 보증하지 않는다.

검토 항목:

1. 공고가 요구하지 않은 자격이나 경력을 만들어내지 않았는가?
2. 보유·예정·준비 중을 구별하고, 개인 프로젝트를 재직 경력으로 바꾸지 않았는가?
3. 필수와 우대를 구별하고 부족한 점을 구체적으로 설명했는가?
4. 자료에 없다는 사실을 실제 미보유라고 단정하지 않았는가?
5. 공고 본문과 표의 조건이 다르면 임의로 하나를 확정하지 않았는가?
6. 직무가 다르거나 일반 사무능력만 맞는데 적합하다고 설명하지 않았는가?
7. 근거 인용이 실패한 답변을 정상 결과로 표시하지 않았는가?

## 실제 앱과의 차이

동일한 `prepare_documents`, `EvidenceAnalyzer`, Vertex 모델 모듈을 사용한다. 다만 이 평가에는 로그인/소유권/DB 자료 선택/업로드 HTTP·프록시/프론트 표시 검증이 없다. 앱의 최대 3개 분석·시간 예산·공유 호출 제한도 적용하지 않는다. 3개 작업을 동시에 실행하는 평가 처리량을 학생 1명의 응답 속도로 해석하면 안 된다. 배포 후 인증된 API와 실제 UI로 별도 통합 테스트가 필요하다.

현재 출력은 조건별 자연어 설명이지, 단일 장문의 자기소개서 첨삭이나 합격 확률이 아니다. 프론트는 설명을 일치 항목/부족한 필수조건/부족한 우대사항/추가 확인사항으로 표시할 수 있다. 희망 직무와의 적합성 및 최소 후보 유지 정책은 별도 추천 단계에서 검증한다.
