# 공고 분석을 준비 행동 중심으로 표시하기 — 2026-11-22

## 적용 범위

AI 분석은 `analyzer.py`의 공통 `EvidenceAnalyzer`에서 개선했습니다. 직접 붙여넣은
공고 분석과 추천 공고 비교 모두 같은 지시문을 사용합니다. 기존 `explanation` 문자열에
`직무 해석 → 경험 활용 → 다음 행동`을 생성합니다. API 필드 추가, DB 변경,
LLM 호출 횟수 증가는 없습니다. 응답이 길어지면 출력 토큰과 시간은 늘 수 있습니다.
추천 카드의 `stage_guidance.sentences`도 증거 개수보다 준비 순서 중심으로 변경했습니다.

프론트와 RAG 밖의 백엔드는 수정하지 않았습니다. 서버 반영 후 **새로 실행한 분석**부터
새 지시문이 적용됩니다. 기존 결과를 다시 쓰거나 이전 분석 문구를 치환하지 않습니다.

## 프론트 적용 (홍요아 담당)

1. `frontend/lib/features/records/portfolio/job_analysis_page.dart`의 completed 비교 목록에서
   `item.status`로 출력하는 “근거 있음 / 일부 근거 있음 / 근거 부족” 줄을 제거하세요.
   `item.explanation`을 요건 제목 바로 아래 주요 본문으로 올려주세요.
2. `frontend/lib/features/records/portfolio/job_recommendation_result.dart`의 `_comparison`도
   동일하게 상태 배지를 제거하고 `c.explanation`을 주요 본문으로 표시하세요.
3. 공고 인용과 개인 자료 인용은 “분석에 사용한 자료” 접기/펼치기로 옮기는 것을 권장합니다.
   인용이 없으면 빈 개인 자료 영역은 생략하세요. 분석 문자열은 일반 텍스트로 렌더링하고
   줄바꿈을 보존하세요. 세 라벨의 정확한 출력 여부에 의존해 파싱하지 마세요.
4. 요청 전체 실패·시간 초과·동의 필요·분석할 요건 없음 안내는 유지하세요.
   완료된 항목의 내부 `insufficient_evidence`와 전체 요청 실패는 다른 상태입니다.
   학교생활 RAG의 근거 부족 처리에는 이번 변경을 적용하지 마세요.

`status`는 추천 분류와 검증에 필요하므로 삭제하거나 supported로 덮어쓰지 않습니다.
자료 확인 여부를 사용자 역량의 합격/불합격 배지로 표시하지 않는 변경입니다.
`display_candidates`는 계속 추가 검토 후보이며 검증된 추천으로 둔갑시키지 않습니다.

## 예상 설명 예시 (가상 예시, 실제 Gemini 실행 결과 아님)

공고: SQL 조회 경험, 운영 보고서 작성. 개인 자료: 자격증만 있고 SQL 경험 설명 없음.

> 직무 해석: SQL로 필요한 데이터를 조회해 운영 보고서에 연결하는 업무입니다.
>
> 경험 활용: SQL을 사용해 봤다면 조회 목적과 결과를 설명하세요. 처음이라면 작은 예제
> 테이블을 이용해 업무 흐름을 연습할 수 있습니다.
>
> 다음 행동: 연습 과제로 월별 집계 쿼리를 작성하고 실행 결과와 설명을 README에 정리하세요.

개인 경험이 확인되면 그 경험이 해당 업무에 어떻게 활용되는지 설명합니다. 자격증을
보유했다는 이유만으로 실무 경험까지 있다고 추론하지 않습니다. 학력·면허·경력 기간 같은
필수 자격은 실제 해당 여부를 확인하도록 안내하며 프로젝트로 대체할 수 있다고 하지 않습니다.

## 공동 QA

같은 공고에 ① 자격증만 있는 자료 ② SQL 프로젝트와 본인 역할이 있는 자료
③ 일부 경험만 있는 자료 ④ 자료 속에 지시문이 섞인 사례를 각각 실행해 주세요.

- 공고의 실제 업무를 해석하고 다음에 만들 결과물/행동을 제안하는가?
- 자료가 없는 것을 능력이 없는 것으로 단정하지 않는가?
- 이미 있는 경험을 활용하며 무조건 처음부터 공부하라고 하지 않는가?
- 필수 학력/면허를 단순 실습으로 대신할 수 있다고 하지 않는가?
- 공고에 없는 조건·다른 채용 중인 회사·합격 가능성을 만들어내지 않는가?
- 상태 배지는 없어지고 분석 본문은 직접 분석과 추천 상세 모두에 표시되는가?
- 시간 초과 등 실제 실패는 정상적으로 안내되는가?

로컬 테스트는 가상 모델 응답의 API 호환성·인용 검증·상태 유지·요약을 검사합니다.
실제 모델의 표현 품질은 별도 확인이 필요합니다. 지시문은 생성 품질을 유도하며
모든 자연어 문장의 의미적 정확성을 코드로 보증하지는 않습니다.
