# 학사일정·규정 본문 안내 전달서

이 모듈은 링크 바로가기 대신 클릭한 내용의 **본문을 JSON 응답 안에** 반환한다.
기존 프론트·백엔드/API는 수정하지 않았다. 새 HTTP API를 배포한 상태는 아니다.
학사 판정용 감사와 참고 문서 열람은 분리되어 있으며 문서를 개인 판정 규칙으로 자동 승인하지 않는다.

## 클릭 흐름

- `home → calendar → calendar:2026 → calendar:2026:11`
  - 2026년 11월 날짜·행사명·기간을 본문 카드로 안내.
  - 월을 걸치는 일정은 양쪽 월에 표시하고 동일 내용은 한 번만 표시.
  - 수집한 페이지의 달력 연도와 제목의 '학년도'를 구분. 제목은 원문 그대로 보존.
- `home → regulations → regulations:2-0-1 → 장/묶음 → 조항`
  - 학칙 / 학칙시행세칙 / 특수대학원 학칙 / 특수대학원 학칙시행세칙 /
    일반대학원 학칙 / 일반대학원 학칙시행세칙의 6개 버튼.
  - 각 문서는 장·부칙·별표·서식 등으로 나누고 해당 조항의 추출 본문을 표시.
  - 항목이 많으면 12개 단위 묶음으로 이동. `buttons`를 그대로 렌더링하면 된다.
  - PDF 페이지를 넘는 조항은 페이지별 카드 여러 장으로 이어서 표시.
- `regulations:2-0-5:pages:3`처럼 전체 페이지 보기로 본문과 표를 함께 읽을 수 있다.
  - 부칙의 경과조치, 별표, 서식도 포함한다. 삭제된 조항은 원문대로 남긴다.

처음 PDF 분할 과정에서 일부 페이지의 문서 머리글만 항목에서 제외했다. 전체 페이지 본문에는
머리글도 남아 있다. 추출된 모든 비머리글 줄이 항목에 보존되는지 테스트한다.
표·서식의 텍스트 읽기 순서는 시각적 원문과 다를 수 있으며, 의미를 추론해 교정하지 않았다.
일부 첫 페이지와 표 페이지를 시각 확인했으나 158쪽 전체의 표 셀을 수작업 검수한 것은 아니다.

## 프론트가 표시할 필드

공통: `title`, `message`, `buttons`, `warnings`, `cards`.
추가된 카드 유형은 `type`으로 분기한다. 이 화면의 `ready`는 안내 가능 상태이며,
졸업 충족이나 공식 승인 상태가 아니다. 규정 응답에는 `audit`가 없다.

| 카드 type | 표시할 내용 |
| --- | --- |
| `calendar_event` | title, body, start_date, end_date, date_text |
| `regulation_excerpt` | title, body(줄바꿈 보존), sources의 문서명·쪽 |
| `regulation_page` | title, body, tables(행 배열의 배열), sources |

`tables`는 페이지 전체의 추출 표다. 하나의 조항에 전부 귀속시키지 않는다.
병합 셀의 null은 병합/공란 상태 그대로 유지하고 0이나 면제로 변환하지 않는다.
텍스트는 HTML로 해석하지 않는다. `body`를 링크로 대체하지 않는다.
`source_url`은 출처 메타데이터이며 안내를 읽기 위해 클릭할 필요가 없다.
문서 목록의 `source`는 문서 전체, 카드의 `sources`는 페이지 출처다.
학부·특수대학원·일반대학원 범위를 `scope`로 표시한다.

각 PDF 응답은 제공 문서 버전 기준이다. 최신 규정임을 자동 보증하지 않고 입학연도별 적용을
판정하지 않는다. 현재 조항뿐 아니라 부칙·경과조치도 사용자가 선택해 읽을 수 있다.
규정의 해석 요약이나 새 문장을 LLM으로 생성하지 않는다. 고정 안내문과 원문 추출 본문을 결합한다.

## 자료 및 갱신

- `data/calendar-2026.json`: 공식 학사일정 페이지에서 수집한 88개 행.
- `data/regulations.json`: 제공 PDF 6개·158쪽의 본문, 표, 장/조항 목차.
- `data/sources/`: 수집 HTML과 원본 PDF. 파일 해시로 원본을 식별한다.
- `examples/content-responses.json`: 실제 내용 응답 예시.
- `examples/catalog.json`: 동적으로 구성한 전체 메뉴. 수작업으로 ID를 만들지 않는다.

PDF 수입은 선택 사항인 기존 `pdfplumber` 의존성을 사용한다. 런타임 안내와 달력 수집은
표준 라이브러리만 사용한다. `backend/`에서:

```bash
# 명시적으로 실행할 때만 네트워크 요청. 연도별 한 페이지를 읽는다.
app/rag/.venv/bin/python -m app.rag.guidance.collect calendar --year 2026

# 제공 파일 6개를 다시 읽어 하나의 규정 코퍼스를 만든다.
app/rag/.venv/bin/python -m app.rag.guidance.collect regulations --directory /Users/admin/Downloads

# 실제 안내 확인: API·DB·LLM 불필요
app/rag/.venv/bin/python -m app.rag.guidance calendar:2026:11
app/rag/.venv/bin/python -m app.rag.guidance regulations
app/rag/.venv/bin/python -m app.rag.guidance regulations:2-0-5:pages:3
```

달력 수집은 요청 시간/크기 제한을 두고 12개 월·연도·날짜/제목 쌍을 검사한다.
구조가 달라지거나 일정이 하나도 없는 응답, 파싱 실패, 통신 실패에는 이전 JSON을 덮어쓰지 않는다.
그러므로 새 연도 자료가 아직 게시되지 않았으면 새 연도 메뉴를 만들지 않는다.
이는 자동 주기 갱신이 아니다. 운영 스케줄러 연결은 백엔드 팀의 후속 작업이다.
`fetched_at`을 항상 보여주고, 수집 후 7일 이상이면 `snapshot_stale=true`와 경고가 나온다.
동작 중의 클릭은 네트워크 호출 없이 마지막 성공 스냅샷을 읽는다.

PDF를 갱신하면 원본 SHA와 목차가 바뀔 수 있으므로 프론트는 새 catalog를 다시 읽고
이전 메뉴/선택 ID를 무조건 재사용하지 않는다. 원본 파일은 해시별로 보관된다.
이 문서의 경로와 폴더 구조는 내부용이다. 서버의 절대 파일 경로를 프론트에 노출하지 않는다.
학사일정은 공식 페이지의 게시 스냅샷이고 PDF는 사용자가 제공한 문서이며 두 출처를 구분한다.

## 검증 범위

일정 88행과 원본 HTML 파싱 결과 일치, SHA 검증, 연도/월 범위, 엔티티 처리,
월간 중복 제거, 페이지 간 조항 연결, 6개 PDF의 전 추출 줄/페이지 보존,
학생 개인정보 미포함, 메뉴 이동, 수집 실패 시 이전 데이터 보존을 자동 검증한다.
실제 프론트의 표 렌더링과 운영 API 인증·배포는 이번 범위에 포함되지 않는다.
