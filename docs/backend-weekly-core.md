# 백엔드 핵심 흐름 점검 · 2026-10-31

이번 주 우선순위는 학교 RAG 근거 검증과 졸업 결과 안내, 개인화·채용 분석의 최소 계약이다.
추가 관리 기능·새 인프라·채용 데이터 영속화는 이번 변경에 포함하지 않았다.

| 작업 | 기존 상태 | 이번 변경 | 남은 작업 |
|---|---|---|---|
| 학교 RAG | 승인 DB·UUID 범위 검색·회수 차단 구현 | 인용에 DB 적용 조건·문서 버전·출처 확인일 추가 | 실제 학교 원문 검토·적용 조건 및 검색 품질 검증, 실제 생성기 연결 |
| 졸업 안내 | Rule Engine·공식 감사·불변 이력 구현 | 감사 결과를 수치·부족 항목·규칙/기록 근거와 함께 안내 | 실제 학교 자료로 시나리오 검증, 프런트 안내 화면 연결 |
| 개인화 | 개인 자료 CRUD·소유권·버전 구현 | 선택한 본인 자료만 별도 문맥으로 조립 | 학교 근거와 개인 문맥을 구분해 사용하는 AI/RAG 연결 |
| 채용 분석 | 2차 MVP 모듈 경계만 존재 | 공고 원문·개인 기록 선택 API와 공급자 어댑터 경계, 인용·버전 검증 | 실제 요건 추출·비교·설명 어댑터, 프런트 입력·결과 화면, 실제 품질 평가 |

## 계획과 일정 조정

[최초 계획 비교](initial-plan-comparison.md)는 전체 10주 일정과 채용 분석의 2차 MVP 배치를
설명한다. 이번에는 전체 채용 기능에 앞서 원문 1개·선택 자료의 비영속 계약을 착수한다.
개인화도 전체 생성 기능보다 본인 자료 선택·분리 전달부터 구현한다.
원래 주차별 기준일과 각 담당의 확정 완료일은 이 작업에 제공되지 않아 날짜 단위 지연은
산정하지 않는다. 위 상태를 기준으로 실제 학교 자료 검토와 AI/RAG 연결, 프런트 연결의
담당별 완료일을 맞추고 추가 관리 기능의 우선순위를 낮춘다. 담당자를 임의 배정하지 않는다.

## 검증 범위

합성 자료로 공통/개인 근거 분리, 소유권·누락·버전 충돌·허위 인용 차단과
졸업 안내의 충족·미충족·확인 필요 및 근거 회수 후 재확인을 검증한다.
실제 학교 자료나 LLM을 사용한 품질 검증 완료를 뜻하지 않는다.
상세 계약은 [학교 RAG](api/school-knowledge.md), [졸업 안내](api/graduation-audits.md),
[개인화·채용 분석](api/job-analysis.md)을 따른다.

# 백엔드 주간 결과 · 2026-11-07

학사 안내 전달, 맞춤 안내, 채용 분석의 백엔드 경로를 연결했다. 신우철의 `feature/template`을
통합해 안내 자료와 취업 분석 모듈을 API에 연결했다. Vertex 키가 없어 실제 Gemini 호출은
검증하지 못했으며, 합성 응답과 검증기로만 확인했다.

| 주간 항목 | 백엔드 완료 | 남은 작업 |
|---|---|---|
| 실제 문서 출처·적용 조건·검색 정확도 | 안내 스냅샷 출처 해시 검증, 개발 평가 재측정 | D1 원문 검토·승인. 원문 URL, 검토 승인, 적용 연도·이수경로가 비어 있어 준비도 `false` |
| 정형 안내 API | [노드·감사·원문 파일 API](api/academic-guidance.md) | 프론트 화면 연결 |
| 개인 자료 분리 맞춤 안내 | [분리 응답·인용 검증·회수 차단](api/personalized-guidance.md) | 승인 문서와 실제 모델로 시나리오 검증 |
| 채용공고 분석 | [Gemini 연결, 동의, 식별 정보 제거, 호출 상한](api/job-analysis.md) | 키 설정, 실제 응답 평가, 프론트 동의 연결 |
| 통합 시연·평가 | 시연 스모크, 합성 시나리오 평가 도구 | 키 설정 후 실제 품질·응답 시간 측정 |

## 측정 결과

개발 PDF 2개(6쪽)와 개발자가 만든 질문 기준이다. 독립 평가가 아니며 실제 사용자 질문의
정확도를 뜻하지 않는다. LLM 답변 품질은 측정하지 못했다.

| 평가 | 조건 | 결과 |
|---|---|---|
| 검색·동작 36건 | 페이지 청킹, 상위 3개 | 36/36, Hit 100%, MRR 0.917 |
| 검색·동작 36건 | 페이지 청킹, 상위 1개 | 31/36, Hit 84.6%, MRR 0.846 |
| 검색·동작 36건 | 연도별 청킹, 상위 3개 | 36/36, Hit 100%, MRR 0.878 |
| 연도 혼합 12건 | 연도별 청킹, 상위 3개 | 12/12, MRR 0.819 |
| 연도 혼합 12건 | 페이지 청킹, 상위 3개 | 0/12. 여러 연도 표가 한 청크라 문서상 예상된 결과 |
| 준비도 점검 | 공식 범위 조건 | `ready_for_scoped_local_test=false` |

첫 번째 결과의 정확도가 낮으므로 답변 근거는 상위 3개를 유지한다. 연도별 조건 질문이 많으므로
운영 청킹은 연도별 방식을 기본으로 검토한다. 결정은 D1, D5와 함께 한다.

로컬 API와 임시 PostgreSQL의 응답 시간이다. 서버 부하와 네트워크는 포함하지 않는다.

| 구간 | p50 | p95 |
|---|---|---|
| 정형 안내 노드 211회 | 12ms | 33ms |
| 개인 문맥 조립 | 23ms | 1회 측정 |
| 채용 분석 미설정 응답 | 32ms | 1회 측정 |
| 규정 PDF 264KB | 134ms | 1회 측정 |

안내 자료 2,915개 노드를 전부 계약으로 검증했고, API 메모리는 약 210MB다.
Gemini 호출 시간은 키 설정 후 측정한다. 프록시 제한은 60초, 앱 제한은 40초다.

## 알려진 한계

- 식별 정보 제거는 형식이 있는 값과 본인 이름만 처리한다. 다른 사람의 이름은 남을 수 있다.
- 공고 URL과 PDF 입력, 여러 사이트 공고 검색, 개인 요약 API는 이번 범위가 아니다.
- 안내 자료는 스냅샷이다. 자동 갱신이 없고 7일이 지나면 경고가 나온다.
- OCR 53쪽과 규정 표는 전수 교정하지 않았다.
- PDF 원본이 저장소와 이미지에 들어간다. 백엔드 이미지는 압축 기준 100MB에서 172MB로, `/app`은
  65MB에서 163MB로 늘어난다. 안내 자료가 85MB, Vertex 인증 의존성이 약 14MB다. 저장 위치는 미정이다.
- Gemini를 켜면 `/me/school-queries`도 질문을 식별 정보 제거 후 Google로 보낸다. 이 경로는 개인
  기록을 보내지 않지만 요청별 동의 필드가 없다. 화면에 전송 사실을 안내해야 한다.
- 모델 답변의 인용과 형식은 검증하지만 문장의 의미까지 검증하지는 않는다. 실제 응답 평가가 필요하다.

## 일정 조정 필요

Vertex 프로젝트, 리전, 모델 ID, 서비스 계정 키가 없으면 실제 답변 시연을 할 수 없다.
시연 전에 키 설정과 `--live` 평가(예상 하루), 프론트 동의 화면 연결 시간을 확보해야 한다.
키가 늦어지면 시연은 정형 안내와 근거 분리 응답까지로 줄이고, 채용 분석은 설정 전 상태로
보여 준다. 합성 응답을 실제 분석처럼 시연하지 않는다.
