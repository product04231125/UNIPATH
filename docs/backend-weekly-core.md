# 백엔드 핵심 흐름 점검 · 2026-10-31

이번 주 우선순위는 학교 RAG 근거 검증과 졸업 결과 안내, 개인화·채용 분석의 최소 계약이다.
추가 관리 기능·새 인프라·채용 데이터 영속화는 이번 변경에 포함하지 않았다.

| 작업 | 기존 상태 | 이번 변경 | 남은 작업 |
|---|---|---|---|
| 학교 RAG | 승인 DB·UUID 범위 검색·회수 차단 구현 | 인용에 DB 적용 조건·문서 버전·출처 확인일 추가 | 실제 학교 원문 검토·적용 조건 및 검색 품질 검증, 실제 생성기 연결 |
| 졸업 안내 | Rule Engine·공식 감사·불변 이력 구현 | 감사 결과를 수치·부족 항목·규칙/기록 근거와 함께 안내 | 실제 학교 자료로 시나리오 검증, 프런트 안내 화면 연결 |
| 개인화 | 개인 자료 CRUD·소유권·버전 구현 | 선택한 본인 자료만 별도 문맥으로 조립 | 학교 근거와 개인 문맥을 구분해 사용하는 AI/RAG 연결 |
| 채용 분석 | 2차 MVP 모듈 경계만 존재 | 공고 원문·개인 기록 선택 API와 공급자 어댑터 경계, 인용·버전 검증 | 실제 요건 추출·비교·설명 어댑터, 프런트 입력·결과 화면, 실제 품질 평가 |

## 계획과 일정 조정

[최초 계획 비교](initial-plan-comparison.md)는 전체 10주 일정과 채용 분석의 2차 MVP 배치를
설명한다. 이번에는 전체 채용 기능에 앞서 원문 1개·선택 자료의 비영속 계약을 착수한다.
개인화도 전체 생성 기능보다 본인 자료 선택·분리 전달부터 구현한다.
원래 주차별 기준일과 각 담당의 확정 완료일은 이 작업에 제공되지 않아 날짜 단위 지연은
산정하지 않는다. 위 상태를 기준으로 실제 학교 자료 검토와 AI/RAG 연결, 프런트 연결의
담당별 완료일을 맞추고 추가 관리 기능의 우선순위를 낮춘다. 담당자를 임의 배정하지 않는다.

## 검증 범위

합성 자료로 공통/개인 근거 분리, 소유권·누락·버전 충돌·허위 인용 차단과
졸업 안내의 충족·미충족·확인 필요 및 근거 회수 후 재확인을 검증한다.
실제 학교 자료나 LLM을 사용한 품질 검증 완료를 뜻하지 않는다.
상세 계약은 [학교 RAG](api/school-knowledge.md), [졸업 안내](api/graduation-audits.md),
[개인화·채용 분석](api/job-analysis.md)을 따른다.
