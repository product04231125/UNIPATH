# 채용공고 비교를 위한 특수 목적 AI 검토

> 상태: 아키텍처 제안 (2차 MVP부터 기본 매칭 도입, 특수 목적 AI는 3차 이후 검토)
>
> 목적: 사용자 프로필과 여러 채용공고를 비교할 때, 일반 생성형 LLM 외에 리랭커·결정형 모델·분류 모델을 어떤 경계에서 검토할지 정의한다.

## 1. 문제 정의

이 기능은 사용자의 전공, 이수 과목, 자격증, 경험, 프로젝트 및 희망 직무와 여러 채용공고의 요건을 비교해 다음을 보여 준다.

- 공고별 필수 요건의 충족·부족·정보 부족
- 우대 요건의 보유 여부와 자동 비교하지 않은 항목
- 여러 공고 중 현재 프로필과 더 관련성 높은 공고의 순위
- 비교가 모호하여 사용자 확인 또는 사람 검토가 필요한 항목

결과는 합격 가능성 예측, 자동 지원 추천 또는 인사 판단이 아니다. 공고에 명시된 요건과 현재 프로필의 **설명 가능한 적합도**를 제공한다.

## 2. 기본 원칙과 역할 분리

| 구성 요소 | 책임 | 최종 판단 여부 |
| --- | --- | --- |
| 공고 수집·요건 추출 | 공고 원문과 URL·수집 시각을 보존하고 `JobRequirement`로 구조화 | 아니오 |
| 규칙 기반 매칭기 | 명시적 필수 요건을 후보자 프로필과 항목별 비교 | 예: 충족·부족·정보 부족 |
| 리랭커 | 여러 공고를 사용자 프로필과의 의미적 관련도 순으로 정렬 | 아니오 |
| 결정형 AI | 제한된 선택지에서 우선 검토 또는 판단 보류 신호를 반환 | 아니오 |
| 분류 모델 | 공고의 직무군·기술·경력 조건 등 반복 라벨을 정규화 | 아니오 |
| 생성형 LLM | 요건 추출 결과와 매칭 근거를 사용자에게 설명 | 아니오 |

`JobMatch`와 `JobMatchDetail`은 언제나 구조화된 요건, 후보자 프로필의 근거 식별자 및 명시적인 매칭 정책으로 생성한다. 외부 AI의 점수·순위·확률은 필수 요건 상태를 덮어쓰지 못하며, 설명 생성의 근거로만 사용한다.

졸업요건의 충족·미충족은 이 문서에서 다루는 AI, RAG 또는 LLM이 아닌 `Academic Rule Engine`만 판정한다.

## 3. 검토할 특수 목적 AI 유형

### 3.1 리랭커: 여러 공고의 정렬

리랭커는 질의와 여러 문서를 함께 받아 문서별 관련도 점수와 순위를 반환하는 모델이다. 이 기능에서는 최소화한 사용자 프로필 요약을 질의로, 각 공고의 구조화된 요건 요약을 문서로 사용한다.

```text
후보자 프로필 요약 + 선호 조건
              ↓
공고 A/B/C의 정규화된 요건 요약
              ↓
리랭커의 관련도 점수와 순위
              ↓
규칙 기반 필수 요건 결과와 함께 화면에 표시
```

- 적합한 경우: 수십~수백 개 공고에서 “더 살펴볼 공고”를 먼저 정렬할 때
- 부적합한 경우: 자격증 보유 여부, 최소 경력 기간처럼 명시적으로 계산 가능한 필수 조건의 판정
- 후보: Cohere Rerank는 다국어 텍스트와 반정형 JSON의 리랭킹을 지원하며, Voyage Rerank는 질의와 문서 목록에 대해 순위와 관련도 점수를 반환한다.
- 도입 전 확인: 한국어 공고 품질, 점수 안정성, 지연시간, 가격, 데이터 처리 조건

### 3.2 결정형 AI: 좁은 A/B 선택과 보류 신호

JEV 같은 결정형(System One) API는 장문 답변을 생성하기보다 상태(`state`)와 정의된 질문(`questions`)에 대해 제한된 선택지, 확률, 신뢰도를 반환한다.

예를 들어 규칙 기반 결과가 비슷한 두 공고에 대해 아래처럼 제한된 질문만 사용한다.

- `A 우선 검토`, `B 우선 검토`, `동등`, `판단 보류` 중 하나를 선택
- 공고 요건이 후보자 경험으로 자동 비교 가능한지 여부
- 사람 검토 또는 사용자 추가 입력이 필요한지 여부

일반 생성형 LLM의 구조화 출력으로도 유사한 결과를 만들 수 있다. 결정형 API의 가치는 기존 LLM으로 불가능한 기능이 아니라, 결정 결과를 별도 계약으로 받고 후속 정책에서 확률·신뢰도를 일관되게 처리할 수 있다는 데 있다.

- 적합한 경우: 우대 조건 문장이 모호하고, 결과 공간을 제한할 수 있을 때
- 부적합한 경우: 필수 요건 판정, 합격 예측, 자유 형식 설명, 복잡한 장문 요약
- 도입 전 확인: 실제 API 제공 상태, 한국어 품질, 캘리브레이션, 비용, SLA, 개인정보 처리 조건. 특정 공급자·버전은 확정하지 않는다.

### 3.3 분류 모델: 반복되는 공고 라벨 정규화

분류 모델은 공고 텍스트를 미리 정한 라벨로 분류하고 각 라벨의 점수를 반환한다. 예시는 직무군, 요구 경력 구간, 기술 분야, 포트폴리오 요구 여부, 원격 근무 가능 여부다.

- 적합한 경우: 팀이 합의한 라벨 체계와 검증된 라벨링 데이터가 축적된 뒤 대량 공고를 빠르게 정규화할 때
- 부적합한 경우: 새롭거나 모호한 요구사항을 근거 없이 단정할 때
- 후보: Mistral의 Classifiers API, Hugging Face의 텍스트·제로샷 분류 또는 관리형 엔드포인트. 자체 호스팅을 선택하면 외부 전송을 줄일 수 있으나 운영 부담이 생긴다.
- 도입 전 확인: 라벨 정의, 학습·검증용 합성 또는 적법한 데이터, 한국어 성능, 오분류 시 `needs_review` 경로

### 3.4 일반 생성형 LLM: MVP의 추출과 설명

일반 생성형 LLM은 정해진 Pydantic 스키마에 맞춰 공고 원문에서 요건 후보를 추출하고, 이미 계산된 매칭 결과를 근거와 함께 설명하는 데 사용한다. 추출 결과는 저장 또는 매칭 전에 스키마 검증과 출처 연결을 거쳐야 한다. 모델이 만든 JSON만으로 필수 요건 상태나 공고 간 최종 추천을 확정하지 않는다.

## 4. 제안 처리 흐름

```text
채용공고 원문·URL·수집 시각
          ↓
생성형 LLM 보조 요건 추출 + 스키마 검증
          ↓
JobRequirement (출처와 함께 구조화)
          ↓
후보자 프로필 조립 (학사·자격증·경험·프로젝트)
          ↓
규칙 기반 항목별 매칭 → JobMatch / JobMatchDetail
          ↓
선택 1: 리랭커로 여러 공고의 관련도 순위화
선택 2: 결정형 AI로 모호한 A/B 비교의 참고 신호 생성
선택 3: 분류 모델로 대량 공고 라벨 정규화
          ↓
근거·점수·불확실성·자동 비교 제외 사유를 포함한 결과
          ↓
생성형 LLM이 기존 근거만 사용해 사용자용 설명 생성
```

리랭커, 결정형 AI, 분류 모델은 모두 선택적인 어댑터다. 예를 들어 `JobRankingProvider`, `JobDecisionProvider`, `JobClassificationProvider` 인터페이스 뒤에 두며, 장애·한도 초과·낮은 신뢰도에는 호출 없이도 규칙 기반 결과를 반환한다.

## 5. 단계별 도입 권고

| 단계 | 도입 범위 | 채택 조건 |
| --- | --- | --- |
| 2차 MVP | 구조화된 요건 추출, 규칙 기반 매칭, 근거 포함 설명 | 특수 목적 AI 없음 |
| 3차 MVP 이후 PoC | 리랭커로 다수 공고 순위화 | 규칙 기반 매칭만 쓸 때보다 관련성 평가가 개선됨 |
| 3차 MVP 이후 PoC | 결정형 AI의 A/B·보류 신호 | 모호한 우대 조건에서 과도한 단정이 줄어듦 |
| 데이터 축적 후 | 전용 분류 모델 | 라벨 정의와 검증 데이터가 충분하고 운영 이점이 있음 |

현재 가장 먼저 검토할 후보는 **리랭커**다. “여러 공고 중 현재 프로필과 관련성이 높은 공고를 정렬”하는 문제와 API 계약이 직접 맞는다. JEV는 이 순위를 대체하는 기본 엔진이 아니라, 소수의 모호한 비교에만 제한적으로 비교 실험할 후보이다.

## 6. 안전·개인정보·검증 조건

- 외부 서비스에는 사용자 식별정보, 연락처, 자격증 번호, 불필요한 프로젝트 원문을 보내지 않는다. 필요한 경우에도 프로필을 최소화·익명화한다.
- 공급자별 데이터 보관, 모델 학습 이용 여부, 처리 지역, 삭제, 보안·SLA 조건을 도입 승인 전에 확인한다.
- 결과에는 공고 URL, 요건 식별자, 프로필 근거 식별자, 매칭 상태, `non_evaluation_reason`을 포함한다.
- 낮은 신뢰도, 입력 정보 부족, 모델 장애는 성공처럼 처리하지 않고 `needs_review`, `insufficient_profile_data`, `not_evaluated` 등 기존 상태로 표현한다.
- 합성 프로필과 라벨링한 공고 쌍으로 필수 요건 결과의 불변성, 순위 품질, 보류 판단, 설명-근거 일치, 개인정보 최소화, 실패 시 폴백을 평가한다.

## 7. 참고 자료

- [Cohere Rerank 문서](https://docs.cohere.com/docs/rerank): 다국어·반정형 데이터 리랭킹 모델 설명
- [Voyage Rerank API](https://docs.voyageai.com/reference/reranker-api): 질의와 문서 목록에서 관련도 점수와 순위를 반환하는 API
- [JEV API 문서](https://www.jevai.org/docs): 상태와 타입이 있는 질문으로 결정·확률·신뢰도를 반환하는 공개 API 설명
- [Mistral Classifiers API](https://docs.mistral.ai/api/endpoint/classifiers): 텍스트 분류 API
- [Hugging Face Text Classification](https://huggingface.co/docs/inference-providers/tasks/text-classification): 점수를 포함한 텍스트 분류 API 및 모델 선택지

참고 자료의 모델명, 비용, 기능 지원, 약관은 수시로 바뀔 수 있으므로 실제 도입 결정 시 공식 문서와 계약 조건을 재확인한다.
