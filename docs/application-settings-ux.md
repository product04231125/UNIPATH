# 애플리케이션 설정 UX 기준

이 문서는 UniversityPath 학생 화면의 **설정** 정보 구조와 UX 기준을 정의한다.
설정은 사용자가 드물게 바꾸는 개인화·계정·정보 옵션을 위한 공간이며, 현재 화면의
필터·정렬·탭·기록 추가처럼 자주 수행하는 작업 명령을 모아두는 곳이 아니다.

현재는 설계 문서이며, 아래 항목이 모두 구현되었거나 서버에 저장된다는 뜻이 아니다.
실제 데이터 저장, 인증, 외부 API, 개인정보 처리 정책은 각 담당 설계와 API 계약이
확정된 뒤에만 추가한다.

## 1. 진입점과 화면 구조

- 좌측 탐색 메뉴의 마지막 항목을 `설정`으로 두고 하단에 고정한다. 학생이 어디에
  있든 같은 위치에서 찾을 수 있게 한다.
- 설정은 모달보다 메인 본문을 사용하는 독립 페이지로 연다. 넓은 화면에서도 읽기
  좋은 최대 폭을 두고, 관련 항목을 섹션 제목 아래 한 열로 배치한다.
- 각 행은 **제목, 짧은 영향 설명, 현재 값 또는 제어 요소**로 구성한다. 외부 사이트나
  상세 페이지 이동은 화살표/외부 이동 아이콘과 함께 명확히 표시한다.
- 설정 수가 늘어나면 `일반`, `AI와 데이터`, `알림`, `접근성`, `계정·정보`의 5개
  이하 범주로 나눈다. 드문 고급 옵션은 한 단계만 펼칠 수 있게 하며 중첩 확장은 피한다.
- 변경 가능한 설정은 바뀌는 즉시 화면에 반영한다. 저장 버튼이 필요한 비가역 또는
  여러 항목 묶음 변경은 무엇을 저장하는지 명확히 표시한다.

## 2. 설정에 둘 항목과 두지 않을 항목

| 범주 | 권장 항목 | 저장/적용 원칙 |
| --- | --- | --- |
| 일반·작업 공간 | AI 패널 기본 열림 여부, 마지막 메뉴 복원, 도킹 패널 폭 복원 여부 | 개인 UI 선호이므로 기기 로컬 저장을 우선 검토한다. 기본값은 AI 패널 닫힘이다. |
| 표시·접근성 | 앱 테마 `시스템 설정 사용/밝게/어둡게`(지원 시), 정보 밀도, 동작 줄이기 | 운영체제의 글자 크기·고대비·색상 설정은 복제하지 않고 존중한다. 앱 선택지가 시스템 동작과 충돌하면 시스템 우선임을 표시한다. |
| AI와 데이터 | 대화 이력 표시/삭제, AI가 현재 화면의 기록을 문맥으로 읽는 범위, AI 기능 안내·데이터 사용 설명 | Rule Engine 판정값이나 공식 규정 적용 범위는 이 설정으로 바꾸지 못한다. 동의·보존 기간·삭제 범위는 백엔드 정책 확정 후 제공한다. |
| 알림 | 마감·기록 확인·시스템 알림의 수신 채널과 빈도 | 알림 기능이 구현되기 전에는 스위치를 노출하지 않는다. 권한이 필요한 경우 OS 권한 상태와 이유를 먼저 설명한다. |
| 언어·지역 | 지원 언어, 날짜·시간 표시 형식(지원 시) | 기본은 시스템 언어·지역을 사용한다. 학사 규정의 공식 명칭·날짜 기준을 임의 번역하거나 변환하지 않는다. |
| 외부 연계 | 1365, Q-Net, 고용24 등 외부 안내/연계의 상태와 연결 해제 | 비밀번호·API 키를 설정 화면에 직접 입력·표시하지 않는다. 실제 연결은 서비스별 동의와 어댑터 계약이 생긴 뒤에만 제공한다. |
| 계정·정보 | 프로필 확인, 로그아웃, 데이터 내보내기·삭제 요청, 개인정보처리방침·도움말·버전 | 대학·학과·입학연도·적용 교육과정은 졸업 판정 범위이므로 단순 설정 토글로 바꾸지 않는다. 정정 절차를 별도 안내한다. |

다음 항목은 설정이 아니라 **현재 작업 화면**에 둔다.

- 졸업요건 기준 탭, 교육과정 표 보기 방식, 현재 목록의 필터·정렬·검색
- 활동·경험·자격·포트폴리오 기록의 추가·수정·삭제
- AI의 현재 질문, 문서 근거 열기, 추천 항목의 적용 여부
- 학교 시스템에 등록해야 하는 승인·증빙 절차

## 3. 데이터와 권한의 경계

| 종류 | 예시 | 원칙 |
| --- | --- | --- |
| 기기 로컬 UI 선호 | 패널 폭, 마지막 메뉴, 일시적인 보기 밀도 | 로그인 계정과 동기화하기 전에는 이 기기에서만 적용됨을 알린다. 공용 PC에서는 복원·자동 로그인 같은 옵션을 기본으로 켜지 않는다. |
| 계정 단위 선호 | 알림 수신, 언어, AI 이력 보존 선택 | 인증·개인정보 정책·API 계약이 확정된 뒤 서버 저장 여부를 결정한다. |
| 공식 학사 데이터 | 학교, 학과, 입학연도, 교육과정, 승인 활동 | 설정값이 아니다. 학교 시스템 또는 권한 있는 관리자 데이터가 바뀐 뒤 Rule Engine에 반영된다. |
| 민감한 연결 정보 | 비밀번호, 토큰, 외부 서비스 API 키 | 프런트엔드 설정 화면이나 로컬 저장소에 두지 않는다. 외부 서비스 어댑터와 안전한 인증 흐름 뒤에서 처리한다. |

## 4. 설정 UI의 동작 규칙

- 이진 선택은 토글을, 2~5개의 상호 배타적 선택은 라디오 버튼을, 더 많은 선택은
  드롭다운을 사용한다. 단순 실행(이력 삭제, 로그아웃, 외부 사이트 열기)은 버튼으로
  분리한다.
- 비활성 설정에는 사라진 토글 대신 **왜 사용할 수 없는지** 설명을 붙인다. 예:
  "알림 기능은 학교 일정 연동 후 사용할 수 있습니다."
- 위험하거나 되돌리기 어려운 행동(대화 이력 삭제, 연결 해제, 계정 삭제 요청)은
  구체적인 대상·영향을 보여 주고 확인을 받는다. 가능하면 일정 시간의 실행 취소나
  복구 절차를 제공한다.
- 저장·삭제·동기화 실패는 토스트만으로 끝내지 않고 해당 설정 행에 재시도 행동과
  텍스트 오류 설명을 남긴다. 변경 중에는 중복 실행을 막되 현재 상태를 읽을 수 있어야
  한다.
- 설정 페이지의 현재 값은 화면에 보이는 동작과 일치해야 한다. 예를 들어 AI 패널의
  기본 열림 값과 실제 다음 시작 시의 상태가 다르면 안 된다.
- 접근성 설정은 시스템 설정을 무시하는 별도 복제본을 만들지 않는다. 시스템 글꼴 크기,
  고대비, OS 테마, 키보드 접근성을 우선 지원하고 앱 고유의 보조 선택지만 추가한다.

## 5. 초기 MVP 권장 범위

처음부터 모든 설정을 화면에 넣지 않는다. 실제 기능이 있는 항목만 아래 순서로
추가한다.

1. **정보**: 앱 버전, 도움말, 개인정보처리방침/이용 안내 링크.
2. **작업 공간**: AI 패널 기본 열림, 패널 폭·마지막 메뉴 복원 여부.
3. **표시**: 시스템 테마 사용과 앱 테마 선택은 테마 구현·대비 검증이 끝난 경우에만.
4. **AI와 데이터**: 실제 대화 이력 저장·삭제 정책, 기록 문맥 사용 범위가 구현된 뒤.
5. **알림·외부 연계·계정 삭제**: 권한, API 계약, 개인정보 정책, 운영 절차가 모두
   확정된 뒤.

학교·학과·교육과정 변경이나 졸업 판정 규칙 수정은 학생 설정 화면의 MVP 범위가
아니다. 이는 관리자 기능 및 공식 데이터 갱신 흐름에서 별도로 다룬다.

## 6. 설정 화면 QA 체크리스트

| 확인 항목 | 통과 기준 |
| --- | --- |
| 발견 가능성 | 좌측 메뉴 하단의 `설정`에서 모든 일반 설정을 찾을 수 있고, 현재 작업 명령이 설정에 섞이지 않는다. |
| 변경 결과 | 가역 설정은 즉시 반영되고, 다음 시작 시 복원 여부와 저장 위치가 설명과 일치한다. |
| 비가역 행동 | 삭제·연결 해제·로그아웃의 대상과 영향이 명확하며 확인 또는 복구 경로가 있다. |
| 접근성 | 모든 제어 요소에 라벨·키보드 포커스·상태 설명이 있고, 고대비·텍스트 확대에서도 잘리지 않는다. |
| 권한·보안 | OS 권한, 외부 사이트 이동, 데이터 보존·삭제가 실제 지원 범위를 넘어서 약속되지 않는다. 민감 정보 입력란이 없다. |
| 규칙 엔진 | 설정 변경만으로 학교·학과·입학연도·교육과정·공식 승인값이 바뀌거나 졸업 판정이 임의로 달라지지 않는다. |

## 7. 참고 자료

- [Microsoft Learn — Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings): 설정 진입점, 단순한 기본값, 설정 종류별 제어 요소, 즉시 반영, 읽기 좋은 한 열 레이아웃 기준.
- [Apple HIG — Settings](https://developer.apple.com/design/human-interface-guidelines/settings): 드물게 바꾸는 일반 설정과 현재 작업 화면의 옵션을 구분하고, 시스템 전역 설정을 중복하지 않는 원칙.
- [Microsoft Learn — Navigation basics](https://learn.microsoft.com/en-us/windows/apps/design/basics/navigation-basics): 탐색 위치의 일관성·단순성·명확성 원칙.
- [W3C WAI — Support Adaptation and Personalization](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o8-personalization/): 사용자 선호와 단순화·개인화가 접근성에 주는 이점.
- [Apple HIG — Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles): 안전한 기본값, 사용자 주도성, 투명성, 실수 복구를 설정 UX에 적용하는 참고 원칙.
