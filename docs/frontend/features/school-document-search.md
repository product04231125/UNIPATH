# 학교 문서 검색·근거

실제 계정은 졸업 요건에서, 관리자는 관리 현황에서 `학교 문서 검색·근거`로 진입한다.
등록 학교·학과는 필수, 교육과정·입학연도·이수 경로는 선택한다. 이름이나 개인 프로필을
UUID로 추정하지 않는다. 검색 질문은 기존 계약에 맞춰 1~4000자다.

기존 `POST /me/school-searches`만 호출하고 서버가 검색한 문서명·쪽·발췌·원문 URL을 표시한다.
본문 검색용 승인 문서가 대상이며 관리자 문서의 적용 상태만으로 검색 승인되지 않는다.
LLM 답변을 생성하거나 졸업요건 충족 여부를 계산하지 않는다.

검색 성공, 승인 근거 부족, 추가 정보 필요, 검색 실패를 구분한다. 추가 입력 필드는 한글로
안내한다. 통신 실패는 질문과 학교 선택을 유지한 채 명시적 재검색을 제공한다. 질문이나
문맥을 바꾸면 이전 근거를 지워 현재 질문의 답으로 오인하지 않게 한다. 전송 중 중복 검색은 막는다.
닫을 때 작성 내용 폐기 확인을 제공하고 원문 링크는 기존 외부 열기 확인을 거친다.

[학교 문서 API](../../api/school-knowledge.md), [검증](../verification/school-document-search-ui.md)을 따른다.
본문 검토/승인·회수는 별도의 [관리자 근거 검토 화면](school-knowledge-review.md)에서 수행한다.
신규 추출본 등록·수정과 운영 검색 품질 평가는 후속이다. 새 API/LLM 연결을 추가하지 않았다.
