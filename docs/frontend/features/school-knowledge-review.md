# 학교 문서 근거 검토

실제 학교관리자·슈퍼관리자는 관리 현황의 `학교 문서 근거 검토`에서 진입한다. 학생과 개발
샘플에는 관리자 진입점을 표시하지 않는다. 실제 로그인 사용자 UUID와 로그인 세대에 묶인
공통 전송 객체로 기존 SchoolKnowledgeAdminApi만 호출한다. 서버가 최종 학교 범위를 검증한다.

## 현재 구현

- 등록된 추출본 목록·검토 상태 필터·cursor 추가 읽기·재조회를 제공한다.
- 상세는 최신 추출본과 페이지 요약을 읽고 문서명·상태·출처 확인일·원문 버전·검토/회수 사유와
  시각을 표시한다. 원본 해시·학교/학과/교육과정/원문 식별자는 접힌 보조 영역에서 확인한다.
- 페이지를 선택하면 본문·분할 순서·문자 offset·해시·입학연도/이수경로·추출 경고를 표시한다.
  서버의 명시적 빈 페이지와 누락 페이지를 구별하고 누락을 빈 페이지로 채우지 않는다.
- 초안은 출처·적용 범위·추출 본문·전체 원본 검토의 네 가지 확인을 사용자가 각각 선택한다.
  직접 확인한 소문자 SHA-256(64자)이 등록 원본과 일치하고 검토 사유가 1~500자일 때 기존
  승인 API로 전송한다. 해시와 확인을 자동 입력하지 않는다. 전체 페이지 완전성·범위·미해결
  경고·현재 원문 적용 상태의 최종 승인 가능 여부는 서버에서 검사한다.
- 승인본은 별도 회수 사유(1~500자)와 현재 버전으로 회수한다. 회수본/알 수 없는 상태에
  승인·회수 버튼을 만들지 않는다. 성공 응답의 대상과 상태를 확인하고 목록을 갱신한다.

문서 메타데이터 적용과 본문 검색 근거 승인은 별도다. 이 화면에서 졸업 판정·LLM 답변·자동
학교 인증이나 원본 자동 검증이 이루어졌다고 표시하지 않는다. 공식 원본 파일은 검토자가
별도로 열어 대조한다. SHA-256 확인은 검토자의 명시적 입력이며 프론트가 파일을 해시하거나
원문 사이트를 다운로드하는 기능은 추가하지 않았다.

## 상태와 입력 보호

읽기 대기·빈 목록·실패·명시적 재읽기와 승인/회수 전송 중 상태를 구분한다. 처리 중 중복
결정과 닫기를 막는다. 실패 사유 입력을 보존하고 서버의 해시/사유 필드 오류를 입력에 표시한다.
422는 보완 후 명시적으로 재시도할 수 있다. 버전 충돌·불명확한 응답 등은 이전 페이지를
숨기고 결정을 잠가 최신 자료 재조회를 요구한다. 재조회로 작성 내용을 버릴 때도 폐기 확인한다.

페이지 응답의 문서 ID·쪽·버전을 선택한 추출본과 비교하고 다르면 본문을 표시하지 않는다.
401/403/404가 확인되면 상세와 부모 목록의 문서/본문·결정 제어를 숨긴다. 서버 작업을
자동 재전송하지 않는다. 새로 읽은 문서에는 기존 확인 체크·해시·사유를 자동 승계하지 않는다.
닫기는 공통 InputDialog의 계속 작성/내용 폐기 확인을 사용한다. 입력을 영속 저장하지 않는다.

## 남은 범위

신규 추출본 등록·페이지 본문/범위 수정·초안/페이지 삭제는 별도 후속 UI다. 현재 목록은
담당자가 기존 API/가져오기 도구로 등록한 실제 추출본을 사용한다. 새 API·DB·OCR·색인·LLM은
만들지 않았다. 실제 학교 자료·운영 서버 심사와 Windows 네이티브 실기는 미검증이다.

[기존 계약](../../api/school-knowledge.md), [검증 기록](../verification/school-knowledge-review-ui.md)을 따른다.
