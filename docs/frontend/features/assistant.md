# AI 도우미

## 목적

AI 도우미는 기록·탐색·문서 설명을 보조한다. 졸업 충족 판정, 학교 승인, 필수 요건을 스스로
결정하거나 기록을 자동 변경하지 않는다.

## 현재 구현

- `features/assistant/assistant_panel.dart`와 `assistant_conversation.dart`에 도킹 패널과 로컬
  대화 상태가 있다.
- `workspace.dart`가 열림·닫힘·폭·분리 창 상태를 조정한다.
- Web은 도킹 패널과 좁은 폭 오버레이만 제공한다. Windows만 네이티브 보조 창을 사용한다.
- Windows 열기 버튼은 기본 내부 패널이며 설정에서 분리 창을 선택할 수 있다. AI는 여전히
  닫힌 상태로 시작한다. 이미 열린 분리 창을 전면화하고 최대화 중에는 내부 패널을 연다.
- 분리 창 열기 실패 시 내부 패널과 재시도 가능한 안내를 제공한다. 분리 재시도가 성공하면
  실패 안내를 지운다. 플랫폼 창 호출은 `AssistantWindowHost` 뒤에 격리한다.
- 좁은 오버레이 폭은 아이콘 탐색 제외 폭의 절반 이내·최대 360px이다. 300px 미만은 이름 있는
  전송 아이콘을 사용해 입력 공간을 남긴다.
- Windows 보조 창을 닫으면 AI 열기 아이콘 상태로 돌아간다. 메인 최대화로 보조 창이 닫히는
  경우만 내부 패널로 복귀한다. 최대화 해제 뒤 자동으로 다시 분리하지 않는다.

## 학교 질의 API 연결

- 도킹/오버레이와 Windows 분리 창은 같은 `AssistantApi`·`AssistantConversation`·응답 위젯을
  사용해 `POST /api/v1/assistant/queries`를 호출한다. 고정 목업 답변은 제거했다.
- `테스트용 설정창`은 팝업이 아니라 채팅 내부의 스크롤 영역에서 열린다. 기존 학교·학과·
  입학연도·이수경로 입력 템플릿을 유지하며 질문 입력은 하단에 남는다.
- 설정에서 저장한 학교 정보는 질의 문맥에 반영된다. 채팅에서 `질의에 사용`을 누르면 같은
  개인 프로필에 저장하고 설정에도 반영한다. 저장 실패는 입력을 보존한다.
- Windows 분리 창은 메인 창에 학교 정보 조회·저장을 요청한다. 개인 일정과 계획 옵션은
  메인 저장소가 보존한다. 예시 프로필이나 개인 졸업 규칙은 전송하지 않는다.
- 메인 저장소는 프로필·일정의 읽기와 쓰기를 순서대로 처리한다. 분리 창과 메인 창의
  동시 저장에서도 일정·학교 정보가 서로 덮어쓰이지 않으며 실패한 쓰기 뒤에도 재시도할 수 있다.
- 학교 정보 저장 중에는 버튼·Enter를 통한 질문 전송과 다시 질문을 막는다. 저장에 성공한
  공유 프로필만 질의 문맥으로 사용한다. 실패한 입력은 폼에서 유지한다.
- 분리 창에서 메인 학교 정보를 읽지 못하면 인라인 안내와 `학교 정보 다시 읽기`를 제공한다.
- 서버의 `grounded`, `insufficient_evidence`, `needs_user_input`, `failed`를 구분해 표시한다.
  추가 필드는 한국어로 안내하고, 졸업 판정은 별도 졸업감사가 필요하다는 안내를 표시한다.
- 응답 대기 중에는 중복 전송을 막는다. 실패·추가 정보 요구 시 입력을 유지하며 `다시 질문`은
  동일 대화 항목을 현재 질의 문맥으로 갱신한다. 요청 중 작성한 새 질문은 성공 후에도 보존한다.
- 근거 답변은 문서 제목·페이지·원문과 HTTP(S) 출처 열기 버튼을 함께 표시한다. 근거가 없으면
  목업 답변이나 졸업 기준으로 대체하지 않는다. 실제 백엔드의 PDF는 미승인이며 생성기는 미연결이다.
- HTTP 검증 오류, 서버 오류, 20초 시간 초과와 연결 실패는 인라인 재시도를 제공한다.
  원본 서버 오류·질문은 로그에 남기지 않는다. 공통 오류의 입력 필드와 문의 식별자를 표시한다.
- 기본 API 주소는 `http://127.0.0.1:8010`; `--dart-define=API_BASE_URL=...`로 바꾼다.
  Web은 고정 포트 3000과 백엔드 CORS 허용 주소를 맞춘다.

## 현재 경계

- 대화 이력은 현재 창의 메모리에만 유지하며 도킹과 분리 창 사이에 동기화하지 않는다.
  학교 질의 문맥만 기기 로컬 프로필을 공유하며 분리 창에는 IPC로 전달한다.
  서버 대화 저장·재조회·졸업 판정·인증·개인 기록 API는 아직 없다.
- 창의 실제 열림과 대화 상태는 영구 저장되지 않는다. 열기 방식 설정만 기기에 저장한다.
- 백엔드 구현과 공개 계약은 [학교 질의 API](../../api/assistant.md) 및 OpenAPI를 따른다.
  백엔드 PR #8의 구현도 이 연동 브랜치에 포함하여 같은 체크아웃에서 공통 환경을 실행할 수 있다.

## 후속 계약·검증

### 좁은 Web 하단 패널 검토 — 미채택

- 우측 오버레이는 채팅이 닫혔을 때 본문 높이를 유지하지만 열린 상태에서 다른 본문·세로
  스크롤바를 가릴 수 있다. 이번 수정은 홈 주간표 접근을 보장하며 전체 본문 가림 해소는 아니다.
- 하단 패널은 본문과 가로·세로 손잡이를 덮지 않는 장점이 있다. 다만 패널 높이 280px·분리선
  6px을 가정하면 900×768에서는 나머지 프레임이 482px, 480×520에서는 234px이다.
  실제 본문은 여기서 작업 공간 상단 52px와 세로 여백 56px도 제외하므로 낮은 창에서 불리하다.
  이는 구현 측정이 아니라 현재 프레임 치수에 따른 가용 높이 계산이다.
- 제안: 좁은 Web의 충분한 높이(초기 검토 700px 이상)에서는 280px 시작·높이 조절 가능한
  비중첩 하단 패널을 시도하고, 낮은 높이는 40px 접힌 헤더를 기본으로 검토한다. 입력은 패널
  하단 고정, 대화만 스크롤하며 접기/재열기에서 대화와 포커스를 보존해야 한다.
  확대·최소 입력 높이·본문 최소 높이 검증 후 최종 임계값을 정한다.
- 이번 목표의 판단: 하단 배치는 후속 UX 후보로 권장하되 채택·설정·공통 강제 규칙을 만들지 않는다.
  Windows 기본 분리/최대화 도킹 정책과 별개다.

- HTTP 모델/상태 처리, 입력 보존·재시도·중복 차단·늦은 응답 폐기와 합성 근거 표시를 테스트한다.
  `dart run tool/smoke_assistant_api.dart`는 실제 로컬 백엔드의 개발 상태를 검증한다.
- Web의 열기·닫기·좁은 폭 오버레이와 Windows의 열기·닫기·분리·전면화 동작을 검증한다.
- 이번 변경 검증: 전체 테스트 166개, 추가 인라인 폼 220/360/480px·200% 확대 3개,
  정적 분석과 Web·Windows 빌드 통과. 학교 프로필 양방향 저장·계획/일정 보존·실패 시
  미저장 문맥 차단은 `shared_school_context_test.dart`에서 확인한다.
- 실제 Windows 메인/분리 창 간 조회·저장·변경 알림 IPC는 런타임 수동 검증이 남아 있다.
- 2026-10-11 `develop` 통합 검증: Flutter 정적 분석과 전체 175개 테스트, Web Release 빌드,
  공통 Docker의 백엔드 91개 테스트·8개 하위 테스트 및 실제 API smoke를 통과했다.
  브라우저에서 채팅↔설정 학교 정보 공유, 저장된 문맥 전송, 480px 폼 스크롤,
  연결 실패 후 재시도와 졸업 판정 분리를 확인했다. 학교 정보·일정 동시 저장의 데이터
  유실을 재현한 회귀 테스트와 읽기/저장 실패·재시도·Enter 전송 차단 테스트를 추가했다.
