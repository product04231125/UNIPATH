# 공통 관리자 작업 공간

## 현재 구현

- 상단의 역할·학교 선택·활성 범위와 공통 메뉴는 두 역할이 공유한다. 슈퍼관리자는 전체 학교와
  학교 등록·수정·기존 합성 사용자 범위 부여/회수·계정 정지를 관리한다. 학교관리자는 허용 범위만 관리한다.
- 학교·학과, 교육과정·과목·과목 연결, 졸업요건·공식 문서의 목록·상세·등록·수정을 제공한다.
  참조 없는 초안은 삭제할 수 있다. 확인에는 참조 개수·접근 가능한 항목을 표시하고 참조가 남으면 차단한다.
- 모든 편집·범위 회수는 InputDialog의 폐기 확인·무변경 취소·저장 중 차단·실패 입력 보존을 사용한다.
- 규칙·문서는 검토·목업 적용 확인, 기존 버전 보존·새 버전 초안, 적용자·시각을 표시한다.
  문서 출처 HTTP(S)·종류·적용 범위·기간·관련 규칙 버전과 원문 열기를 제공한다.
- `/admin/<메뉴>/<목업 ID>` 상세는 종류·최신 계정 상태·활성 범위를 확인한다. 범위 회수·정지 시 접근 불가다.
  읽기 실패는 다시 읽기를 제공하고, 작업 실패는 원본을 보존해 같은 행동을 재시도할 수 있다.
- Router가 repository를 소유해 메뉴 이동·로그아웃·샘플 재진입 동안 목업을 보존한다.
  앱 재시작은 합성 초기값으로 돌아가며 학생 개인 저장소는 변경하지 않는다.

개발 로그인에서 학생/학교관리자/슈퍼관리자를 선택한다. 관리자 두 역할은 공통 셸과
`/admin/...` hash 경로를 사용하며 역할에 따라 메뉴를 구분한다. 학생의 관리자 직접 진입과
학교관리자의 관리자 관리 경로는 접근 불가 상태다. 로그아웃은 `/login`으로 복귀한다.

## 목업·계약 경계

`AdminRecord`·`admin_fields.dart`의 key·옵션은 임시 클라이언트 스키마다.
이수구분·필수 여부는 CurriculumCourse 연결에 두고 규칙 조건 설명은 실제 rule_definition이 아니다.
하위 범위 관리자도 해당 학교 과목을 조회·연결할 수 있지만 학교 전체 범위 없이 과목 원본을 수정할 수 없다.
실제 규칙 묶음·하위 규칙 복제, 적용 버전 선택, 문서 승인, 이력 보관과 역할/범위·오류 응답 계약은
OpenAPI 확정 후 모델·adapter·테스트를 교체한다.

`AdminRepository` 뒤의 `FakeAdminRepository`는 합성 학교·사용자·범위를 메모리에만 유지한다.
모든 변경은 최신 계정 상태·역할·활성 범위를 검사한다. 범위 부여는 기존 합성 사용자를
학교관리자로 바꾸고 회수는 원본 범위를 보존한다. 자기 계정 정지·임의 역할 승격은 지원하지 않는다.
초안 적용은 목업 상태 변경이며 실제 학교 승인·Rule Engine 적용이 아니다. 적용 버전은
직접 수정/삭제하지 않고 새 초안으로 복사한다. 참조가 있는 삭제는 차단한다.
실패는 원본을 유지하고 메타데이터 이력만 기록한다. 관리자 데이터는 학생 저장소와 분리된다.

실제 인증·권한·관리자 API는 없다. 역할·범위는 개발용이며 학생 개인 저장소와 분리한다.
관리자 서버 권한 검증·최초 계정 생성·DB 및 파일 영구 저장은 백엔드 계약 작업이다.
CSV·PDF·RAG·졸업 판정은 이번 범위가 아니다.

## 검증

`admin_workspace_test.dart`는 종류별 입력·보호, 계정/범위 조작·초안 적용·버전·삭제 참조,
480×520·200% 확대·키보드·읽기 실패/재시도를 검사한다.

`admin_navigation_test.dart`가 두 역할의 진입·메뉴 차이·로그아웃·학생 직접 경로 차단과
좁은 로그인 좌우 버튼 배치를 검사한다.
`admin_repository_test.dart`는 학교 간 접근 차단·계층 소속·중복 범위·회수·정지·
버전 보존·삭제 참조·실패/재시도 및 안전한 문서 출처를 검사한다(6개 통과).
