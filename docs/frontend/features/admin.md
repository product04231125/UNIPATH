## 졸업요건의 종류별 조건 연결 (2026-10-25)

- 등록/수정 폼은 한 줄 요건 설명과 종류별 계산 입력을 구분한다. 학점·봉사 최소량, 필수 과목과 선택 최소 학점/평점·척도, 활성 자격증, 논문·작품 유형/승인/허용 성적, 기타 수동 확인 조건을 기존 실행 조건 DTO로 보낸다.
- `요건 설명 저장`은 기존 학사 API를 사용하고 서버가 반환한 UUID를 유지한다. 입력창을 닫거나 요건을 다시 생성하지 않고 계산 조건 작성을 이어간다. 종류 전환 시 조건 초안을 보존하고 미저장 조건도 폐기 확인에 포함한다.
- 실행 조건 API는 적용된 메타데이터를 요구한다. 사용자가 명시적으로 `요건 검토·적용`을 선택하며 묶음 소속이면 묶음 전체 적용을 확인한다. 적용본 목록/상세에는 `계산 조건` 진입점을 제공하고 설명은 읽기 전용이다.
- `계산 조건 초안 저장`은 기존 `/admin/rule-programs` POST/PUT을 사용한다. 입학연도·이수 경로와 실제 승인 문서의 페이지/문단을 사용자가 선택한다. 학교·범위가 맞는 승인 문서, 경고 없는 본문만 선택지로 제공하며 최종 적합성은 서버가 검증한다. 기존 묶음 초안 수정은 다른 요건·근거·버전을 보존한다.
- 422 입력 오류는 해당 입력에 표시하고 값을 보존한다. 409/결과 불명은 쓰기를 잠근 뒤 목록 재조회·초안 재선택으로 복구한다. 생성 응답 유실을 새 POST로 자동 재전송하지 않는다. 참조 과목/자격 버전 변경은 다시 검토·선택해야 한다.
- 이 연결은 실행 **초안 저장**이며 자동 승인이나 학생 졸업 판정이 아니다. 승인·회수/전체 검토 절차를 이 폼에 추가하지 않았다. 새 API·학교 확정 기록·임의 근거를 만들지 않는다. 샘플은 실제 조건 저장 성공을 표시하지 않는다.
- 학생 폼은 기존 개인 계산 이력 API로 연결한다. [통합 검증 및 제한](../verification/requirement-api-connection-2026-10-25.md).

## 목업·계약 경계

`AdminRecord`·`admin_fields.dart`의 key·옵션은 임시 클라이언트 스키마다.
이수구분·필수 여부는 CurriculumCourse 연결에 두고 규칙 조건 설명은 실제 rule_definition이 아니다.
하위 범위 관리자도 해당 학교 과목을 조회·연결할 수 있지만 학교 전체 범위 없이 과목 원본을 수정할 수 없다.
실제 규칙 묶음·하위 규칙 복제, 적용 버전 선택, 문서 승인, 이력 보관과 역할/범위·오류 응답 계약은
OpenAPI 확정 후 모델·adapter·테스트를 교체한다.

`AdminRepository` 뒤의 `FakeAdminRepository`는 합성 학교·사용자·범위를 메모리에만 유지한다.
모든 변경은 최신 계정 상태·역할·활성 범위를 검사한다. 범위 부여는 기존 합성 사용자를
학교관리자로 바꾸고 회수는 원본 범위를 보존한다. 자기 계정 정지·임의 역할 승격은 지원하지 않는다.
초안 적용은 목업 상태 변경이며 실제 학교 승인·Rule Engine 적용이 아니다. 적용 버전은
직접 수정/삭제하지 않고 새 초안으로 복사한다. 참조가 있는 삭제는 차단한다.
실패는 원본을 유지하고 메타데이터 이력만 기록한다. 관리자 데이터는 학생 저장소와 분리된다.

실제 인증·권한·관리자 API는 없다. 역할·범위는 개발용이며 학생 개인 저장소와 분리한다.
관리자 서버 권한 검증·최초 계정 생성·DB 및 파일 영구 저장은 백엔드 계약 작업이다.
CSV·PDF·RAG·졸업 판정은 이번 범위가 아니다.
