# 학교 발급 자료 제출과 검토

실제 계정의 졸업 요건에서 `학교 발급 PDF 제출·이력`, 관리자 관리 현황에서
`학교 발급 원본 검토`로 진입한다. 샘플 계정에는 이 진입을 노출하지 않는다.

원본 제출은 등록 학교(필수), 학과·교육과정(선택), 종류, 발급일, 2 MiB 이하 PDF,
관리자의 원본·검토 이력 열람에 대한 명시적 동의를 받는다. 개인 기록 전체의 열람 동의가 아니다.
기존 바이너리 API를 사용하며 기기 자료 보관함으로 자동 복제하지 않는다.
실패 시 파일과 입력 및 동일 키를 보존한다. 결과 불명 상태에서 변경한 내용의 전송은 막는다.
작성 중 취소는 폐기 확인을 제공한다.

목록·상세·다운로드·검토 이력·본인 검토 허용 철회를 제공한다. 관리자는 제출본의 원본을
내려받고 발급기관과 제출자 신원을 각각 확인한 뒤 현재 버전·해시로 원본 확인 승인한다.
반려/확인 회수는 사유를 받는다. 본인 원본의 직접 승인은 표시하지 않으며 서버 권한 검사를 따른다.
변경 실패 후에는 현재 상세를 다시 읽고 검토하도록 요구한다. 자동 재전송은 없다.

원본 확인은 정규화한 학생 기록 승인이나 졸업 판정이 아니다.
실제 학교의 발급·신원 확인과 운영 서버 승인은 이 프런트엔드 합성 검증에 포함되지 않는다.
[원본 계약](../../api/official-record-sources.md), [검증](../verification/official-sources-ui.md)을 따른다.

## 학교 확인 학생 기록

동일 진입 영역의 `학교 확인 학생 기록`에서 학생은 본인 승인 이력·상세·기록별 원본 쪽과
현재 감사 입력 사용 가능 여부를 조회한다. 관리자는 허용 범위의 초안/승인 이력과 확인된 원본을
조회하고 원본에서 성적·봉사·자격·논문 기록을 직접 대조해 초안을 등록/수정한다.

과목과 자격은 등록 목록의 UUID·판을 사용한다. 원문 성적은 보존하고 숫자 평점·척도는
원본에 있을 때만 함께 입력한다. 미확인 시간·완료 여부·유효기간은 null/미확인 상태를 유지한다.
전체/일부 검토와 기록 0건을 구분하고, 기준일·쪽수·원본 페이지 대응을 검증한다.
신규 저장 실패는 입력·행·동일 키를 보존하며 결과 불명일 때 변경한 본문을 보내지 않는다.

승인은 내용/페이지·학적 문맥·전체/일부 검토 범위의 독립 확인 3개, 현재 기록 판과 원본 해시를
전송한다. 본인 직접 승인은 차단하고 서버 권한을 따른다. 승인 후 수정 대신 별도 검토가 필요하다.
사유가 필요한 초안 폐기·승인 회수, 검토 이력과 상세 다시 읽기를 제공한다.
같은 문맥의 기존 승인 교체를 지정하는 UI는 제공하지 않으며 서버 충돌을 표시한다.
승인은 해당 기록의 검토 결과이고 졸업감사 판정은 별도다.
[학생 기록 계약](../../api/official-student-records.md), [검증](../verification/official-records-ui.md)을 따른다.
