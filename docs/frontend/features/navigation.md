# 메뉴 URL 탐색

## 현재 구현

- Flutter SDK Router로 주요 메뉴 선택과 URL을 연결한다. Web은 기본 hash 전략을 사용해
  `/#/schedule`처럼 진입하며 별도 서버 rewrite나 라우터 패키지를 추가하지 않는다.
- 경로는 `/home`, `/schedule`, `/courses`, `/graduation`, `/activities`, `/experiences`,
  `/credentials`, `/portfolio`, `/settings`다. `/`는 홈이다. 메뉴 선택은 새 탐색 항목으로
  보고하며 브라우저 뒤로·앞으로 변경은 같은 Workspace의 선택 메뉴를 갱신한다.
- 직접 진입·새로고침은 주소의 메뉴를 연다. 모달·빠른 추가 의도·목업 스위치·채팅 열림·
  포트폴리오 하위 단계는 URL에 저장하지 않는다. 일반 URL 진입으로 추가 폼을 열지 않는다.
- 알 수 없는 경로는 오류 안내와 홈 이동을 제공한다. 쿼리는 기능 입력/API 매개변수로 해석하지 않는다.

## 목업 경계

- 로그인은 기존 메모리 내 목업 그대로다. 주소는 인증·권한의 증명이 아니며 실제 세션이나 토큰을
  만들지 않는다. 로그인 전 메뉴 주소로 들어오면 로그인 목업을 표시하고 성공 뒤 요청 메뉴를 연다.
- 새로고침에서는 목업 로그인 상태가 사라지므로 다시 로그인해야 한다. 요청 메뉴 주소는 유지한다.
  로그아웃은 `/login`으로 현재 주소를 대체한다. 뒤로 돌아와도 로그인 상태를 복원하지 않는다.
- Windows도 같은 Router로 메뉴를 선택하지만 브라우저 주소/기록 UI는 없다. OS 창 동작과 별개다.

## 검증과 후속 계약

- `app_navigation_test.dart`는 9개 직접 진입, URL 보고 유형, 외부 주소 변경의 뒤로/앞으로 대응,
  Workspace 유지, 새로고침·목업 로그인 후 요청 메뉴 복원과 미등록 경로 복구를 검사한다.
- `input_dialog_test.dart`의 홈 빠른 추가 검사는 URL 연동 뒤에도 팝업을 한 번만 열고 일반 탐색에서는
  열지 않는지 검사한다. 실제 IAB에서 /schedule 직접 진입, /activities 이동, 뒤로·앞으로와
  새로고침 뒤 요청 주소 유지·목업 진입 후 복원을 확인했다. 실행 근거는 검증 문서에 구분한다.
- 인증 API·역할·세션 만료 계약이 정해지면 로그인 경계를 교체한다. 이번 작업에서 보호 경로 권한이나
  서버 리디렉션 정책을 정의하지 않는다.
