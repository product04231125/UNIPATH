# 메뉴 URL 탐색

관리자 개발 세션은 `/admin/overview`, `/admin/schools`, `/admin/curricula`, `/admin/rules`,
`/admin/documents`, `/admin/history`, `/admin/accounts` hash 경로를 사용한다. 메뉴 아래 목업 ID를
붙인 상세 경로는 종류·현재 역할·활성 범위를 확인한다. 로그아웃은 기존 `/login`으로 복귀한다.

## 현재 구현

- 2026-11-08: 학생 작업 공간에서 예시 데이터 표시를 끄고, 펼친/접힌 사이드바의 목업 전환 항목을 제거했다. 개인 입력·서버 기록과 빈 상태는 유지하며 격리된 fixture는 테스트에서만 명시적으로 사용할 수 있다.

- Flutter SDK Router로 주요 메뉴 선택과 URL을 연결한다. Web은 기본 hash 전략을 사용해
  `/#/schedule`처럼 진입하며 별도 서버 rewrite나 라우터 패키지를 추가하지 않는다.
- 경로는 `/home`, `/schedule`, `/courses`, `/graduation`, `/activities`,
  `/credentials`, `/portfolio`, `/job-postings`, `/settings`다. `/`는 홈이다.
  `/portfolio`는 자료, `/job-postings`는 채용공고 분석이다. 이전 `/experiences`는
  활동 화면(`/activities`)을 연다. 메뉴 선택은 새 탐색 항목으로
  보고하며 브라우저 뒤로·앞으로 변경은 같은 Workspace의 선택 메뉴를 갱신한다.
- 직접 진입·새로고침은 주소의 메뉴를 연다. 모달·빠른 추가 의도·목업 스위치·채팅 열림·
  포트폴리오 하위 단계는 URL에 저장하지 않는다. 일반 URL 진입으로 추가 폼을 열지 않는다.
- 알 수 없는 경로는 오류 안내와 홈 이동을 제공한다. 쿼리는 기능 입력/API 매개변수로 해석하지 않는다.

## 목업 경계

- 로그인은 기존 메모리 내 목업 그대로다. 주소는 인증·권한의 증명이 아니며 실제 세션이나 토큰을
  만들지 않는다. 로그인 전 메뉴 주소로 들어오면 로그인 목업을 표시하고 성공 뒤 요청 메뉴를 연다.
- 새로고침에서는 목업 로그인 상태가 사라지므로 다시 로그인해야 한다. 요청 메뉴 주소는 유지한다.
  로그아웃은 `/login`으로 현재 주소를 대체한다. 뒤로 돌아와도 로그인 상태를 복원하지 않는다.
- Windows도 같은 Router로 메뉴를 선택하지만 브라우저 주소/기록 UI는 없다. OS 창 동작과 별개다.

## 검증과 후속 계약

- `app_navigation_test.dart`는 메뉴 경로마다 직접 진입, 이전 `/experiences`의 활동 복원, URL 보고 유형, 외부 주소 변경의 뒤로/앞으로 대응,
  Workspace 유지, 새로고침·목업 로그인 후 요청 메뉴 복원과 미등록 경로 복구를 검사한다.
- `input_dialog_test.dart`의 홈 빠른 추가 검사는 URL 연동 뒤에도 팝업을 한 번만 열고 일반 탐색에서는
  열지 않는지 검사한다. 실제 IAB에서 /schedule 직접 진입, /activities 이동, 뒤로·앞으로와
  새로고침 뒤 요청 주소 유지·목업 진입 후 복원을 확인했다. 실행 근거는 검증 문서에 구분한다.
- 인증 API·역할·세션 만료 계약이 정해지면 로그인 경계를 교체한다. 이번 작업에서 보호 경로 권한이나
  서버 리디렉션 정책을 정의하지 않는다.

## 상단·작업 공간 개편 (2026-10-14)

- 상단 뒤로/앞으로는 로그인한 역할의 앱 탐색 이력을 이동한다. 로그아웃 때 이력을 비운다. 사이드바 숨김은 자동 아이콘화와 독립적이며 상단에서 다시 열 수 있다. 방문한 학생 페이지는 실행 중 상태를 유지하며 숨겨진 페이지의 포커스·애니메이션을 제외한다.
- 구현·검증과 환경 한계는 [1·2·4 검증 기록](../verification/ux-124-verification.md)을 따른다.

### 2026-10-15 사이드바 학업 정보
- 고정 이름·학번·학과를 제거했다. 이름 계약이 없어 내 학업 정보로 표시한다. 저장된 PlanningProfile의 학교·학과·입학연도를 표시하고(현재 실제 일반 계정은 서버 저장, debug 샘플은 기기 저장), 부재/읽기 중/실패 상태를 구분한다. 입학연도를 학번으로 표시하지 않는다.
- workspace_ux_test의 sidebar uses available academic profile로 미설정/저장 정보를 검증한다.

### 작은 창의 메뉴 이동 중 사이드바 안정성 (2026-10-15)
- 900~1023px에서 홈은 주간표 공간을 위해 아이콘 탐색이었지만 설정·활동·일정으로 이동하면 본문 최소 폭이 0으로 바뀌어 글자 메뉴가 펼쳐졌다. 작은 창 시작 후 버튼 클릭으로 본문이 밀리는 원인이었다.
- 학생 화면 공통으로 홈의 기본 최소 본문 폭을 유지한다. 졸업 비교표가 더 넓으면 추가 요구 폭도 적용한다. 창 폭이 같은 동안 홈→다른 메뉴의 기본 폭 감소로 사이드바를 펼치지 않는다. 넓어진 창에서는 기존 폭 판단으로 펼친다.
- workspace_ux_test의 compact startup navigation 480/900/1000px 3건에서 사이드 메뉴·홈의 전체 일정 링크·1440px 확장을 확인했다. 전체 278건 중 276건 통과 후 테스트 배치 오류/이전 페이지별 확장 기대 2건을 정리하고 영향 5건을 재검증했다. 테스트 명령 5회(최초 재현 실패 포함), 분석·Web/Windows 빌드 각 1회.

- 실제 Web 900×768의 홈 시작 → 설정 → 홈의 활동 기록 버튼 이동에서도 아이콘 사이드바 유지 확인. 이미지: frontend/build/sidebar-home-900.png, sidebar-settings-900.png. 공용 팁 확인은 기존 Python 위치/Git fetch 환경 오류로 실패했으며 제품 검증과 구분한다.

## 휴대폰 세로 Web 하단바 (2026-11-03)

- 가용 폭 `< 600` 이고 `height / width > 1.6`이면 학생 좌측 사이드바 대신 하단바를 쓴다.
  예: `360×800`, `390×844`, `430×932`, `450×900`. `480×520`·정확 `480×768`·`900×768`은 기존 좌측 메뉴다.
- 하단바 주 목적지: 일정, 졸업 요건, 홈, 자료, 채용공고 분석. 더보기는 세로 목록이 아니라
  하단 가로 스트립(아이콘+라벨)으로 나머지 목적지(사이드 순: 수강 관리, 활동, 자격, 설정)를
  두고, 로그아웃은 그 아래 가로 행동 줄에 둔다. 계정 보안은 더보기에 두지 않는다. 목업
  토글은 두지 않으며 예시 데이터는 끈다. 사이드바 순서는 홈·일정·수강 관리·졸업 요건·활동·
  자격·자료·채용공고 분석·설정이다. 경험·포트폴리오·성과 메뉴는 학생 탐색에서 빼 둔다.
- Web 휴대폰에서는 상단 뒤로/앞으로·사이드바·제목 줄을 숨긴다. Windows 휴대폰 비율 창은
  창 제어만 남긴다. 메뉴 설명은 Web/PC/휴대폰이 같은 한 줄이며 휴대폰에서만 저장 위치 안내를 숨기지 않는다.
- AI 전용 보기가 열린 동안과 가상 키보드가 열린 동안 하단바를 숨긴다. 휴대폰 비율에서는
  `480px` 작업 공간 가로 스크롤 fallback을 쓰지 않는다.
- 휴대폰에서만 하단바 높이 56, 페이지 제목 22, 헤더 아래 간격 12, 본문 패딩 12다. 계정 보안은
  Web/PC/휴대폰 모두 설정 `계정·정보`이며 제목표시줄·더보기에는 두지 않는다.
- `phone_shell_test`가 대표 세 크기·더보기·AI 숨김·1440 좌측 메뉴·`480×520` 아이콘 레일을 검사한다.
  모바일 합격으로 `480×520`을 쓰지 않는다. 인증 후 `390×844` 브라우저 실기는
  [휴대폰 셸 검증](../verification/phone-shell-2026-11-03.md)을 따른다.
