# 인증과 계정

일반 로그인·회원가입은 실제 FastAPI 계정·세션 API에 연결한다. 계약과 최초 운영자
생성은 [인증 API](../../api/authentication.md), 정확한 DTO는 [OpenAPI](../../api/openapi.json)를 따른다.

- 기존 테마·폼·비밀번호 표시를 유지한다. 가입 비밀번호는 15~128자, 이름은 최대 128자다.
  중복 제출/모드 변경을 막고 실패 시 입력·오류 안내·재시도 경로를 유지한다.
- Web은 HttpOnly 쿠키, Windows는 프로세스 메모리 토큰을 사용한다. 비밀번호·토큰을
  SharedPreferences에 저장하지 않는다. 로그아웃은 서버 세션을 종료한 뒤 화면을 전환하며
  통신 실패 시 로그인 상태를 유지한다.
- 역할은 서버 응답의 user/school_admin/super_admin으로 결정한다. 실제 관리자는 DB의
  학교 범위 화면을 사용한다. 합성 학사 편집기는 개발 샘플 진입 전용이며 Release에는 없다.
- 클라이언트는 60초 간격/앱 복귀 시 신원을 갱신하고, 서버는 매 요청 현재 권한을 확인한다.
  만료 401이면 로그인으로 돌아가되 통신 실패만으로 세션을 폐기하지 않는다.
- 실제 일반 계정의 학업 프로필·일정·개인 자료·구성·지원 문서는 서버 저장이며 기기 원본/debug는 사용자 UUID별로 분리한다. 기존 익명 자료를 자동 귀속하지 않는다. 본인 기기 프로필·일정 이전은 동의 후 진행하며 다른 개인 자료 10종도 별도 동의 이전을 제공한다. 이메일 검증/복구·SSO는 후속 작업이다.

검증은 auth_integration_test.dart의 실제 HTTP 계약·토큰 비영속성·입력 보존·중복 제출·
서버 관리자 역할 진입·계정별 자료 격리 및 기존 탐색/기록/설정 테스트를 사용한다.

## 계정 보안

실제 AuthApi를 사용하는 세 역할은 공통 제목표시줄의 `계정 보안`을 사용한다.
입력은 공통 InputDialog로 표시하며 현재·새 비밀번호·재입력, 표시/숨기기와
별도 확인 후 모든 기기 로그아웃을 제공한다. 15~128자를 유지하고 공백을 자르지 않는다.
실패 시 입력을 보존하고 불명확한 응답은 자동 재전송하지 않는다. 세션 확인 뒤 명시적으로
같은 요청을 재시도하며, 401만 확인한 경우 변경·전체 세션 종료 성공으로 표시하지 않는다.
확인된 성공은 모든 세션을 종료하고 로그인 화면에 완료 안내를 남긴다.
일반 작업 공간과 관리자 작업 공간 모두 같은 진입점을 사용하며 개발 샘플에는 표시하지 않는다.
자세한 수명·동시 로그인 처리와 검증은 [계정 보안 연결](../../api/account-security-integration.md)을 따른다.

## 학교관리자 최초 가입·학교 신청

회원가입에서 `학생` / `학교관리자`를 선택한다. 학생은 기존 일반 가입 API를 사용한다.
학교관리자는 이름·이메일·비밀번호·확인에 더해 학교명(필수·128자), 공식 홈페이지
(선택·2048자·http/https), 직책(필수·128자), 연락 이메일(필수·254자), 사유(필수·1000자)를
입력한다. [최초 접수 API](../../api/initial-school-admin-signups.md)는 계정·학교 신청·세션을
원자적으로 저장한다. 승인 전 계정은 `user`이며 학교와 관리 범위는 자동 생성하지 않는다.
확인된 응답만 접수 번호·승인 대기로 표시하고 `계속하기`로 일반 계정 작업 공간에 진입한다.
실제 서버 연결이 없는 개발 샘플에서는 접수를 차단한다.

결과가 불명확하면 입력과 client_id를 보존하고 같은 요청으로 재확인한다. 이때 가입 필드와
유형 변경을 잠그며, 다른 입력을 새 접수처럼 보내지 않는다. 로그인으로 전환해 본인 이력을
확인할 수 있다. 비밀번호를 영속 저장하거나 학교 정보를 기존 reason에 합치지 않는다.

## 기존 계정의 학교 관리 권한·신청 이력

공통 제목표시줄의 `학교 관리 권한·신청 이력`에서 `등록된 학교`와 `미등록 학교`를 선택한다.
등록된 학교는 기존 UUID 기반 [권한 신청 API](../../api/school-admin-applications.md)를 사용한다.
미등록 학교는 최초 접수와 같은 학교 메타데이터 계약의 본인 신청 API를 사용한다.
학교 목록이 비어도 미등록 학교를 신청할 수 있고 두 유형의 초안은 창 안에서 따로 유지한다.
신청자 이름은 로그인 계정의 읽기 전용 표시다. 같은 입력 재시도는 같은 client_id를 사용한다.
서버가 반환한 이력·검토 사유·상태·대기 취소·추가 읽기를 제공하며 실패 시 입력을 보존한다.
입력창을 닫을 때 공통 폐기 확인을 사용하고 앱 재시작 시 초안을 복원하지 않는다.

## 슈퍼관리자 심사

`학교관리자 신청 접수`(`/admin/applications`)는 등록 학교 권한 신청과 최초·미등록 학교 접수를
구분한다. 목록·상태 필터·추가 읽기·상세·승인/반려를 제공하며 학생과 학교관리자는 접근할 수 없다.
최초·미등록 학교 심사는 입력 보호 대화상자에서 기존 학교 연결/새 학교 등록을 명시적으로 선택하고
신원·담당자 소속 확인과 신청자에게 보이는 검토 사유를 요구한다. 학교·신청·신청자 버전을 서버가
검증한다. 학교명 일치로 기존 학교에 자동 연결하거나 이메일만으로 소속을 인증하지 않는다.
충돌·응답 불명은 쓰기를 잠그고 현재 결과를 다시 확인한다. 권한 상실 시 신청자 개인정보와 제어를
숨기고 목록을 비운다. 자동 학교 인증·증빙 업로드는 별도 후속 작업이다.

검증: `school_signup_flow_test.dart`의 실제 HTTP 계약/위젯 검증과 기존 가입·권한 신청·심사·
미등록 학교·권한 상실 회귀를 사용한다. 480×520/1440×900, 심사 글자 크기 200%를 확인했다.
분리 브랜치의 [가입 폼 준비 기록](../verification/school-admin-signup-2026-10-25.md)과
[미등록 학교 입력 준비 기록](../verification/unregistered-school-application-ui.md)은 통합 전
이력이며 당시의 미지원·미저장 설명은 현재 구현 상태를 뜻하지 않는다. Windows 네이티브 실기
검증은 별도로 진행한다.
