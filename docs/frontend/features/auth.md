# 인증과 계정

일반 로그인·회원가입은 실제 FastAPI 계정·세션 API에 연결한다. 계약과 최초 운영자
생성은 [인증 API](../../api/authentication.md), 정확한 DTO는 [OpenAPI](../../api/openapi.json)를 따른다.

- 기존 테마·폼·비밀번호 표시를 유지한다. 가입 비밀번호는 15~128자, 이름은 최대 128자다.
  중복 제출/모드 변경을 막고 실패 시 입력·오류 안내·재시도 경로를 유지한다.
- Web은 HttpOnly 쿠키, Windows는 프로세스 메모리 토큰을 사용한다. 비밀번호·토큰을
  SharedPreferences에 저장하지 않는다. 로그아웃은 서버 세션을 종료한 뒤 화면을 전환하며
  통신 실패 시 로그인 상태를 유지한다.
- 역할은 서버 응답의 user/school_admin/super_admin으로 결정한다. 실제 관리자는 DB의
  학교 범위 화면을 사용한다. 합성 학사 편집기는 개발 샘플 진입 전용이며 Release에는 없다.
- 클라이언트는 60초 간격/앱 복귀 시 신원을 갱신하고, 서버는 매 요청 현재 권한을 확인한다.
  만료 401이면 로그인으로 돌아가되 통신 실패만으로 세션을 폐기하지 않는다.
- 실제 일반 계정의 학업 프로필·일정·개인 자료·구성·지원 문서는 서버 저장이며 기기 원본/debug는 사용자 UUID별로 분리한다. 기존 익명 자료를 자동 귀속하지 않는다. 본인 기기 프로필·일정 이전은 동의 후 진행하며 다른 개인 자료 10종도 별도 동의 이전을 제공한다. 이메일 검증/복구·SSO는 후속 작업이다.

검증은 auth_integration_test.dart의 실제 HTTP 계약·토큰 비영속성·입력 보존·중복 제출·
서버 관리자 역할 진입·계정별 자료 격리 및 기존 탐색/기록/설정 테스트를 사용한다.

## 계정 보안

실제 AuthApi를 사용하는 세 역할은 공통 제목표시줄의 `계정 보안`을 사용한다.
입력은 공통 InputDialog로 표시하며 현재·새 비밀번호·재입력, 표시/숨기기와
별도 확인 후 모든 기기 로그아웃을 제공한다. 15~128자를 유지하고 공백을 자르지 않는다.
실패 시 입력을 보존하고 불명확한 응답은 자동 재전송하지 않는다. 세션 확인 뒤 명시적으로
같은 요청을 재시도하며, 401만 확인한 경우 변경·전체 세션 종료 성공으로 표시하지 않는다.
확인된 성공은 모든 세션을 종료하고 로그인 화면에 완료 안내를 남긴다.
일반 작업 공간과 관리자 작업 공간 모두 같은 진입점을 사용하며 개발 샘플에는 표시하지 않는다.
자세한 수명·동시 로그인 처리와 검증은 [계정 보안 연결](../../api/account-security-integration.md)을 따른다.

## 학교관리자 가입과 기존 권한 신청·접수 (2026-10-25)

회원가입 화면에서 `학생` / `학교관리자`를 선택한다. 학생은 이름·이메일·비밀번호·확인으로 기존
가입 API를 사용한다. 학교관리자는 같은 계정 정보 아래에 학교명(필수·128자), 공식 홈페이지
(선택·2048자·http/https), 직책(필수·128자), 연락 이메일(필수·254자), 신청 사유(필수·1000자)를
작성한다. 이름은 가입 계정 입력을 사용한다. 가입 유형과 로그인/가입 탭을 바꿔도 현재 화면의
입력은 유지하며, 화면 종료·앱 재시작 복원이나 비밀번호 영속 저장은 추가하지 않는다.

기존의 별도 ‘학교관리자 가입 신청’ 버튼과 일반 가입/로그인 후 자동 신청창 이동은 제거했다.
최초 학교관리자 가입 접수 API는 없다. 일반 가입 DTO에는 이름·이메일·비밀번호만 있고 기존
권한 신청은 로그인과 등록 학교 UUID가 필수다. 따라서 학교관리자 유형은 미접수·서버 미저장
안내와 비활성 `학교관리자 가입 신청 · 접수 준비 중`을 표시한다. Enter 제출도 막아 일반 계정을
대신 생성하지 않는다. 학교명·홈페이지를 기존 reason에 넣거나 임의 ID로 우회하지 않는다.
**최초 신청 → 승인 대기는 아직 미구현이며 백엔드 계약 의존성이다.**

이미 가입한 실제 계정의 추가 권한 신청/이력은 공통 제목표시줄 `학교 관리 권한·신청 이력`에서
기존 API로 제공한다. 최초 가입과 구별한다. 슈퍼관리자는 작업 공간의 `학교관리자 신청 접수`
(`/admin/applications`) 메뉴에서 서버 접수 목록·새로고침·상태 필터·상세·승인/반려를 사용한다.
접수 목록은 전체 학교 대상이라 현재 학교 선택을 표시하지 않는다. 학교관리자/학생은 메뉴와
직접 경로 접근을 차단한다. 개발 샘플은 실제 계정 필요 안내만 표시하며 가짜 접수를 생성하지 않는다.
기존 제목표시줄의 심사 접근도 유지한다.

기존 계정의 권한 신청자는 학교 카탈로그를 선택하고 직책·연락 이메일·사유를 제출한다. 본인 이력·검토 사유·대기 취소와 페이지 추가 읽기를 제공한다. 같은 입력 재시도는 같은 client_id를 사용하고 불명확한 응답 뒤 다른 입력을 새 신청처럼 보내지 않는다. 실패 입력·서버 필드 오류와 폐기 확인을 보존한다.

슈퍼관리자는 상태 필터·상세를 읽고 신원·학교 담당 확인과 신청자에게 보이는 검토 사유로 승인/반려한다. 자기 신청과 종료 신청은 심사할 수 없고 권한·경쟁/버전은 기존 API가 최종 확인한다. 새 API·자동 학교 인증·증빙 업로드는 구현하지 않았다.

심사 권한을 잃으면 신청자 상세와 승인/반려 제어를 숨기고 접수 목록을 비운다. 충돌·결과 불명
이후에는 닫고 최신 목록을 확인하도록 안내한다. [종합 검증](../verification/school-workflows-2026-10-24.md)을 따른다.

관련 계약은 ../../api/school-admin-applications.md, 구현은 school_admin_applications_dialog.dart다. 위젯/모의 HTTP는 가입 유형·입력 보존·미지원 제출 차단·접수 메뉴 접근, 신청 실패/동일키 재시도/입력 폐기 보호, 취소 확인, 승인·반려/소유자 헤더를 확인했다. 실제 서버 계정과 네이티브 실기는 이번 검증 범위 밖이다.

### 미등록 학교 입력 준비 (2026-10-24)

기존 계정용 권한 신청창에서 `등록된 학교`와 `미등록 학교`를 선택한다. 학교 목록이 비어도 유형 선택과 입력은
표시한다. 등록된 학교는 기존 API로 신청하고 `학교 목록 다시 읽기`로 새로 등록된 학교를 직접 선택한다.

미등록 학교는 학교명(필수·128자), 공식 홈페이지(선택·2048자·안전한 http/https), 로그인 계정의
신청자 이름(읽기 전용), 직책(필수·128자), 연락 이메일(필수·254자), 사유(필수·1000자)를 작성한다.
두 유형의 입력은 창 내부에서 따로 유지하고 유형 전환으로 지우지 않는다. 새 폼은 필수값·이메일·URL을
입력 중 검증한다. 작성 후 닫기는 공통 폐기 확인을 사용하며 창을 닫거나 앱을 재시작하면 복원하지 않는다.

미등록 학교 접수 API는 없어 `접수 연동 대기` 버튼은 항상 비활성이다. 폼 상단에 미접수·서버 미저장을
명시하고 서버 요청·임의 학교 ID·접수 이력·성공 안내를 만들지 않는다. 등록 학교 신청의 DTO나
관리자 학교 등록 권한도 변경하지 않는다. 접수 이력에는 서버가 반환한 신청만 표시한다.
[검증 기록](../verification/unregistered-school-application-ui.md)을 따른다.


가입 구조 정정과 접수 메뉴 검증은 [2026-10-25 기록](../verification/school-admin-signup-2026-10-25.md)을 따른다.
2026-10-24의 모달 입력 준비는 기존 계정의 권한 신청 흐름에 대한 이력이며 최초 가입 완료를 뜻하지 않는다.
