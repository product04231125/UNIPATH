# 홈

## 현재 구현

- 좁은 창에서 채팅이 열리면 주간표는 오버레이 폭을 제외해 배치한다. 마지막 날짜와 손잡이가
  채팅 밑에 숨지 않으며 날짜 이동은 채팅을 닫지 않아도 가능하다. 공통 가로 스크롤은 맞는 폭에서
  넘치는 폭으로 바뀔 때도 실제 범위에 맞춰 제스처를 갱신한다.


- 본문 스크롤바에 16px 여백을 예약하며 주간표 최소 폭에 합산한다. 메뉴 아이콘화 우선과
  초기 Windows 클라이언트 1424×861에서 빈/일정 3건 상태의 무스크롤 조건을 유지한다.

- 홈 `일정 추가`는 일정 메뉴 이동과 신규 입력 모달 열기를 한 번에 요청한다. 날짜 선택·
  기존 일정·일반 메뉴 이동은 해당 날짜 화면만 연다. 저장소 준비 전 요청은 대기하며 읽기 실패 시
  기존 데이터 보호/재시도를 유지한다. 준비 뒤 한 번 소비되어 재빌드·재진입에 중복 팝업이 없다.

- 본문 전체 폭에 날짜·오늘 일정 수·개인 계획 상태를 표시하고, 그 아래 7일 표를 배치한다.
  기본 데스크톱 폭에서는 요약 정보와 상태 칩을 가로로 정리하고, 다가오는 개인 일정 최대 3건,
  준비 상태(프로필/첫 일정), 다음 기록 링크를 세 열로 배치해 기본 Windows 창에 들어오게 한다.
  좁은 폭과 글자 확대에서는 세로 재배치·스크롤로 모든 행동에 접근할 수 있다.
- 하단 카드가 같은 행에 있을 때는 실제 줄바꿈된 내용의 최대 높이에 맞춰 상단·하단선을
  정렬한다. 고정 높이·내용 잘림 없이 3열/2열 배치를 유지하며 세로 배치에서는 자연 높이를 쓴다.
- 홈의 데스크톱 주간 표는 날짜별 일정 1건과 추가 건수를 요약한다. 날짜를 누르면 전체 목록을
  확인할 수 있다. 넓은 글자 확대 레이아웃은 기존 2건 미리보기를 유지하며, 일정 화면은
  중복 주간표 없이 월간 달력·선택 날짜 목록을 제공한다.
- 주간 표에서 이전/다음 주와 오늘로 이동할 수 있고, 날짜를 선택하면 일정 화면의 해당 날짜가
  열린다. 가로 공간이 부족하면 최소 날짜 칸 폭과 보이는 스크롤바를 유지한다.
  펼친 메뉴 때문에 날짜 칸이 부족해지면 메뉴부터 아이콘으로 접고, 그래도 부족할 때만
  주간표를 가로 스크롤한다. 카드 여백을 포함한 최소 폭은 732 logical px이다.

- 빠른 이동 카드 대신 기본 일요일부터 보이는 7일 개인 일정표, 준비 목록, 개인 계획 학년별 다음
  기록 링크를 보여 준다. 사용자는 설정에서 주 시작 요일을 바꿀 수 있고, 일정이 없는 날짜는
  `일정 없음`으로 표시한다.
- 준비 목록은 아직 입력하지 않은 `설정 > 학업과 계획`과 `일정`의 정확한 입력 위치로 이동한다.
- 개인 계획 학년은 로컬 프로필의 입학연도 기반 제안 또는 사용자의 직접 설정값이다. 공식 학적
  판정이나 서버 추천이 아님을 화면에 명시한다.
- 낮은 창에서는 홈 본문이 세로 스크롤되어 모든 링크에 접근할 수 있다.

## 목업 경계


- 이번 주 일정은 기기 로컬 개인 일정만 읽는다. 학교 공식 일정, 반복 일정, 알림, 외부 캘린더와
  MCP 연결은 아직 제공하지 않는다.
- 수강·활동·경험·졸업요건·포트폴리오 링크는 계획을 시작하기 위한 화면 이동일 뿐, 각 기록의
  충족 여부를 판정하지 않는다.

## 후속 계약·검증

### 채팅 열린 주간표 검증

- `chat_calendar_access_test.dart`: 1440×900·900×768·480×520, 글자 배율 1/2에서 채팅과
  주간표 경계 분리·손잡이 끝까지 드래그·가로 휠·마지막 날짜 클릭 후 일정 이동을 검사했다.
  교육과정 폭 전환·기본 Windows 홈·카드/헤더와 합친 관련 21개가 통과했다.
- 이 단위는 진단 포함 test 12회(렌더 출력용 비동기 중단 1회 포함)였다. 손잡이 드래그 실패의
  원인은 폭 전환 뒤 내부 제스처가 비어 있는 상태였으며 공통 위젯의 metrics 기반 갱신으로 수정했다.
  이미지·히트 경로·내부 제스처 진단 코드는 제거했다. 전체 suite와 analyze/build는 최종 안정화 때 한 번 수행한다.

- 서버 프로필·일정 계약이 생기면 `planning` repository를 해당 API adapter로 교체한다.
- 프로필 미설정, 일정 없음/있음, 7일 일정표, 학년별 링크, 좁은 폭과 낮은 높이를 위젯·수동으로
  검증한다.
- 공통 타이포그래피는 기본 테마의 색상·글꼴을 보존한다. Windows 플랫폼 위젯 테스트에서
  홈 제목·메뉴·본문의 밝은 배경 대비와 대화상자·목록 테마 색상 보존을 회귀 검증한다.
- Windows 기본 외곽 창 1440×900에서 제목 표시줄·테두리를 제외한 1424×861 클라이언트 영역을
  기준으로, 빈 상태와 긴 제목의 일정 3건 상태 모두 홈 스크롤 범위가 0임을 검증한다.
  높이를 600으로 줄이면 스크롤이 생기고, 글자 확대에서도 콘텐츠 접근을 유지한다.

## 메뉴 전환 순서 검증

- `workspace_ux_test.dart`의 `responsive order` 3개는 홈의 폭 축소·복원, 교육과정 탭과
  AI 도킹 폭, 320px Web 작업 공간 스크롤바의 드래그를 검사한다.
- 테스트 명령 5회: 신규 3개 검사 → 실패한 2개 재검사(카드 테두리 2px 누락 및 부동소수
  허용 오차 보완) → 전체 82개 중 81개 통과 → 기존 일정 테스트의 아이콘 탐색 대상 수정 후
  실패한 1개만 통과. 전체 검사는 한 번만 실행했으며 나머지 통과 결과는 재사용한다.
  마지막으로 480px fallback 경계에서 교육과정 탭을 보존하도록 키를 부여하고 해당 테스트
  1개만 재검사했다.
- 정적 분석과 Web·Windows 빌드는 첫 안정화 때 각각 한 번, 마지막 탭 보존 코드 변경을
  반영한 마무리 때 각각 한 번 검사한다(각 2회). 최종 결과는 모두 통과했다.
- 자동 검사 뒤 사용자가 Windows 메뉴 전환을 확인했다.

## 홈 하단 카드 정렬 검증

- `home lower cards` 4개는 빈 상태/일정 3건과 글자 배율 1/2에서 본문 폭 1100·900·700을
  확인한다. 같은 행 경계 좌표, 세로 배치의 자연 높이, 일정·설정·다음 기록 버튼을 검사한다.
- 기본 Windows 클라이언트 1424×861 무스크롤 2개, 좁은 폭·확대 회귀 8개와 함께 관련 14개 통과.
  테스트 명령 2회: 초기 ListTile intrinsic 높이 추정의 잘림을 발견한 뒤, 실제 레이아웃 높이로
  바꾸어 영향받은 홈 검사만 재실행했다. 전체 테스트는 반복하지 않았다.
- 분석·Web·Windows 빌드는 안정화 뒤 각각 한 번 통과했다. 사용자가 Windows 실제 화면의
  하단선과 시각적 균형을 확인하여 카드 정렬 작업을 마무리했다.
