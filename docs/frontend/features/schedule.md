# 일정

## 목적

학생이 과제, 개인 일, 활동, 마감을 자신의 계획으로 정리하고 이번 주와 월간 흐름을 확인한다.

## 현재 구현

- 좌측 탐색의 `일정`에서 월간 달력, 선택한 날짜의 목록, 이번 주 목록을 제공한다.
- 홈과 같은 7일 표를 사용하며 월간 요일·주간 시작일 모두 개인 설정을 따른다. 날짜를 선택하면
  해당 날짜의 목록으로 연결한다. 종료 시각이 자정이면 다음 날 일정으로 중복 표시하지 않는다.
- 월간 날짜 칸 높이는 글자 확대에 맞춰 늘어나고, 전체 본문은 낮은 창에서도 스크롤된다.
- 제목, 시작·종료 일시, 분류(학업·개인·활동·마감), 선택 메모로 개인 일정을 추가·수정·삭제한다.
- 프로필과 일정은 `SharedPreferences`의 기기 로컬 저장소에 보관되며 Web과 Windows에서 같은 화면을
  사용한다.
- 저장 성공 뒤에만 목록을 바꾸고 편집 창을 닫는다. 저장 실패 시 작성 제목·기간·분류·메모와
  기존 목록을 유지하고 편집 창에서 재시도를 제공한다. 저장 중 중복 저장·닫기를 막는다.
- 일정 삭제는 제목을 표시한 별도 확인 뒤 수행한다. 취소 또는 삭제 실패 시 기존 일정과
  편집 창을 유지한다. 읽기 실패는 원본을 덮어쓰지 않고 쓰기 차단·재시도 화면으로 표시한다.

## 목업 경계

- 이 기능은 개인 계획 전용이다. 학교 공식 학사일정, 반복 일정, 알림, 외부 캘린더, MCP 연결을
  생성하거나 추정하지 않는다.
- 현재 저장 형식은 API 계약이 아니라 클라이언트 로컬 어댑터의 임시 형식이다.

## 후속 계약·검증

- 서버 일정 API와 동기화·삭제·충돌 정책이 정해지면 local repository를 API adapter로 교체한다.
- 일정 CRUD, 재시작 뒤 로컬 저장, 달력·이번 주 표시, 좁은 창과 Web/Windows 빌드를 검증한다.

## 저장 안전성 보완 검증

- `planning_storage_test.dart` 7개: 저장 거부/예외, 읽기 오류·부분 데이터 차단, 복구,
  일정 저장 실패 입력 유지, 삭제 확인/취소/실패/재시도, 설정·홈·일정 읽기 오류 표시.
- 관련 검사 → 설정 테스트의 갱신 대기 및 복구된 입력란 확인 → 최종 전체 검사로 테스트 명령 3회.
  전체 77개 통과. `flutter analyze`는 중괄호 스타일 1건 수정 후 문제 없음(2회).
- `flutter build web`·`flutter build windows` 각각 1회 성공. 분석 수정은 동작이 같은 중괄호
  스타일만 변경하여 테스트·빌드 결과를 재사용했다. Windows 네이티브 UI 수동 확인은 미실행.
