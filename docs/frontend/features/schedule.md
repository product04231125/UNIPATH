# 일정

## 목적

학생이 과제, 개인 일, 활동, 마감을 자신의 계획으로 정리하고 월간 흐름과 날짜별 목록을 확인한다.

## 현재 구현

- 홈 빠른 추가의 `PendingUiAction`은 저장소 읽기 성공 뒤 한 번만 소비한다. 일반 메뉴 진입과
  날짜 선택에는 입력창을 열지 않는다. 읽기 실패→복구와 열린 모달 중 저장소 변경 후에도 중복하지 않는다.

- 일정 등록·수정은 공통 입력 모달을 사용한다. 신규 폼의 자동 날짜·기본 분류는 빈 상태로
  취급하지만 제목·메모·변경된 날짜/분류는 작성 내용이다. 기존 수정은 비워도 명시적 취소가 필요하다.

- 820px 이상에서 달력과 선택 날짜 목록은 공통 `EqualHeightRow`로 하단선을 맞춘다.
  더 좁은 화면은 자연 높이의 세로 배치를 유지한다.

- 공통 `PageHeader`로 한글 제목·기존 개인 일정 설명을 표시한다. 제목의 추가 버튼은
  좁은 폭·글자 확대에서 아래 행으로 이동한다. 제목·본문은 최대 폭 1100 안에서 왼쪽 정렬하며
  읽기 대기·실패에도 화면 제목을 유지한다.
- 좌측 탐색의 `일정`은 월간 달력과 선택한 날짜의 목록만 제공한다. 중복 `이번 주 일정`
  표는 제거했으며 홈의 주간표는 유지한다. 일정 화면에는 주간표의 최소 폭 요구도 적용하지 않는다.
- 월간 요일 시작 순서는 개인 설정을 따른다. 날짜를 선택하면 해당 날짜의 목록으로 연결하며
  홈에서 누른 날짜도 월간 달력과 목록의 최초 선택으로 사용한다. 종료 시각이 자정이면
  다음 날 일정으로 중복 표시하지 않는다.
- 월간 날짜 칸 높이는 글자 확대에 맞춰 늘어나고, 전체 본문은 낮은 창에서도 스크롤된다.
- 제목, 시작·종료 일시, 분류(학업·개인·활동·마감), 선택 메모로 개인 일정을 추가·수정·삭제한다.
- 프로필과 일정은 `SharedPreferences`의 기기 로컬 저장소에 보관되며 Web과 Windows에서 같은 화면을
  사용한다.
- 저장 성공 뒤에만 목록을 바꾸고 편집 창을 닫는다. 저장 실패 시 작성 제목·기간·분류·메모와
  기존 목록을 유지하고 편집 창에서 재시도를 제공한다. 저장 중 중복 저장·닫기를 막는다.
- 일정 삭제는 제목을 표시한 별도 확인 뒤 수행한다. 취소 또는 삭제 실패 시 기존 일정과
  편집 창을 유지한다. 읽기 실패는 원본을 덮어쓰지 않고 쓰기 차단·재시도 화면으로 표시한다.

## 목업 경계

- 이 기능은 개인 계획 전용이다. 학교 공식 학사일정, 반복 일정, 알림, 외부 캘린더, MCP 연결을
  생성하거나 추정하지 않는다.
- 현재 저장 형식은 API 계약이 아니라 클라이언트 로컬 어댑터의 임시 형식이다.

## 후속 계약·검증

- 공통 모달 검사에서 기본 날짜/분류만 있는 폼은 바깥 클릭으로 닫고, 작성 제목은 보호한다.
  모달의 24px 화면 여백·640px 최대 폭·16px 스크롤 여백·고정 행동 영역을
  1440×900·900×768·480×520/글자 200%로 검사했다. 기존 저장·삭제 실패 보존 검사도 통과했다.

- `card_layout_test.dart`에서 900px 병렬 카드의 하단선과 480px 자연 높이 세로 배치를
  글자 배율 1/2로 검사했다. 관련 기록·홈 검사와 함께 10개 통과.

- 서버 일정 API와 동기화·삭제·충돌 정책이 정해지면 local repository를 API adapter로 교체한다.
- 일정 CRUD, 재시작 뒤 로컬 저장, 월간 달력·선택 날짜 목록 및 홈 주간표 유지, 좁은 창과
  Web/Windows 빌드를 검증한다.

## 중복 주간표 제거 검증

- `monthly schedule` 4개는 480×520·1440×900 및 글자 배율 1/2에서 월간 달력만 남는지,
  개인 주 시작 요일, 초기 날짜·날짜 선택·목록 접근 및 수정 저장을 검사한다.
- 홈 날짜 이동·빈 주간표·일정 추가 저장·저장/삭제 실패 보존·삭제 확인 등 기존 검사와
  합쳐 관련 13개 통과(테스트 명령 1회). 분석·Web·Windows 빌드는 안정화 뒤 각각 한 번 실행한다.
- 자동 검사 이후 사용자 최종 확인으로 중복 주간표 제거 작업을 마무리했다.

## 저장 안전성 보완 검증

- `planning_storage_test.dart` 7개: 저장 거부/예외, 읽기 오류·부분 데이터 차단, 복구,
  일정 저장 실패 입력 유지, 삭제 확인/취소/실패/재시도, 설정·홈·일정 읽기 오류 표시.
- 관련 검사 → 설정 테스트의 갱신 대기 및 복구된 입력란 확인 → 최종 전체 검사로 테스트 명령 3회.
  전체 77개 통과. `flutter analyze`는 중괄호 스타일 1건 수정 후 문제 없음(2회).
- `flutter build web`·`flutter build windows` 각각 1회 성공. 분석 수정은 동작이 같은 중괄호
  스타일만 변경하여 테스트·빌드 결과를 재사용했다. Windows 네이티브 UI 수동 확인은 미실행.
