# 수강 관리

## 목적

학교 수강 기록을 확인하고 현재·다음 학기 계획을 정리한다. 지원되지 않는 학교의 사용자는
개인 기준을 위한 보조 기록을 직접 입력할 수 있다.

## 현재 구현

- 2026-11-04: 사이드바 예시 데이터 토글과 수강 예시 행을 제거했다. 개인 합계·저장 동작은 유지한다.

- 제목은 공통 `PageHeader`의 한글 제목과 한 줄 설명 `학기별 수강 계획과 개인 이수 기록을 정리합니다.`이며 중복 영어 라벨을 표시하지 않는다.
  읽기 대기·실패에도 제목을 유지한다. 저장 위치·졸업 반영 안내는 헤더와 목록 아래에 두지 않는다.
- `frontend/lib/features/records/course/course_page.dart`가 화면과 수강 추가 상태를 소유한다. CTA·팝업 제목은 `수강 과목 추가`다.
- 수강 추가는 설정과 같은 검색형 선택으로 과목을 고른다. 선택지는 로그인·학교 문맥이 있으면 학교 카탈로그, 내 교육과정 과목, 이미 쓴 수강 기록(이름·코드 중복 제거)이다. 이름·코드·학점·이수구분은 선택 후 읽기 전용이며 직접 타자 입력은 없다. 공통 `설명 · 메모` 자유 입력도 수강 폼에서는 숨긴다(저장 스키마의 `detail`은 빈 값으로 유지). 목록이 비면 `설정·교육과정에서 과목을 먼저 등록하세요`를 안내한다. 이번 건만 연도·학기·성적·상태·분반을 입력한다. `catalog_course_id`는 추가하지 않고 기존 `course-records` 필드에 복사한다.
  실제 계정의 개인 기록 CRUD는 서버에 저장되며 새 작업 공간/다시 불러오기로 조회한다. debug/이전 원본은 기기에 남는다.
- 학업 프로필(`PlanningProfile.isConfigured`)이 없으면 목록은 열고 수강 과목 추가만 설정 CTA로 막는다.
  수강 목록 행의 `개인 기록` 배지는 두지 않는다(활동·자격 등 다른 기록 메뉴 배지는 유지).
- 수강 연도(학년도)는 검색 가능 선택이며 `1900`~`현재+1`이다. 학기는 `1학기`/`2학기`/
  `여름 계절학기`/`겨울 계절학기` 고정 선택이고, 기존 비표준 `term`은 수정 중 다른 학기를
  골라도 원래 값이 옵션에 남는다. 범위 밖 기존 연도도 그대로 두면 다른 필드만 수정·저장할
  수 있다. 분반은 숫자만 받으며 원 성적·과목 코드는 문자 입력을 유지한다. 저장은 기존처럼
  `CourseTerm.encode` → `term` 문자열이다.
- 수강 연도와 학기 필터를 조합하고, 해당 개인 기록의 학점 합계를 제공한다. 합계 옆에 `공식 이수학점 아님`을 붙이지 않는다.
- 교육과정 확인 안내는 목록 아래 펼치기/접기 영역에 둔다. 과목 정체는 카탈로그·교육과정·기존 수강에서만 고르며, 실제 공식 교육과정 데이터나 판정 결과를 생성하지 않는다.
- 입력·저장·검증 경계는 [ERD 대조](../manual-input-boundaries.md)를 따른다.

## 목업 경계

- 과목명·학점·학기 등 현재 입력은 API 모델이나 학교 확정 수강 기록이 아니다.
- 공식 교육과정 행렬·서버 삭제/수정 계약은 미확정이다. 개인 학점 합계는 졸업 판정이 아니다.

## 후속 계약·검증

- 공식 수강 기록과 개인 보조 기록의 출처·수정 가능 여부를 API에서 구분한다.
- 직접 입력이 수강 메뉴에만 반영되는지 위젯 테스트한다.

## 2026-10-14 작성 내용 취소 보호

명시적 취소 시 신규 작성 내용 또는 원본 대비 변경이 있으면 폐기 확인을 표시한다.
계속 작성은 입력과 선택을 보존하고, 내용 폐기만 닫는다. 빈 신규·무변경 수정은 확인 없이
취소한다. 저장 중 차단과 저장 실패 입력 보존은 유지한다. 공통 구현과 검증 범위는
[공통 입력 검증](../verification/ux-ui-verification.md)을 따른다.

## 2026-10-14 정보 순서 검증

- 개인 기록 회귀 12개, 헤더 10개, 카드·앱 메뉴 23개 통과. 새 회귀는 480×520·글자 배율 1/2에서
  개인 과목이 예시보다 앞에 있고, 합계에 예시가 포함되지 않으며 도움말을 펼칠 수 있는지 확인한다.
- 실제 Web 1440×900·480×520에서 예시 표시·빈 개인 기록 상태를 확인하고 Enter 키로 도움말을 펼쳤다.
  전체 회귀·정적 분석·Web/Windows 빌드는 공통 테마 마무리 검증으로 수행한다.
- 최종 전체 회귀 229개와 정적 분석이 통과했다. 480×520·200% 실제 글꼴 렌더에서도 제목·입력·필터를
  줄바꿈해 표시한다. 배포물과 검증 한계는 공통 검증 기록을 따른다.

## 2026-10-25 수강 연도·학기 구분

- 신규 입력은 수정 가능한 올해 학년도 기본값과 필수 학기 선택을 제공한다. 연도·학기는
  닫힌 선택이며, 계절학기를 날짜로 환산하거나 겨울학기를 다음 달력 연도로 자동 이동하지
  않는다. 사용자가 해당 학년도를 지정한다.
- 기존 `term` 계약에 `2026년 1학기` 형태로 저장한다. 새 API·DTO 필드·서버 enum은 추가하지 않는다.
  합친 문자열은 128자 이내다.
- `YYYY년 학기`, `YYYY학년도 학기`, `YYYY-1`, `YYYY-2`, `YYYY/1`, `YYYY/2`를 명확한 연도 표기로 읽는다.
  그 밖의 자유 문자열은 연도를 추정하지 않고 `연도 미지정`으로 표시한다.
- 기존 연도 없는 기록은 수정 시 연도 칸을 비워 두며, 사용자가 확인한 연도를 직접 보완할 수 있다.
  기간을 건드리지 않은 수정은 기존 `term` 원문(공백 포함)을 그대로 보낸다. 자동 마이그레이션은 없다.
- 필터는 저장된 개인 기록에서 만들고 연도·학기를 함께 적용한다. 마지막 항목 삭제/수정 뒤에도
  선택한 필터와 빈 결과 안내를 유지하므로 사용자가 필터를 바꾸어 다른 기록을 볼 수 있다.
- 올해 기본값만 있는 새 폼은 빈 폼이다. 연도 변경도 작성 내용으로 보호하며 저장 실패·재시도와
  계속 작성에서 값을 유지한다. 예시 과목은 개인 필터·합계 밖의 예시 영역에 남는다.
- 검증 및 한계: [수강 관리 검증](../verification/course-year-semester-2026-10-25.md).
  운영 서버 왕복·학교 공식 수강 기록 연동은 이번 프런트 검증에 포함하지 않는다.

### 2026-11-07 과목 후보의 프로필 범위

등록 학교 과목과 교육과정 과목 연결 조회에 프로필의 institution_id·department_id·curriculum_id를 함께 전달한다.
선택한 교육과정의 이수구분을 사용하며 개인 교육과정/기존 기록 대체 후보는 유지한다.
기존 카탈로그 필터를 사용하므로 과목 원본 department_id 저장 계약의 추가 여부와 별개다.
