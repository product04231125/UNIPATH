# ERD 기준 개인 수동 입력 경계

기준은 [논리 ERD](../database-erd.md)이며 실제 전송 계약은 OpenAPI다. 현재 도메인 API와
물리 도메인 테이블은 없으므로 아래 개인 입력은 기기 로컬 어댑터이며 서버 DTO가 아니다.
사용자가 입력한 값은 학교 공식 데이터·승인·이수·졸업 판정으로 승격되지 않는다.

## 메뉴별 대조와 현재 구현

| 메뉴 | ERD 대응 | 개인 입력 | 공식·읽기 전용 경계 |
| --- | --- | --- | --- |
| 수강 | Course, AcademicRecord | 과목명·코드, 학기, 이수구분, 학점, 원 성적 표기, 개인 상태; 분반은 HTML 목업의 로컬 보조 값 | 학교 Course/교육과정 FK·성적 환산·확정 이수학점은 생성·변경하지 않음 |
| 활동 | VolunteerRecord, Experience.details | 기관·기간·역할, 직접 입력 시간, 사용자가 확인한 승인 시간·상태·확인일 | 학교 승인 행위가 아니며 승인 시간 합계는 개인 기록 집계일 뿐 |
| 경험 | Experience | 종류·제목·기관·시작/종료일·진행 상태·역할·결과 | 역량 판정·ExperienceSkill 관계는 생성하지 않음 |
| 자격 | UserCertificate, CertificateProvider/Certificate | 자격명·기관·점수/등급·취득/만료일·상태·증빙 링크 | 마스터 FK·유효성 정책·기관 인증은 확정하지 않음; 자격증 번호는 수집하지 않음 |
| 성과 | Experience.details 및 HTML 성과 목업 | 종류·제목·기간·나의 역할·결과·공개 가능한 링크 | ERD에 별도 포트폴리오 테이블 없음; 공개 게시·파일 업로드는 하지 않음 |
| 일정 | 현재 ERD에 독립 일정 엔터티 없음 | 기존 기기 로컬 일정 CRUD | 학교 공식 일정이 아님 |
| 설정 | User, Institution/Department/Curriculum 범위 | 기존 개인 학교·학과·입학연도·계획 학년·시작 요일 | 학교·학과 마스터와 관리자 범위는 수정하지 않음 |
| 졸업 | GraduationRuleSet/Rule의 개인 분리 정책 | 기존 개인 기준 설정은 메모리 목업; 후속 로컬 규칙 구조·CRUD 필요 | 공식 규칙·감사·충족 계산은 서버 Rule Engine 책임 |

## 저장·검증

- 수강·활동·경험·자격·성과의 추가·수정·삭제는 `personal_record_repository.dart`의
  메뉴별 v1 키에 저장한다. UUID는 개인 레코드 식별자이며 서버 FK로 추정하지 않는다.
- 메뉴 전환과 재시작 뒤 보존한다. fixture는 별도 예시이며 수정·삭제 대상과 집계에서 제외한다.
- 저장 성공 뒤에만 메모리 목록을 갱신한다. 읽기 실패는 원본을 덮어쓰지 않으며 재시도를 제공한다.
  저장 실패는 입력을 유지하고, 삭제 실패는 기존 기록을 유지한다. 삭제 전에 대상을 확인한다.
- 음수·비유한 숫자, 0학점, 실제로 없는 날짜, 역전된 기간, 로그인 정보를 포함한 URL을 거부한다.
  승인 시간은 `approved`와 학교 상태 확인일을 함께 기록해야 한다.
- 수강은 학기 필터와 개인 입력 학점 합계, 활동은 사용자가 승인됨으로 기록한 시간 합계를 제공한다.
  이는 졸업 판정이 아니라 입력된 수치의 합이며 fixture·미확인 상태를 합산하지 않는다.

## 계약이 필요한 후속 영역

개인 졸업 규칙·교육과정, 학교 연동 후 매핑·병합, 개인 자료 RAG, 파일 저장·삭제 이력,
포트폴리오 구성·지원 문서, 서버 동기화는 아직 구현되지 않았다. 기존의 임시 상태값과 자유 입력
분류를 서버 enum으로 취급하지 않는다. 계약 확정 시 어댑터·마이그레이션·테스트를 함께 교체한다.
