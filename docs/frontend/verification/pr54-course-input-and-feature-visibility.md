# PR #54 수강·관리자 입력과 미연결 기능 노출

기준: develop edbd77e에서 시작한 feature/frontend-course-input-flow. 백엔드 코드 변경 없음.

## 수강 과목 문제와 수정

기존 과목 조회는 학생 프로필의 학교/학과/교육과정 ID를 전달한다. 서버 카탈로그는 선택 교육과정에 연결된 과목만 반환한다. 관리자 과목 등록과 교육과정 연결은 별도 리소스였으며 제보 캡처의 연결 목록은 0개였다. 실제 계정 API 응답을 보지 않았으므로 제보의 단일 원인은 확정하지 않는다.

과목 폼이 기존 두 API를 순서대로 저장한다. 과목 ID를 연결 요청에 사용하며 이수구분·필수 여부는 한 번 입력한다. 연결명은 자동 초기화한다. 선택 교육과정의 기존 연결만 수정하며 다른 교육과정 연결은 보존한다. 과목 저장 성공 후 연결 실패는 과목 ID를 보존하며 재시도 전에 연결 목록을 다시 조회한다. 과목 저장 응답 자체가 불명확하면 자동 재전송하지 않고 목록 확인 후 수정으로 이어가도록 안내한다.

학생 선택란은 항상 유지한다. 학교 설정 누락/카탈로그 실패/분류 조회 실패/정상 빈 목록을 구분한다. 다시 읽기는 학기·성적 입력을 보존한다. 학교별 분류 초안은 이름만 입력하고 내부 ID를 자동 생성한다. 필수·선택은 등록 없이 기본 선택지다. 사용자 지정 분류의 공식 저장·학생 재조회는 서버 계약 대기다.

기존부터 노출되는 미연결 항목: 학점표 저장·인증 요건 저장·학교 분류 저장, 채용 URL/파일 입력 및 분석 연결 전 안내. 해당 계약을 구현 완료로 표시하지 않는다.

변경하지 않은 조건: 학생/관리자 권한에 따른 신청·검토 제한, 게스트 쓰기 차단, 플랫폼별 보조 창 기능, 화면/채팅 설정의 환경 scope 주입, 데이터가 없는 결과·첨부·페이지네이션, 로컬 저장소의 서버 전용 새로고침 문구. 이 조건은 API가 없다는 이유로 기능을 숨긴 경우와 구별한다.

## 검증 범위
