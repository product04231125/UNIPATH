## 자동 검증 결과

- Flutter 3.47.5 / Windows, 한국어·LTR. 전체 검사 1회: 총 286건 중 283건 통과, 이전 화면 기대 3건 실패. 이 세 건은 변경된 등록/기본 탭 흐름에 맞춰 보완했고 선택 재검증으로 모두 통과했다. 수정된 관리자 알림의 영향 파일 2개는 최종 50건 모두 통과했다. 전체 286건을 다시 실행한 것으로 기록하지 않는다.
- 자료/개인 학업 관련 최종 11건 통과. 추가 접근성 라벨 보완 후 해당 11건 중 9건 통과, 2건은 검사 핸들 종료 시점 문제였고 해당 두 화면 크기 재실행 통과. PDF 바이트를 네이티브 DB에 쓰고 닫기/재열기로 복원하는 검사 포함.
- `flutter analyze --no-pub` 최종 문제 없음. 초기 경고 24건 및 추가한 검사 1건 보완 포함 전체 분석 3회. 마지막 입력 라벨 변경 파일은 선택 `dart analyze`로 문제 없음 확인.
- `flutter build web --no-pub`, `flutter build windows --no-pub` 성공. 첫 성공 이후 관리자 성공 알림과 입력 접근성 라벨 보완으로 두 플랫폼 산출물을 갱신했다(각 3회 성공, 최종 라벨 변경 포함). 빌드 로그는 frontend/build/structure-build-*.log에 보관한다.
- 반복 구현·실패 진단을 포함한 테스트 명령은 24회(전체 1회/선택 23회, 비동기 테스트 대기 중단 1회 포함). 분석·빌드 성공을 Windows 물리 입력/고대비/스크린리더 검증으로 확장하지 않는다.

## 실제 Web 검증

- 별도 로컬 debug 서버 127.0.0.1:5174, 크림·브라운, DPR1, 1440×900와 480×720. 학생·슈퍼관리자 합성 진입을 사용했다. 사용자 실자료나 실제 계정은 사용하지 않았다.
- 자료 설명 등록, 합성 PDF 파일 선택·보관, 브라우저 새로고침/합성 재로그인 뒤 설명/PDF 2건 복원. 자료 목록/폼의 2열 및 좁은 폭 세로 배치 캡처.
- 학생 개인 학교 실제 등록/목록 갱신/입력 초기화, 관리자 학교 본문 등록과 폼 내부 성공 상태, 두 화면의 넓은/좁은 배치 확인.
- 관리자 성공 SnackBar가 하단 로그아웃을 가리는 회귀를 발견해 폼 내부 메시지로 수정했다. 새 학생 입력 라벨은 접근성 이름으로 연결하고 위젯 semantics 검사로 확인했다.
- 캡처(비추적): frontend/build/structure-review/{materials,academic,admin}-{1440,480}.jpg. 전체 viewport 파일 크기를 확인했으며 앱 패널 미리보기의 잘림과 구분한다.

## 남은 계약·환경 검증

- 자료는 Web IndexedDB/Windows 앱 지원 디렉터리의 기기 보관이다. 파일 10MB/전체 PDF 50MB는 클라이언트 초기 한도다. 서버 업로드·권한·보유기간·동의·색인/삭제 전파·RAG 근거/AI 분석 계약은 후속이며 기존 학교 질의 API에 자료를 임의 전송하지 않는다.
- 기존 성과·포트폴리오 구성·지원 문서 키/본문/참조는 보존한다. 개인 학업을 공식 관리자 데이터나 공식 판정으로 표시하지 않는다.
- Windows 앱 빌드와 네이티브 DB 재열기는 확인했으나 실제 Windows 파일 선택/저장 대화상자·물리 키보드·혼합 DPI/고대비/스크린리더는 새로 실기 검증하지 않았다. Web 파일 내보내기 다운로드는 어댑터 코드/위젯 경계 검사이며 이번 브라우저에서 다운로드 실기를 별도 수행하지 않았다.
- 신규 3테마 비교·많은 데이터·실제 학교관리자 전체 화면 검증은 기존 남은 검증과 구분한다. 제품 원격 푸시·PR 갱신은 수행하지 않는다.
