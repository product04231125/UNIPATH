# 학교 신청·감사·원본·기록·검색 연결 검증

2026-10-24, `feature/frontend-integration-audit`. Flutter 프런트엔드와 문서/테스트만 변경했다.
기존 OpenAPI·전송 adapter만 사용했으며 백엔드 엔드포인트·DB·Rule Engine·RAG·LLM을 추가하지 않았다.

## 핵심 상태 보완

- 전송 중 중복 행동과 변경을 차단한다. 실패는 입력/파일/기록 행을 유지하고 신규 생성은
  동일 키로 재시도한다. 결과 불명 상태에서 바뀐 본문을 임의로 재전송하지 않는다.
- 원본/학생 기록의 401·403·404 이후 상세·변경 제어를 숨기고 재조회 안내를 표시한다.
  신청 심사의 권한 상실도 신청자 상세를 숨기고 부모 접수 목록을 지운다. 서버 권한을 대체하지 않는다.
- 감사 기준 작성 후 개인 기준 화면으로 이동하면 폐기 확인을 받는다. 계속 작성은 입력을 유지한다.
- 현재 검토 필요 사유와 서버 필드 오류를 관련 입력/기록에 표시한다.
- 문서 적용, 본문 검색 승인, 발급 원본 확인, 학생 기록 승인, 졸업감사는 서로 다른 상태다.

## 검증 결과

- `flutter test --no-pub`: 전체 **470개 통과, 11개 skip**, 1회. skip은 격리 서버 설정이 필요한
  기존 HTTP 검사다. 서버 설정/비밀값을 임의로 만들지 않았다.
- 전체 검사 뒤 실제 인증 capability를 쓰는 역할별 진입 검사 3개를 추가해 대상 검사로 모두 통과했다.
  학생은 `/me`, 두 관리자 역할은 `/admin` 기록 경로를 쓰고 동일 소유자 헤더를 보낸다.
- 핵심 상태 대상 검사 6개 최초 통과, 신청 권한 오류/최소 창 검사를 더한 8개 통과.
  480×520·글자 200%의 기본 다이얼로그와 1440×900/480×720의 실행 흐름을 검증했다.
- `flutter analyze --no-pub`: 최초 조건문 서식 6개를 정리한 뒤 문제 없음. 추가 진입 검사 서식 1개도 정리했다.
- `flutter build web --no-pub`, `flutter build windows --no-pub`: 최종 코드 각각 1회 성공.
- 단위 기록: [신청](school-admin-applications-ui.md), [감사](official-graduation-ui.md),
  [PDF 원본](official-sources-ui.md), [학생 기록](official-records-ui.md), [검색](school-document-search-ui.md).

## 남은 제한과 별도 후속

- 실제 학교 데이터·검토자의 발급/신원 확인·운영 서버 왕복과 Windows 네이티브 조작은 미검증이다.
  합성 응답/위젯/전송 계약/빌드 검증을 실서버 승인 완료로 표시하지 않는다.
- 학교 문서 본문·전체 적용 규정 검토 및 공식 실행 규칙/자격 마스터 관리 UI는 이번 요청 밖이다.
  감사/검색의 실자료 사용에는 담당자의 기존 API/도구를 통한 선행 등록·승인이 필요하다.
- 기존 승인 기록 교체 대상 지정 UI는 제공하지 않는다. 해당 충돌은 서버 응답으로 안내한다.
- 개인 포트폴리오 PDF의 RAG 업로드, 채용 분석·개인화, 외부 인증과 실제 LLM 설정은 추가하지 않았다.
- 제품은 로컬 커밋이며 푸시·PR은 수행하지 않았다.
