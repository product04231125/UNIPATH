# UI·UX 검토 6건 개선 검증 (2026-10-15)

> 해당 작업 시점의 검토·검증 이력입니다. 현재 UI 기준은 [제품 UX 기준](../product-ux.md), 현재 기능은 [기능 문서](../README.md#기능-문서)를 따릅니다.

## 결과

1. AI 학교 정보 폼: Workspace 소유 GlobalKey로 도킹/좁은 보기 전환에서 입력·선택을 유지한다.
2. 좁은 AI: 가용 폭 1180px 미만에서 전용 보기. 본문은 Offstage로 보존하고 포커스·semantics에서 제외한다. 돌아가기·닫기·Esc 및 열기 버튼 포커스 복귀, Tab/Shift+Tab 내부 순환을 제공한다. 넓은 도킹은 다음 상단 영역으로 탐색을 계속한다.
3. 활동: `기록됨`을 `충족`으로 재해석하지 않는다.
4. 승인: 저장 enum은 유지하고 대기·승인·반려·검토 필요로 표시한다.
5. 사이드바: 고정 이름·학번 제거. 저장된 학교·학과·입학연도 또는 미설정/로딩/실패 상태를 표시한다. 인증된 이름 응답은 아직 없다.
6. 관리자: 좁거나 확대된 상단에서 중복 역할 줄을 줄이고 제목·학교·범위를 유지한다. 반응형 2열 기준은 유지한다.

## 자동 검증

- Flutter SDK 3.47.5, 전체 테스트 1회: 267건 중 263건 통과. 이전 동시 오버레이 정책을 요구하던 달력 4건 실패.
- 달력 검사를 전용 보기에서 복귀한 뒤 마지막 날짜·가로 스크롤 접근을 확인하도록 갱신했다. 480px 두 경우 통과, 900px 두 경우는 부동소수점 수준의 스크롤 범위를 제외하도록 검사 조건을 보정한 뒤 통과했다. 넓은 두 경우도 통과했다. 최종적으로 267건 모두 통과 근거를 확보했으며 전체 suite를 다시 실행하지 않았다.
- 새 회귀: 학교 폼 상태/선택 보존, 좁은 AI 폭·탐색·Esc, 활동 상태 의미/승인 원값, 사이드바 미설정/저장 프로필, 관리자 상단 높이/2열 전환.
- 수정 중 테스트 명령 20회 시도(잘못된 실행 디렉터리·Windows batch 정규식 전달 실패 2회 포함). 실패 진단과 관련 테스트만 재실행했다.
- `flutter analyze` 1회: 문제 없음. `flutter build web`, `flutter build windows` 각 1회 성공. 마지막 테스트/문서 변경 후 제품 소스는 변경하지 않았다.

## 실제 렌더링

- Web, 한국어, 크림·브라운, 1440×900/480×520, 합성 샘플 사용자/슈퍼관리자.
- 설정에서 AI 학교 입력 → 좁은 전용 보기 → Esc → 재열기 → 넓은 도킹에서 입력 유지 확인. 좁은 AI 동안 설정 본문이 접근성 트리에서 제외되고 Esc 후 열기 버튼으로 포커스 복귀 확인.
- 활동 목록 `기록됨`, 사이드바 학업 정보 미설정, 좁은 관리자에서 제목·학교 선택·범위·학교 등록 버튼과 카드, 넓은 관리자 학교/학과 2열 확인.
- 이미지(비추적 build 산출물): `frontend/build/ui-review-ai-480.png`, `ui-review-ai-1440.png`, `ui-review-activity-1440.png`, `ui-review-admin-480.png`, `ui-review-admin-1440.png`.

## 한계

- 실제 Windows 네이티브 창의 키보드·스크린리더·고대비·혼합 DPI 검증은 이번에 수행하지 않았다. 200% 확대는 위젯 회귀 테스트 근거이며 실제 브라우저 확대 렌더링과 구분한다.
- 파랑/오렌지 테마의 새 실제 렌더링은 생략했다. 기존 테마 검증을 재사용하며 이번 수정은 팔레트를 바꾸지 않는다.
- 서버 공식 승인·사용자 이름 계약을 추가하거나 추측하지 않았다. 기존 기기 저장/fixture 경계를 유지한다.
- 공용 팁 확인은 로컬 Python 위치/Git fetch 오류로 실패했다. 제품 원격 푸시·PR은 수행하지 않았다.
