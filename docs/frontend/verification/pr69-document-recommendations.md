# PR #69 프런트 연결 검증

## 구현 결과

- 기존 공고 분석 화면과 학교 안내의 추천 workflow에서 새 폼에 진입한다. 분리 채팅의 이동 명령은 메인 창에서 처리한다.
- 직무·명시적 전국 선택, 기기 파일 선택/해제, 저장 기록 ID·버전 선택, 별도의 Google 전송 동의와 설정 철회를 연결했다. 파일은 자동 수집·보관하지 않는다.
- 전용 요청/응답 모델을 사용하고 새 경로에만 180초 클라이언트 대기를 적용했다. 자동 재전송은 하지 않는다. 이는 서버·프록시 시간 제한을 보장하는 값이 아니다.
- 서버 추천 순서, 미확인 필수조건, 공고별 전체 비교·범위·경고와 파일명·쪽수·OCR 출처를 표시한다. 부분 수집·추천 없음·비교 실패·준비 중·HTTP 오류를 구분한다.
- 계정 교체·게스트·취소·오류 뒤 입력 보존을 검증했다. 계정 교체 시 폼 내부 지역 선택 상태도 초기화한다.

## 검증 근거

- 관련 6개 테스트 파일 **39건 통과**: 추천 요청·base64·선택 기록 버전·별도 동의, 실제 loopback HTTP의 인증/owner 헤더·로그아웃 후 재사용 차단, 기록 조회 실패 시 파일만 사용, 게스트 차단, 계정 교체 후 늦은 결과 폐기, 부분 성공·OCR 출처·추천 0건과 실패 분리, 기존 단건 분석 복귀·채팅 workflow·분리 창 이동.
- 전체 `flutter test --no-pub --reporter expanded`: **884 통과 / 기존 선택형 13 생략 / 1 실패**. 실패는 기존 `workspace_ux_test`의 `Windows initial client area has no home scroll, populated=true`: 예상 0, 실제 58px. PR #68에도 동일 develop 기준의 기존 실패가 기록돼 있고, 별도 PR #67의 수정 대상이다. 이번에 홈 코드를 수정하거나 테스트를 생략하지 않았다.
- 최종 `flutter analyze --no-pub`: 문제 없음. Web Release·Windows Release 빌드 성공.
- 실제 Pretendard·아이콘 글꼴로 1440×1000, DPR 1에서 크림/파랑/다크 입력 및 부분 성공(추천 근거 펼침), 다크 글자 200%, 추천 0건+분석 실패를 총 8장 렌더링했다. `output/pr69-frontend/visuals/`에서 시각 확인했다. 기본 화면의 영역 구분·한글 표시·확대 시 스크롤을 확인했다. 네이티브 EXE·브라우저 수동 실기와 구분한다.
- 로컬의 별도 설정(`_env_file=None`, 모델 꺼짐)으로 PR #69 앱을 생성했다. OpenAPI에서 새 경로 등록을 확인했고 ASGI 클라이언트와 `127.0.0.1:18069` 실제 TCP POST 모두 **401**을 반환했다. 확인 후 임시 서버를 종료했다. 실제 자격증명·학생 파일·DB·외부 모델·공고 수집은 사용하지 않았다.
