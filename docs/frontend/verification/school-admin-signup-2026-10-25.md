# 학교관리자 최초 가입 구조 정정 · 2026-10-25

## 요청과 결과

요청은 회원가입에서 학생/학교관리자를 고르고, 학교관리자는 계정 정보와 학교 정보를 같은
화면에서 제출해 승인 대기가 되며 슈퍼관리자가 접수·심사하는 흐름이다. API 생성은 금지다.

- 회원가입 내부 유형 선택, 학교명·홈페이지·직책·연락 이메일·사유 입력을 구현했다.
- 별도 신청 요청 버튼과 일반 가입/로그인 후 자동 모달 이동을 제거했다.
- 유형·로그인 탭 전환 시 계정/학교 입력을 유지한다. 비밀번호·학교 초안을 영속 저장하지 않는다.
- 학생 가입과 공통 로그인은 기존 API를 유지한다. 실제 역할은 서버 응답만 따른다.
- 슈퍼관리자 작업 공간에 `/admin/applications` 접수 메뉴를 추가했다. 기존 심사 API의 목록·
  새로고침·필터·상세·승인/반려를 재사용하고 학교관리자/학생의 메뉴·직접 접근을 막는다.
- 기존 계정의 권한 신청·이력은 제목표시줄에 별도로 유지한다. 최초 학교 가입과 구별한다.

**최초 학교 신청의 서버 접수와 승인 대기 전환은 미구현이다.** 화면 준비나 기존 권한 신청의
심사 가능 상태를 전체 가입 흐름 완료로 보지 않는다.

## API 경계

OpenAPI와 `backend/app/schemas/auth.py`, `admin_applications.py`, 관련 라우트를 대조했다.
가입은 이름·이메일·비밀번호만 받으며 추가 필드를 허용하지 않는다. 권한 신청은 인증된
계정과 등록 학교 UUID가 필수다. 최초 학교명·홈페이지를 받을 계약과 해당 신규 접수의 심사
계약이 없다. 학교 카탈로그도 인증이 필요하다.

학교관리자 가입은 미접수·서버 미저장 안내와 비활성 제출을 표시하고 Enter 제출도 차단한다.
일반 계정 대리 생성·가짜 승인 대기·임의 UUID·신청 사유에 학교 정보 넣기·관리자 학교 등록
API 우회·신규 API나 서버 코드는 추가하지 않았다. 접수 목록에는 기존 서버 신청만 표시한다.

후속 연결에는 최초 신청 접수/신청자 신원/학교 정보 저장, 접수 식별자·상태·오류·재시도,
슈퍼관리자 검토 응답과 학교 등록·권한 부여 관계에 대한 백엔드 계약이 필요하다.

## 원본 통합 브랜치 검증 이력

- 관련 테스트 1회: 가입/기존 신청/미등록 폼 16개 통과.
- 접수 메뉴 테스트 1회: 메뉴→실제 API adapter→목록→상세, 갱신, 하위 역할 직접 접근 차단,
  샘플 미접수 표시 4개 통과. 합성 HTTP 응답을 사용했다.
- 공통 인증 진입/관리자 탐색 변경에 따라 전체 Flutter 테스트 1회: 489개 통과, 11개 생략.
  생략은 기존 격리 서버 HTTP 환경 의존 테스트다. 승인/반려·권한 상실 회귀도 통과했다.
- 정적 분석 최초 1회에서 신규 테스트의 중괄호 lint 2건 발견 후 수정했다. 두 번째 분석은
  문제 없음. 첫 Web/Windows 빌드는 각각 성공했다.
- 브라우저 실제 Web 렌더링에서 학교 필드 간격 부족을 확인해 보완했다. 이 변경 후 관련
  가입/미등록 폼 11개, 정적 분석, Web/Windows 빌드를 각각 1회 추가 검증했다.
- 가입 레이아웃은 1440×900 및 480×520, 글자 100%/200%에서 필드·스크롤·overflow를 검사했다.
  URL/연락 이메일 검증, 유형/탭 입력 보존, 학생 가입 유지와 학교관리자 Enter 제출 차단을 확인했다.

실제 신규 신청 접수·학교 자료·운영 서버 심사·Windows 네이티브 실기는 검증하지 않았다.
브라우저는 로컬 Release Web 빌드의 가입 화면을 확인했으며 실제 계정 가입/신청은 하지 않았다.

`school_admin_application_inbox.dart`, `school_admin_applications_dialog.dart`,
`admin_workspace.dart`, `admin_shell.dart`, `app_navigation.dart`, `workspace_title_bar.dart`.
테스트: `school_admin_signup_ui_test.dart`, `school_admin_application_inbox_test.dart`,

`535cd69`이며 현재 제품 커밋 `554b98f`와 백엔드/OpenAPI 차이는 없다. 원격에 새 최초 접수

등록 학교 UUID 없이 기존 신청 서비스를 호출하면 학교를 찾을 수 없고, 학교를 대신 만드는
기존 `/admin/institutions`는 `require_super`로 제한된다. 일반 가입 후 로그인시키는 우회는
요청한 최초 신청 과정을 대체하지 못하며, 로컬 초안을 슈퍼관리자의 서버 접수로 표시할 수도 없다.

전체 완료를 입증하려면 실제 신청 저장 응답의 식별자/승인 대기 상태, 별도 슈퍼관리자 세션에서
같은 신청 조회, 검토 후 결과/권한 반영을 해당 API 계약에 따라 확인해야 한다. 현재 테스트의
가짜 HTTP 응답이나 초안 화면만으로 이 조건을 충족했다고 판단하지 않는다.
