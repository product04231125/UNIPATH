# 학교 문서 근거 검토 UI 검증 · 2026-10-25

## 범위

관리 현황의 실제 관리자 진입 → 등록 추출본 목록/필터/추가 읽기 → 최신 상세/페이지·범위·
경고·빈 페이지 확인 → 네 가지 독립 검토/직접 입력 hash/사유 승인 또는 사유 회수 → 목록 갱신.
기존 owner-bound 전송과 SchoolKnowledgeAdminApi/생성 DTO만 사용했다. OpenAPI의
KnowledgeApprove/KnowledgeRevoke 요청, 기존 모델·API·ERD/UX 경계를 확인했다.

## 자동 검증

- 첫 UI 테스트 실행 2회는 공통 InputDialog 필수 인자 누락을 순서대로 보완한 뒤 컴파일됐다.
  이후 신규 UI 14개 통과. 전송 중 중복/닫기 차단과 실제 422 필드 오류 확인을 추가했다.
- 최종 관련 실행 1회: school_knowledge_review_ui_test, school_knowledge_api_test,
  school_workflow_state_test **30개 통과**. 신규 검토 UI/진입은 15개다.
- 한국어 경고/이수 경로 표시 보완 뒤 해당 읽기 테스트만 1회 추가 통과. Flutter 테스트 명령은
  총 5회(초기 컴파일 실패 2회, UI 14개, 최종30개, 문구1개) 실행했다.
- 분석은 최종 기능 안정화와 문구 보완 뒤 각각 1회, 두 번 모두 문제 없음.
- `flutter build web`, `flutter build windows` 각각 1회 성공.
- 이 변경은 기존 학교 작업 진입 버튼 1개와 새 기능/상태에 한정된다. 관련 API/공통 작업
  상태 회귀를 함께 실행했고 전체 Flutter 회귀는 반복하지 않았다.

검사한 동작:

- 실패 후 다시 읽기, 빈 상태에서 가짜 문서 없음, 서버 cursor/상태 필터 전송
- 실제 응답의 본문/입학연도/이수 경로/분할·경고 및 명시적 빈 페이지 표시
- 네 확인·hash 불일치·빈 사유의 승인 전송 차단, expected_version/hash/확인4개/사유와 소유자 헤더
- 회수 사유 검증, 422 필드 오류/입력 보존/명시 재시도와 승인/회수 후 목록 갱신
- 403 시 본문/목록/결정 숨김, 409/500 시 입력 보존·결정 잠금·재읽기 폐기 확인
- 다른 버전의 페이지를 현재 본문으로 표시하지 않음
- 응답 대기 중 중복 결정/닫기 차단
- 1440×900와 480×520·글자200%에서 페이지 읽기·사유 입력·닫기/계속 작성에 접근하고 overflow 없음
- 실제 학생에게 관리자 진입 없음, 학교관리자/슈퍼관리자 진입

## 검증 경계

합성 HTTP/위젯 검증이며 실제 학교 본문/원본 검토·운영 서버 승인·네이티브 DPI/키보드 실기를
완료한 것은 아니다. 등록/페이지 수정/삭제·전체 적용 규정 검토·Rule Engine·LLM은 범위 밖이다.
승인 원본은 사람이 외부에서 직접 확인한다. 테스트 fixture의 응답을 제품 데이터로 넣지 않았다.
