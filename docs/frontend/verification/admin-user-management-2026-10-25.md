# 관리자 사용자 관리 보완 — 2026-10-25

## 범위와 계약

OpenAPI의 GET /admin/users는 cursor/limit만 제공하므로 기존 전체 페이지를 읽은 repository 자료에 역할·계정 상태·검색을 적용한다. 이름·이메일·역할명·접근 가능한 활성 관리 범위를 검색하며 현재 학교와 관계없는 전체 사용자 목록임을 표시한다. 범위 회수 뒤 숨겨진/비활성 범위를 검색 근거로 남기지 않는다. 사용자 권한·상태 변경 정책과 개인 기록 접근은 그대로다.

신청 접수는 기존 GET /admin/school-admin-applications의 institution_id/status/cursor 계약을 사용한다. 부모 관리자 repository의 학교 선택지를 전달하고 조회한 접수의 학교명도 보완한다. 필터 변경은 이전 목록/cursor를 지운 뒤 첫 페이지를 읽으며 페이지 추가와 재시도는 필터를 유지한다. 최초 학교관리자 가입 접수·새 API는 포함하지 않는다.

## 검증

- 신규 2개: 역할/상태/대소문자 이메일/학교 검색 결합, 범위 회수 반영, 학교·상태 조회 조건/소유자 헤더/페이지 cursor/필터 변경 초기화/실패 시 이전 목록 숨김/같은 조건 재시도.
- 관련 관리자·API·심사·입력 보호 51개 통과. 로컬 --name 필터로 compact/narrow/480/복합 좁은 사례를 제외했다.
- 새 학교 필터 테스트의 MockClient 안 expect가 위젯 guarded 비동기 검증과 충돌해 진단 중 반복 실패했다. 요청을 수집하고 완료 뒤 검증하도록 고친 후 통과했다. 제품 코드의 API 실패는 아니었다.
- 분석 최초 신규 테스트 조건문 스타일 2건을 보완하고 2회차 문제 없음. Web/Windows build 각1회 성공.
- Web 개발 샘플 1440×1100에서 역할 선택/학교 검색 결합으로 사용자 3명 중 학교관리자 1명 표시와 관리 범위 라벨을 확인했다. 로컬 frontend/build/admin-audit/account-role-filters.jpg, account-filtered-school.jpg에 캡처했다. 접수 API는 합성 HTTP 응답 테스트로 확인했으며 운영 서버/네이티브/좁은 화면은 미검증이다.
