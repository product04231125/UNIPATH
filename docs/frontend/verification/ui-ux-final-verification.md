# 확정 UI·UX 검증 (2026-10-15)

> 해당 작업 시점의 검토·검증 이력입니다. 현재 UI 기준은 [제품 UX 기준](../product-ux.md), 현재 기능은 [기능 문서](../README.md#기능-문서)를 따릅니다.

## 적용 결과

- 크림·브라운 기본 / 밝은 파랑 / 다크 오렌지의 3개 제품 테마를 학생·관리자 설정에서 기기별 저장한다. 개발용 비교 UI와 다크 퍼플은 제거했다. 테마 저장 실패는 기존 테마를 유지하고 재시도 경로를 제공한다. 미저장 학업 폼·Router·역할은 유지한다.
- 삭제 및 삭제 확인은 채워진 붉은 배경이다. 다크 오류 빨강과 제목표시줄 대비를 공통 토큰에서 조정했다.
- 관리자 학교·교육과정·요건·계정/범위·현황·상세·문서/이력에 반응형 2열을 적용했다. 좁은 폭·확대에서는 1열이다. 홀수 마지막 영역은 전체 폭을 사용한다.
- 학생·관리자 사이드바는 축소해도 아이콘과 허용된 메뉴가 남는다. Tab은 메뉴 → 본문 → AI → 상단이며, 2열은 왼쪽 전체 → 오른쪽이다. 모달 순환과 닫기 후 포커스 복귀를 유지했다.

## 자동 검증

- Flutter 3.47.5 / Dart 3.13.4, Windows 로컬.
- `flutter test`: 최종 전체 262개 통과, 전체 실행 1회. 관련 테스트·실패 사례 재실행을 포함한 테스트 명령은 총 14회다. 초기 선택 제어/동명 메뉴 finder·스크롤 접근과 AI 열기 버튼 FocusNode 수명을 보완했다.
- `flutter analyze`: 최종 문제 없음. 총 2회이며 첫 실행의 테스트 `forEach` 스타일 경고를 수정했다.
- `flutter build web`, `flutter build windows`: 각각 1회 성공.
- `app_style_test`: 기본값·복원·저장 실패·알 수 없는 값·3테마 대비·입력 보존·삭제 확인.
- 관리자/키보드 회귀: 네 주요 목록의 좌표와 폭 전환, 두 역할의 480×520/200% 화면, 아이콘 축소 후 탐색, Tab·Shift+Tab·AI 복귀·모달 내부 순환을 확인했다.

## 실제 Web 렌더링

- 로컬 debug 앱의 합성 역할, LTR, 기본 글자 배율, 1440×900 및 480×520 viewport. 브라우저 캡처는 전체 viewport로 저장해 좁은 앱 패널의 잘린 미리보기와 구분했다.
- 크림: 관리자 현황·교육과정 2열과 학생 설정의 왼쪽 프로필/오른쪽 테마.
- 파랑: 관리자 설정과 상단 대비.
- 오렌지: 관리자 설정·축소 메뉴·교육과정 2열, 480×520 1열 및 입력 오류·고정 취소/저장.
- 브라우저 viewport 자동 전환 중 임시 1×1 크기의 Row/높이 overflow 로그가 한 차례 있었다. 지원 검증 크기인 1440×900/480×520의 렌더링 결과와 구분하며 해당 로그를 정상 크기 오류로 집계하지 않는다.
- 로컬 캡처: frontend/build/ui-ux-settings-cream.png, ui-ux-settings-blue.png, ui-ux-admin-orange.png, ui-ux-admin-compact.png, ui-ux-error-compact.png. 생성 산출물이며 제품 소스에 포함하지 않는다.

## 경계

- 실제 Windows의 스크린리더·고대비·물리 키보드·혼합 DPI와 열린 분리 창의 테마 IPC 실기는 이번에 새로 수행하지 않았다. 키보드 동작은 실제 키 이벤트 위젯 검사이며 네이티브 실기를 대신하지 않는다. 지정 SDK 3.47.6은 미검증이다.
- 인증·관리자 데이터는 기존 fake/로컬 경계를 유지한다. 신규 서버 API 계약을 만들지 않았다. 기존 버그 후보 3건은 별도 백로그로 남긴다.
