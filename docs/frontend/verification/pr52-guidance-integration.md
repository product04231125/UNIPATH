# PR #52 프런트 연결 검증

## 계약 기준과 남은 의존성

- 기준 커밋: `76c263b`(PR #52 develop 병합). 로컬 OpenAPI의 학교 질문·맞춤 안내·채용 분석·학사 안내 경로를 Pydantic/Dart 모델과 대조했다.
- 학교 질문은 등록 학교·학과 UUID 문맥을 사용한다. 외부 전송 동의 필드는 없으므로 프런트의 호출 전 동의 차단을 적용한다. 서버 검증 필드는 별도 계약 의존성이다.
- 맞춤 안내는 등록 학교 문맥과 선택한 서버 개인 기록을 사용한다. 학교 근거 없이 개인 기록·개인 교육과정·규칙·PDF만으로 답하는 기능은 계약에 없다.
- 맞춤 안내와 채용 분석의 `external_processing_consent`는 기본 false다. 계정·기능·고지 버전별 기기 저장 허용과 이번만 허용을 구분한다.
- 채용 분석의 공고 입력은 텍스트(최대 20,000자)다. 학교 ID는 받지 않으며 URL·PDF·이미지 분석도 받지 않는다.
- 정형 학사 안내는 경동대학교 수집본이다(`kduniv.ac.kr` 출처). API에 등록 학교 UUID와의 대응·지원 학교 필드는 없다. 등록 학교 이름으로 UUID 대응을 추측하지 않는다. 학교 대응 확인 전 학교별 이용 가드는 보류 의존성으로 남긴다.
- 원문은 인증이 필요한 PDF/JPEG 응답이다. 일반 외부 링크에 bearer 토큰을 넣지 않는다.
- Vertex 모델 기본값은 꺼짐이다. 실제 호출·의미적 답변 품질은 이 프런트 검증으로 입증하지 않는다.

## 1차: 동의 저장·설정과 전송 어댑터

- 기기 동의는 Workspace의 계정 UUID에 묶이며 세 기능을 분리한다. 기본 미허용, 고지 버전 불일치·읽기 실패는 차단한다.
- 저장 성공 후 허용한다. 철회 저장 실패도 현재 세션에서는 차단하고 저장 실패를 표시한다. 이번만 허용은 저장하지 않는다.
- 설정은 프로필 읽기 실패 중에도 동의 설정을 독립적으로 표시한다. 로그아웃/계정 변경 시 Workspace와 함께 폐기한다.
- `ai_consent_preferences_test`: 계정·기능 격리, 저장 실패, 철회, 고지 버전, 폐기 후 늦은 완료, 이번만 허용·취소, 설정 영구 허용/철회 6건 통과.
- `guidance_api_test`: 노드 ID·감사 쿼리, 개인 기록 버전·동의 직렬화, 학교 문맥·학교/개인 응답 분리 확인.

## 남은 검증

채팅 모드·개인 기록 선택·정형 안내·채용 화면 및 IPC 연결은 후속 단위에서 검증한다. 최종 분석·전체 회귀·Web/Windows 빌드·데스크톱 실기는 아직 수행하지 않았다.

## 2차: 학교 질문·맞춤 안내와 IPC

- 등록 학교 UUID 라우팅·미등록 차단·동의 철회·요청 당시 모드/기록 버전·409 입력 보존·프로필 읽기 실패·분리 창의 메인 소유 요청·자료 분리 UI를 추가했다.
- `registered_assistant_test` 7건: 상태 6건 통과, UI 1건에서 ListTile Material 경고를 발견해 Material을 보완하고 해당 1건 재실행 통과.
- 기존 API·공유 프로필·IPC 회귀에서 26건 통과. 이전 제품의 채팅 내부 학교 폼을 찾던 1건은 새 요구에 맞게 질문·모드·선택 범위의 데스크톱 도킹 전환 검증으로 변경하고 통과했다. 좁은 화면 신규 검증은 추가하지 않았다.
- 설정 편집·이름 기반 대체 호출은 실제 Workspace에서 사용하지 않는다. 학교 질문의 서버 동의 필드·개인 기준/PDF 질문은 여전히 미확정이다.
- 정형 학사 안내·채용 화면, 최종 전체 회귀·분석·양 플랫폼 빌드·실기는 남아 있다.

## 3차: 채용공고 분석

- 공고 텍스트·선택 기록·전송 동의를 실제 분석 API에 연결했다. 학교 ID 없이 동작하며 주소·파일 입력은 준비 중으로 비활성 표시한다.
- UI 7건과 기존 직렬화 계약 3건을 실행했다. 9건 통과, 동의 대기 중 분석 로딩이 표시돼 1건 실패했다. 동의 대기와 실제 요청 로딩을 분리한 뒤 실패한 1건 재실행 통과.
- 완료·모델 없음·동의 취소/이번만 허용·409 보존·입력 필요·근거 부족·실패를 검증했다. 실제 Gemini 호출과 정형 학사 안내·최종 통합 검증은 남아 있다.

## 4차: 정형 학사 안내와 인증 원문

- 노드 탐색·준비 중·OCR 경고·표 공란·공식 감사 선택·인증 PDF/JPEG·메인 소유 IPC를 구현했다. 학업 프로필 변경 뒤 늦은 노드/원문 응답은 폐기한다.
- 학사 안내 테스트는 기존 6건 중 5건 통과, 합성 로그인 응답의 UTF-8 헤더 누락 1건을 보완해 재실행 통과했다. 추가 감사 소유권/선택·늦은 노드·실제 학교 가드 3건도 통과했다.
- 2026-11-08 사용자 답변 `대기`: 수집본과 서버 학교 UUID 연결은 대기한다. 가드 기본값을 비워 두고 실제 조회를 차단한다. 이 제한은 프런트 미확정 구현 대신 명시적 활성화 보류다.
- 정적 분석 1회에서 새 조건문 중괄호 lint 44건을 발견했다. 해당 코드만 수정하고 분석 재실행 통과(`No issues found`). 최종 회귀·양 플랫폼 빌드·시각 확인을 진행한다.
