# 학교관리자 신청·접수 UI 검증 (2026-10-24)

이 문서는 당시 검증 이력이다. 가입 진입은 2026-10-25 회원가입 내부 유형 선택으로 대체했다.
현재 동작과 PR 검증은 [가입 구조 정정](school-admin-signup-2026-10-25.md)을 따른다.

- 기존 API/DTO/owner-bound 어댑터만 사용했다. 새 백엔드 경로는 만들지 않았다.
- signup 하단 진입/인증 후 신청, 로그인한 일반/학교관리자 본인 신청과 슈퍼관리자 접수, 카탈로그·필터·cursor·상세·취소/승인/반려를 연결했다.
- 초기 API 회귀 4건 통과. 신규 위젯 3건 최초 실행에서 신청자 두 크기의 실패 안내 기대가 불일치해 안내를 보완, 해당 2건 재실행 통과. 신규 위젯/기존 인증/API 17건 통과 후 승인/반려 두 경로를 선택 실행해 2건 통과했다. 전체 통합 회귀는 모든 요청 흐름 마무리 때 수행한다.
- 분석 1차는 새 코드의 중괄호 스타일 9건으로 실패, 해당 항목만 dart fix 후 2차 문제 없음. 앱 코드 수정 안정화 후 Web/Windows build 각1회 통과. 마지막 테스트 추가는 앱 빌드를 재실행할 이유가 없어 기존 결과를 사용했다.
- 위젯은 1440×900/480×720, 합성 HTTP로 실패 입력 보존·동일 client_id·폐기 확인·승인 확인/반려·owner 헤더를 확인한다. 실제 운영 서버/역할 변경·Windows 네이티브 실기는 실행하지 않았다.
- 나머지 요청(졸업감사/자료 제출·검토/학교 지식 검색)은 이 단위의 완료 범위가 아니다.
