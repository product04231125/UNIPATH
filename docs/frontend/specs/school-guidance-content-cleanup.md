# 학교 질문 수집 자료 정제·응답 역할 정리 요청

## 확인한 문제와 원인 범위

2026-11-08 현재 코드의 `respond()`를 직접 실행해 확인했다. 모든 가독성 문제를 PDF/OCR 추출 탓으로 단정하지 않는다.

- `calendar:2026:01`: 일정 7건의 출처 URL은 모두 같은 경동대학교 2026년 학사일정 페이지다. 11월도 일정 5건의 URL이 모두 같다. 프런트는 항목별 출처를 그대로 반복하던 표시를 공통 원문 영역으로 수정했다.
- 1월 첫 일정은 `title=신년 하례식(2026년도)`, `date_text=01. 02(금)`, `body=01. 02(금) — 신년 하례식(2026년도)`다. `content.py`가 구조화된 제목·날짜를 body에 다시 조합한다. 동일 내용 세 번 노출은 이 응답과 기존 프런트 표시 방식이 결합한 결과이며 PDF 추출 문제로 확인된 것이 아니다.
- 규정에는 OCR 미검토·표 공란·읽기 순서 경고 계약이 있다. 해당 상태는 정제 완료를 뜻하지 않으며 프런트에서 값이나 읽기 순서를 추측해 복원하지 않는다. 사용자가 확인한 정리되지 않은 문장·표에 대해서는 원문과 추출본을 대조하는 추가 점검이 필요하다.
- 일반 졸업 항목까지 개인 audit를 요구하는 트리 응답은 원문 정제와 별개인 정보 구조 문제다. 프런트는 기존 `/catalog/rule-programs`로 승인 기준을 조회해 분리했다. 서버에서도 일반 기준 안내와 개인 점검 결과의 역할을 정렬해 주면 좋겠다.

## 백엔드·AI 담당 요청

1. **구조화 필드 역할 확정**: 일정의 제목·기간·추가 설명과 출처를 구분한다. `body`가 단순 표시용 결합 문자열인지, 별도 설명인지 API 문서로 명확히 해 달라. 기존 클라이언트 호환을 고려하고, 새 필드·버전이 필요하면 OpenAPI로 확정한다.
2. **수집·추출·정제 단계 구분**: 웹 일정, PDF 텍스트, OCR, 표 추출 경로별로 원문 대비 문단·줄바꿈·목록·중복 제목/날짜·머리말/꼬리말 반복을 점검한다. 실제 문제를 확인한 자료와 페이지를 기준으로 정제하며 다른 경로의 문제로 일반화하지 않는다.
3. **의미·근거 보존**: 숫자·단위·날짜·예외·적용 범위·조항 관계를 누락하거나 바꾸지 않는다. 정제한 문장/표와 원문 URL·파일·페이지·판본의 대응을 유지한다. 표의 null을 0/면제로 바꾸지 않는다.
4. **검토 상태 구분**: 정제 실패·OCR 미검토·표 구조 불확실과 검토된 내용을 구분해 현재 경고/상태 계약 또는 합의한 후속 계약으로 반환한다. 실패한 텍스트를 정제된 정상 본문처럼 제공하지 않는다.
5. **일반 기준/개인 결과 정렬**: 이수학점·필수과목·봉사·자격·논문 등은 일반 조건과 출처를, ‘내 졸업요건 요약’은 본인 결과·기준일·현재 사용 가능 여부를 제공하는 방향을 검토한다. 현재 별도 기준 API를 프런트에서 연결했으므로 같은 API를 새로 만들어 달라는 요청은 아니다.

## 프런트 완료 범위와 수용 조건

- 같은 URL/파일/문서/페이지의 출처만 묶는다. 다른 문서·페이지는 구분하며 항목별 원문 근거 대응을 없애지 않는다.
- 달력은 구조화된 제목·날짜를 한 번만 표시한다. body가 두 필드의 정확한 결합인 경우만 중복 표시를 생략하고, 추가 설명이 있으면 보존한다.
- 수집 시각·긴 원시 타임스탬프는 기본 표시에서 제거했다. 자료 확인 설명은 접힌 상세로 옮기고 OCR 경고·오류·실제 일정 날짜는 유지한다.
- 백엔드 정제 수용은 원문 대조 후 내용 손실/수치 변경 없음, 필드 역할 명확화, 페이지·판본 근거 보존, 불확실 상태 표시를 확인한다. 프런트 가독성 개선을 추출 파이프라인 정제 완료로 간주하지 않는다.

이 요청은 PR #53의 백엔드·AI 검토 항목이며 이번 프런트 변경에서는 수집·OCR·정제 서버 코드를 수정하지 않는다.
