# 내 자료로 공고 찾기

## 사용자 흐름

학생이 채용공고 분석에서 ‘내 자료로 공고 찾기’를 연다. 기존 공고 본문 분석은 별도 흐름으로 유지한다. 직무를 입력하고 지역을 고른 뒤 필요하면 현재 학년을 직접 선택한다. 기기의 파일 또는 본인 저장 기록을 고르고 선택한 자료와 외부 처리 고지를 확인한 뒤 분석 실행을 누른다. 선택한 자료에서 추출한 텍스트를 Google Gemini로 보내는 데 동의한 경우에만 요청한다.

입력·자료 선택 → 외부 전송 확인 → 처리 중 → 추천 목록 또는 빈 이유 → 공고별 비교·자료 인용 펼치기 순서다. 오류 뒤 직무·지역·파일·기록 선택을 보존한다. 처리 중 중복 실행을 막으며 자동 재전송하지 않는다. 계정 교체·로그아웃 시 선택과 결과를 폐기한다. 게스트는 전송하지 않는다.

## 계약과 경계

- 요청 계약은 `docs/api/openapi.json`, 표시 계약은 PR #77의 [서버·프런트 적용법](../../../backend/app/rag/career/TEAM_INTEGRATION.md)을 따른다.
- `POST /api/v1/me/job-recommendations`에 직무·지역, 파일 바이트의 base64, 선택 기록 종류·ID·버전, 외부 처리 동의, 비교 한도 3건을 보낸다. 단일 직무 입력칸에 쉼표로 최대 5개 직무(총 80자)를 적을 수 있다. 사용자가 현재 학년을 선택한 경우에만 `academic_stage`를 보낸다. 수집 모드는 서버 설정을 따른다.
- 기기 파일 5개·합계 8MiB, PDF·DOCX·UTF-8 TXT/MD·PNG/JPEG/WebP. PDF 쪽수·OCR 장수·추출 조각 수는 서버에서 검증한다. 기기 자료를 자동 수집하거나 파일 보관함을 만들지 않는다.
- 공급자별 공식 지역 코드 카탈로그가 없어 최초 연결은 명시적 ‘전국’만 활성화한다. 지역 선택란과 제한 사유를 표시하며 코드를 추정하거나 사용자에게 코드 입력을 요구하지 않는다.
- `display_candidates` 순서대로 근거가 확인된 후보, 조건 확인 필요, 분석 미완료 검색 후보를 표시한다. 공고별 `stage_guidance.sentences`를 순서대로 표시하고 같은 출처·ID의 `items`에서 상세 비교와 인용을 연결한다. 별도 추천 근거와 미확인 필수조건 수는 근거가 확인된 후보에 표시한다.
- `display_candidates`가 없는 기존 응답은 `recommendations`와 `items`로 표시한다. 후보가 0건이어도 비교 대상과 수집처 상태를 표시한다. 수집 실패·모델 실패·근거 부족·설정 필요를 구분한다.
- 학년 선택 기능은 PR #77의 요청 필드를 지원하는 API와 함께 배포한다. 배포 전 화면 검증에는 합성 응답을 사용한다.

## 화면 방향과 검증

기존 FeaturePage·SurfaceCard·테마·외부 링크 확인을 재사용한다. 데스크톱 입력, 처리 중, 부분 성공, 추천 없음, OCR 출처, 오류 후 입력 보존을 합성 응답으로 검증한다. 로컬 실제 API 확인은 경로와 연결 상태까지만 수행한다. 실제 OCR·모델·공고 수집의 실행 결과나 품질을 검증했다고 보고하지 않는다.
