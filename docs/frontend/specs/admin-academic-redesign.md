# 관리자 세 메뉴 구현 시나리오

학생 수신·O/X·개인 기록 연결·학생 API는 후속 단계다. 기존 학생 동작은 보존한다.

## 시각 방향

기존 Pretendard와 테마·표면·입력 컴포넌트를 사용한다. 데스크톱에서 목록과 입력의 소속을
하나의 명확한 테두리 영역으로 묶고, 이름·적용 대상·저장 상태를 먼저 읽게 한다.
중립 배경에 주 저장 동작만 강조하고, 장식 이미지와 새 애니메이션은 추가하지 않는다.
한 줄 요건/학점표/인증 요건 명칭을 유지한다. 기존 학교 규정 캡처의 표현 구조를 따른다.

## 학교·학과와 공통 분류

- 역할/진입: 활성 학교 관리 권한을 가진 관리자가 학교·학과 메뉴에서 학교 하나를 선택한다.
- 목적/행동: 학교·학과의 기존 자료를 관리하고 같은 학교의 이수구분/세부분류·경로를 작성한다.
- 입력: 분류 이름·상위 선택, 경로 이름. 필수/선택을 별도 마스터로 만들거나 분류 코드를 입력하지 않는다.
- 반응: 목록은 빈 상태에도 제목·비어 있는 이유·추가 행동을 표시한다. 학교를 바꾸면 작성 보호를 적용한다.
- 완료: 서버 저장→화면 재진입/새 세션 재조회에서 같은 ID와 내용 확인. 게시본은 읽기 전용이며 복사해 개정한다.
- 실패: 입력 보존·동일 요청 재시도·version 충돌 시 최신 목록 재조회. 권한 상실은 저장을 차단한다.

## 교육과정·과목

- 역할/진입: 같은 학교의 교육과정·과목 메뉴에서 교육과정을 선택하거나 등록한다.
- 목적/행동: 적용 학과·입학연도·경로와 과목 목록을 관리한다. 과목을 재사용하고 교육과정별 분류·필수 여부를 한 번 지정한다.
- 입력: 교육과정 이름·기준 연도·범위, 과목 원본·학교 분류·필수/선택·인정학점.
- 반응: 분류의 상위는 세부분류 선택에서 결정한다. 기존 고정 전공/교양과 추가 분류를 동시에 입력하지 않는다.
- 완료: 과목 생성과 교육과정 편입을 원자 저장하고 재조회에서도 원본과 분류 연결이 일치한다.
- 실패: code 중복은 기존 과목 선택으로 복구하고, 충돌·응답 유실은 저장 결과 확인/동일 키 재시도를 제공한다.

## 졸업요건

- 역할/진입: 학교를 선택한 관리자가 한 줄 요건/학점표/인증 요건을 선택한다.
- 공통: 적용 대상을 정하고 본문을 작성·저장·재조회·수정·게시한다. 출처 URL을 한 줄 요건 입력으로 요구하지 않는다.
- 한 줄 요건: 문장 추가·삭제·순서 변경. 별도 규칙 묶음 등록 폼을 필수 단계로 노출하지 않는다.
- 학점표: 다단 열 묶음·경로 행·숫자/빈칸/해당 없음·소계/총계·비고·필요한 열 분류 연결·미리보기.
- 인증 요건: 기준·하위 영역·모두/택1/택N·면제/대체·설명 표. 학생 개인 기록 선택은 제공하지 않는다.
- 완료: 새 세션에서도 대상·본문·stable ID·분류 연결을 보존하고 게시본 원문은 수정되지 않는다.
- 실패: 잘못된 입력 위치를 표시하고 다른 내용은 보존한다. 미완성 초안 저장과 게시 가능 여부를 구분한다.

## 검증 범위

데스크톱을 기본으로 입력/대기/빈 상태/오류/저장 성공/충돌/게시본을 검증한다.
좁은 화면의 신규 수동 검증은 기존 사용자 보류를 유지한다. UI 연결이 끝난 단위마다
실제 계약의 저장·재조회와 관련 위젯 검사, 마지막에 정적 분석·Web/Windows 빌드를 수행한다.
