# 학생 학사 기준 연결 시나리오

확정 범위: 관리자 게시 한 줄 요건·학점표·인증 요건, 주·추가 전공 연결,
학생 O/X·본인 기록 검색·학점 진행 상황·명시적 개정 전환. 기존 기록/감사/개인 계산 유지.

## 흐름

1. 로그인 학생이 설정에서 등록 학교·주학과·입학연도를 저장한다. 같은 학교의
   이수 경로·교육과정을 고르고 주전공/추가 전공을 저장한다. 미선택/여러 후보는 직접 선택한다.
2. 졸업요건에서 적용 후보·현재 기준과 변경 내용을 확인하고 적용한다.
   프로필 부족·대상 미확정·실패·게시본 없음은 서로 다른 상태로 표시한다.
3. 한 줄 요건과 인증의 기준별 미확인/O/X를 바로 저장한다. 항목 아래에서 본인 기록을 검색·확인하며 요건과 연결하지 않는다.
   저장 오류는 입력 유지, 결과 미확정은 같은 요청 재시도, version 충돌은 재조회한다.
4. 수강 원본은 그대로 두고 교육과정 과목·이수 결과·취득학점·산입 여부를 연결한다.
   학점표에서 목표/취득/부족과 산입·제외·확인 필요 근거를 확인한다.
5. 새 개정은 차이를 안내하고 학생 확인 뒤 전환한다. 바뀐 응답은 재확인하며
   기록 수정/삭제·철회·프로필 변경도 오래된 결과로 처리한다. 이전 이력은 보존한다.

## 화면 목업

기존 Pretendard·테마·SurfaceCard·선택 제어·한 화면 주 행동을 재사용한다.
새 텍스트는 시스템 ID 대신 학교·학과·경로·과목 이름을 표시한다.

```text
졸업 요건                         [기존 졸업 감사] [개인 기준 계산]
학교 · 주전공 / 추가 전공 · 입학연도        [학업 기준 설정]
[현재 적용 기준 / 변경 미리보기 / 확인 후 적용]
[한 줄 요건] [학점표] [인증 요건]
왼쪽: 문장/기준 [미확인 O X]  |  오른쪽: 공통 내 기록 찾기
요건 목록 독립 스크롤         |  검색·종류 필터·상세 독립 스크롤
학점표 다단 헤더 — 목표/취득/부족 — [산입 근거]
```

데스크톱 검증이 기본이며 좁은 화면 신규 수동 검증은 기존 보류를 따른다.
학교 정책이 없는 재수강·중복 인정은 자동 확정하지 않는다. 집계는 서버가 수행한다.

## 설정·수강 등록 연결

- 학업 기준 설정은 전공 연결과 학교 후보 API만 사용한다. 학점 집계 조회 실패가 설정 진입을 막지 않는다.
- 교육과정 후보는 서버의 적용 범위(학과·입학연도·경로)를 따른다. 조건 변경으로 맞지 않게 된 선택은 해제하고, 임의로 다른 교육과정을 고르지 않는다.
- 수강 등록은 저장된 주·추가 전공의 게시 교육과정 과목을 가져온다. 학교 분류·필수 여부·인정학점·P/F를 유지한다. 전공 연결이 없는 기존 사용자의 학교 과목 경로와 개인 과목 후보는 유지한다.
- 성적·수강 캡처의 인트라넷 코드·이수구분·학점을 개인 기록 그대로 보존한다. PDF 교과번호와 같은 코드 체계라고 가정하지 않는다. 수강 목록에는 PDF 과목 일괄 연결이나 미연결 경고를 요구하지 않으며 기존 연결 API는 호환용으로만 유지한다.
- 수강 상태는 수강 예정·수강 중·이수 완료·미이수다. 기존 recorded/이수 기록은 이수 완료로 유지한다. 수강 저장과 과목 연결·산입 갱신을 한 서버 트랜잭션으로 처리하며, 이수 완료는 기록된 과목 학점을 사용한다. 일반 화면에서 별도 산입·취득학점 입력을 요구하지 않는다. P/F 미확인 학점은 0으로 바꾸지 않는다.
- 목록은 과목명·학기·분류·학점·상태만 표시하고 메모·출처·분반·성적은 상세 보기에 보존한다. 일반 목록·졸업요건에서 별도 산입 편집 진입을 제거하며 기존 API는 호환용으로 유지한다.
- 목록의 합계는 현재 연도·학기 필터에 맞춰 취득·수강 예정·두 값의 총 학점을 구분한다. 미이수는 총계에서 제외하며, 수강 예정은 취득학점으로 바꾸지 않는다. 과목 선택에는 긴 교육과정 출처·‘내 수강 기록’ 접두어 대신 과목명·코드·학점·분류를 표시한다. 캡처 입력은 개인 수강 기록을 저장하며 학교 공통 과목을 별도로 생성하지 않는다.
- 학점표 열별 집계는 관리자 열의 학교 분류·참조 또는 성적표 이수구분 연결을 사용한다. 관리자 학점표의 ‘성적표 이수구분 연결’에서 값 열마다 정확한 성적표 분류를 지정할 수 있다. 학생에게 과목별 연결 설정을 요구하지 않는다. 게시 원문·목표값·적용본은 변경하지 않는다.
- 성적표 연결 열은 개인 수강 상태·학점으로 취득·예정·총계를 표시하며 현재 부족은 취득만으로 계산한다. PDF 번호 일치는 필요 없다. 소계·총계는 직접 연결할 수 있고 참조 집계에서 동일 기록을 중복 산입하지 않는다. 근거 없는 교양 세부분류는 ‘분류 확인 필요’로 남기며 취득 0으로 표시하지 않는다. 추가 전공 전용 행은 명시적인 전공 산입 자료 없이 자동 배분하지 않는다.
- 학생 학점표는 관리자 다단 열을 유지하고 이수 경로마다 기준학점·취득학점·예정학점·취득+예정·부족학점을 별도 행으로 비교한다. 취득·부족 행을 강조하고 숫자와 설명을 분리한다. 미확인 값은 ‘확인 필요’, 빈 목표는 대시, 명시적인 0은 0으로 표시한다. 산입·제외 사유와 과목은 접힌 ‘산입 내역’에서 확인한다. 관리자 원문 미리보기는 기존 형태를 유지한다.
- 한 줄·인증 개별 요건의 O/X는 문장 옆 선택 칩으로 바로 저장하고 ‘초기화’는 미확인(null)으로 저장한다. 저장 중·응답 유실 상태에는 중복 쓰기를 막고 동일 요청 재시도 경로를 유지한다. 기록 연결 버튼·팝업은 삭제했다. 새 응답은 records=[]로 저장하며 기존 연결은 다음 응답 저장 시 해제하고 과거 이력은 보존한다. 철회·권한·프로필 불일치·게스트 제한은 기존대로 유지한다.
- 한 줄·인증 화면은 왼쪽 요건 목록과 오른쪽 공통 ‘내 기록 찾기’로 나누고 각각 독립 스크롤한다. 항목별 검색 버튼은 제공하지 않는다. 검색은 한 번 조회하고 탭 전환에도 검색어·종류 필터·결과·검색 스크롤 위치를 유지한다. 학점표는 전체 폭으로 표시하며 검색 상태는 보존한다. 가용 폭760 미만에서는 같은 두 영역을 세로 배치한다.
- 수강·활동·자격·경험·성과와 같은 계정의 자료를 함께 검색한다. 제목·메모·기관·기간·성적·상태 등의 등록 필드와 자료의 이름·설명·파일명을 검색하며 PDF 본문은 추출하지 않는다. 종류 필터·상세 펼침·재조회·부분 실패 안내를 제공한다. 검색 결과는 읽기 전용이며 O/X나 기록을 자동 변경하지 않는다. 계정 변경 시 검색 내용과 결과를 비운다.
- 학점표의 다섯 행은 기준·취득·수강 중·취득+수강 중·부족으로 표시한다. 수강 목록의 합계도 실제 수강 중만 더한다. 수강 예정은 계획으로 유지하며 합계에 포함하지 않는다. 기존 예정 응답 필드는 API 호환용으로 유지하고 새 `in_progress`·`earned_with_in_progress` 필드를 표시한다. 학생 기록의 상태를 일괄 변경하지 않는다.
- F·낮은 성적 등으로 다시 수강할 때 별도 재수강 개체를 만들지 않는다. 학생이 과거 기록을 미이수로 관리하고 새 학기 기록을 예정/진행/완료로 관리한다. 과목코드가 같아도 학기가 다른 기록은 삭제·통합하지 않으며 원 성적·메모를 임의로 F로 변경하지 않는다.
