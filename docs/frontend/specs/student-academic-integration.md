# 학생 학사 기준 연결 시나리오

확정 범위: 관리자 게시 한 줄 요건·학점표·인증 요건, 주·추가 전공 연결,
학생 O/X·본인 기록 연결·학점 진행 상황·명시적 개정 전환. 기존 기록/감사/개인 계산 유지.

## 흐름

1. 로그인 학생이 설정에서 등록 학교·주학과·입학연도를 저장한다. 같은 학교의
   이수 경로·교육과정을 고르고 주전공/추가 전공을 저장한다. 미선택/여러 후보는 직접 선택한다.
2. 졸업요건에서 적용 후보·현재 기준과 변경 내용을 확인하고 적용한다.
   프로필 부족·대상 미확정·실패·게시본 없음은 서로 다른 상태로 표시한다.
3. 한 줄 요건의 미확인/O/X, 인증의 기준별 응답과 본인 기록 연결을 저장한다.
   저장 오류는 입력 유지, 결과 미확정은 같은 요청 재시도, version 충돌은 재조회한다.
4. 수강 원본은 그대로 두고 교육과정 과목·이수 결과·취득학점·산입 여부를 연결한다.
   학점표에서 목표/취득/부족과 산입·제외·확인 필요 근거를 확인한다.
5. 새 개정은 차이를 안내하고 학생 확인 뒤 전환한다. 바뀐 응답은 재확인하며
   기록 수정/삭제·철회·프로필 변경도 오래된 결과로 처리한다. 이전 이력은 보존한다.

## 화면 목업

기존 Pretendard·테마·SurfaceCard·선택 제어·한 화면 주 행동을 재사용한다.
새 텍스트는 시스템 ID 대신 학교·학과·경로·과목 이름을 표시한다.

```text
졸업 요건                         [기존 졸업 감사] [개인 기준 계산]
학교 · 주전공 / 추가 전공 · 입학연도        [학업 기준 설정]
[현재 적용 기준 / 변경 미리보기 / 확인 후 적용]
[한 줄 요건] [학점표] [인증 요건]
문장/기준  [미확인 O X]  [연결 기록]
학점표 다단 헤더 — 목표/취득/부족 — [산입 근거]
```

데스크톱 검증이 기본이며 좁은 화면 신규 수동 검증은 기존 보류를 따른다.
학교 정책이 없는 재수강·중복 인정은 자동 확정하지 않는다. 집계는 서버가 수행한다.

## 설정·수강 등록 연결

- 학업 기준 설정은 전공 연결과 학교 후보 API만 사용한다. 학점 집계 조회 실패가 설정 진입을 막지 않는다.
- 교육과정 후보는 서버의 적용 범위(학과·입학연도·경로)를 따른다. 조건 변경으로 맞지 않게 된 선택은 해제하고, 임의로 다른 교육과정을 고르지 않는다.
- 수강 등록은 저장된 주·추가 전공의 게시 교육과정 과목을 가져온다. 학교 분류·필수 여부·인정학점·P/F를 유지한다. 전공 연결이 없는 기존 사용자의 학교 과목 경로와 개인 과목 후보는 유지한다.
- 기존 수강 기록은 재등록하지 않는다. 학생이 실행하는 일괄 연결은 현재 전공의 학교 과목 코드가 정확히 일치하고 후보가 하나인 경우만 연결한다. 이름만 같은 과목이나 여러 후보는 수정에서 선택한다.
- 수강 상태는 수강 예정·수강 중·이수 완료·미이수다. 기존 recorded/이수 기록은 이수 완료로 유지한다. 수강 저장과 과목 연결·산입 갱신을 한 서버 트랜잭션으로 처리하며, 이수 완료는 기록된 과목 학점을 사용한다. 일반 화면에서 별도 산입·취득학점 입력을 요구하지 않는다. P/F 미확인 학점은 0으로 바꾸지 않는다.
- 목록은 과목명·학기·분류·학점·상태만 표시하고 메모·출처·분반·성적은 상세 보기에 보존한다. 일반 목록·졸업요건에서 별도 산입 편집 진입을 제거하며 기존 API는 호환용으로 유지한다.
- 학점표 열별 집계는 관리자 열의 학교 분류·참조 설정이 있어야 한다. 미연결 관리자 기준은 학생 기록이나 열 이름으로 추정하지 않고 기존 확인 필요 상태를 유지한다.
