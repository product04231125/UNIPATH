# Flutter Web·Windows 플랫폼 차이

이 문서는 **현재 구현된** 차이만 기록한다. 공통 UX 원칙은 [제품 UX 기준](../product-ux.md)을
따르며, 구현 전 판단·개인 환경 이슈는 개인 노트에 둔다.

| 영역 | Web | Windows |
| --- | --- | --- |
| 화면 코드 | 같은 Flutter 화면 코드 사용 | 같은 Flutter 화면 코드 사용 |
| 개발용 관리자 | 같은 공통 작업 공간·hash `/admin/...` | 같은 입력·범위·버전 목업 |
| 화면 테마 | 설정에서 3테마 선택·기기 로컬 저장 | 같은 선택·저장, 열린 AI 창에도 IPC 반영 |
| 사이드바 | 축소 시 아이콘 탐색 유지 | 같은 축소/펼치기, 좁은 관리자 창도 아이콘 탐색 |
| 좁은 폭 AI | 가용 폭 `1180px` 미만에서 전체 작업 폭의 AI 전용 보기. 본문 상태 보존·탐색 제외, 돌아가기·Esc 복귀 | 앱 창 폭에 따라 같은 도킹/전용 보기 레이아웃 |
| AI 분리 | 제공하지 않음. 도킹 패널과 좁은 폭 전용 보기 사용 | 열기 기본값은 내부 패널. 분리 창 선택 가능, 실패 시 내부 패널 대체 |
| 대화 상태 | 앱 실행 중 패널 닫기·재열기에서 유지 | 메인이 대화·요청 소유, 분리 창에 IPC 표시. 분리 창 닫기 시 같은 대화로 내부 패널 복귀 |
| 분리 창 전면화 | 해당 없음 | 이미 열린 창을 전면화 |
| 메인 창 최대화 | 브라우저가 창 상태를 관리 | 최대화 중 분리 명령을 숨기고 도킹 패널을 사용 |
| 창 최소 폭 | `480px` 미만에서 작업 공간 가로 스크롤 fallback | 최소 `480×520`, 같은 재배치·스크롤 fallback |
| 탐색·표 전환 순서 | `900px` 미만 또는 표 최소 폭 부족 시 아이콘 탐색을 먼저 적용. 그래도 부족하면 표 스크롤, `480px` 미만은 조작 가능한 작업 공간 스크롤바 | 같은 가용 폭 계산에 메뉴·본문 여백·열린 AI 도킹 폭을 포함 |
| 뒤로가기·앞으로가기 | 주요 메뉴 hash URL과 브라우저 기록 연결, 직접 진입·새로고침에서 요청 메뉴 유지 | 같은 Router 메뉴 선택, 브라우저 기록 UI 없음. OS 창 동작과 별개 |
| 외부 링크 | 확인 후 `_blank` 새 탭 요청 | 확인 후 기본 브라우저 요청 |

플랫폼별 기능을 바꾸면 해당 기능 문서와 이 표를 함께 갱신하고, Web과 Windows 빌드 또는
실행 확인 결과를 변경 단위에 남긴다.

학생·학교관리자·슈퍼관리자 샘플 진입은 두 플랫폼 모두 Release 빌드에 노출하지 않는다.
