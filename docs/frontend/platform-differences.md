# Flutter Web·Windows 플랫폼 차이

이 문서는 **현재 구현된** 차이만 기록한다. 공통 UX 원칙은 [제품 UX 기준](../product-ux.md)을
따르며, 구현 전 판단·개인 환경 이슈는 개인 노트에 둔다.

| 영역 | Web | Windows |
| --- | --- | --- |
| 화면 코드 | 같은 Flutter 화면 코드 사용 | 같은 Flutter 화면 코드 사용 |
| 좁은 폭 AI | 가용 폭 `1180px` 미만에서 아이콘과 오버레이. 아이콘 탐색 제외 폭의 절반 이내·최대 360px, 홈 주간표는 가려진 폭 제외 | 앱 창 폭에 따라 같은 도킹/오버레이 레이아웃 |
| AI 분리 | 제공하지 않음. 도킹 패널과 좁은 폭 오버레이만 사용 | 네이티브 보조 창을 열고 존재·닫힘을 감지 |
| 분리 창 전면화 | 해당 없음 | 이미 열린 창을 전면화 |
| 메인 창 최대화 | 브라우저가 창 상태를 관리 | 최대화 중 분리 명령을 숨기고 도킹 패널을 사용 |
| 창 최소 폭 | `480px` 미만에서 작업 공간 가로 스크롤 fallback | 최소 `480×520`, 같은 재배치·스크롤 fallback |
| 탐색·표 전환 순서 | `900px` 미만 또는 표 최소 폭 부족 시 아이콘 탐색을 먼저 적용. 그래도 부족하면 표 스크롤, `480px` 미만은 조작 가능한 작업 공간 스크롤바 | 같은 가용 폭 계산에 메뉴·본문 여백·열린 AI 도킹 폭을 포함 |
| 뒤로가기·앞으로가기 | URL 라우팅 미구현 | OS 창 탐색과 별개로 메뉴 기록 미구현 |
| 외부 링크 | 확인 후 `_blank` 새 탭 요청 | 확인 후 기본 브라우저 요청 |

플랫폼별 기능을 바꾸면 해당 기능 문서와 이 표를 함께 갱신하고, Web과 Windows 빌드 또는
실행 확인 결과를 변경 단위에 남긴다.
