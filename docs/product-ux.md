# UniversityPath 제품 UX 기준

이 문서는 Flutter Web과 Windows 학생 화면의 공통 UX 기준 단일 원본이다. API, Rule
Engine, RAG의 책임을 바꾸지 않으며, **현재 구현된 정책**과 **추가 권장 사항**을 구분한다.

## 1. 공통 원칙과 작업 공간

- 화면 물리 해상도가 아닌 앱 창의 가용 폭을 기준으로 재배치한다. 큰 창에서는 정보가
  늘어나고, 작은 창에서는 겹침·잘림 없이 재배치·숨김·오버레이로 전환한다.
- 일반 본문·목록·표는 줄바꿈과 유동 폭을 우선한다. 비교 축이 많은 교육과정 행렬만
  하나의 가로 스크롤 컨테이너 안에 그룹 헤더·열·데이터 행을 함께 둔다.
- AI는 기록·탐색·문서 설명을 돕는 보조 영역이다. 학점·필수과목·승인 여부의 충족
  판정은 Rule Engine 결과로만 보인다. RAG/LLM은 근거와 설명을 제공하며 판정을 바꾸지
  않는다.
- 한 화면에는 가장 중요한 행동 하나를 주 행동으로 둔다. 버튼은 `활동 추가`, `공식 문서
  열기`처럼 동사와 대상을 명시하고, 색만으로 상태를 전달하지 않는다.

| 대상 | 현재 기준 | 의도 |
| --- | --- | --- |
| Windows 메인 창 | 기본 `1440×900`, 최소 `1365×768` | 좌측 탐색·본문·우측 AI를 함께 읽을 수 있는 작업 공간 |
| 우측 AI 도킹 패널 | 가용 폭 `1180px` 이상, 폭 `300–480px` | 본문을 가리지 않는 보조 대화 영역 |
| 좁은 Web 창 | `1180px` 미만에서 채팅 아이콘·오버레이 | 본문 폭 우선 |
| 분리 AI 창 | Windows만, 최소 `300×520` | 메인과 겹치지 않는 보조 OS 창 |
| AI 기본 상태 | 닫힘 | 필요할 때만 열어 현재 과업 집중 유지 |

### AI 패널과 창

- 도킹 패널은 폭 조절 가능하되 본문을 먼저 침해하지 않는다.
- 독립 창이 열려 있으면 메인의 채팅 아이콘은 새 창 대신 해당 창을 전면화한다.
- 메인을 최대화하면 분리 창을 닫고 도킹 패널로 복귀하며, 최대화 중에는 분리 명령을
  노출하지 않는다. Web 팝업이 차단되면 도킹/오버레이를 대체 수단으로 제공한다.
- AI를 닫으면 원래 제어 요소로 포커스를 되돌리고, 좁은 창의 오버레이는 `Esc`로 닫을 수
  있게 한다. 대화 실패·근거 부족은 토스트만 쓰지 말고 재시도 가능한 인라인 상태로 남긴다.

## 2. 레이아웃·입력·접근성

### 정보 밀도와 표

- 홈은 일반 데스크톱 높이에서 핵심 행동과 상태를 한 화면에 보이게 한다. 좁아질 때는
  장식·보조 설명·여백 순서로 줄이고 핵심 행동은 유지한다.
- 활동·경험·자격·포트폴리오·성과는 같은 카드 밀도와 그리드를 사용한다. 넓은 화면의
  여백은 읽기 길이·보조 영역에 사용하고 의미 없는 빈 공간으로 남기지 않는다.
- 일반 표는 열 폭을 재배분하고 긴 텍스트를 줄바꿈한다. 교육과정 행렬만 최소 셀 폭과
  가로 스크롤을 유지한다.

### 입력과 상태

- 입력에는 항상 라벨, 형식/예시, 필수 여부를 표시한다. 오류는 문제 필드·이유·수정
  방법을 텍스트로 보여 주고, 실패해도 작성 값은 보존한다.
- 저장·임시저장·동기화 대기·성공·오류는 같은 영역에서 현재 상태와 다음 행동을 보여 준다.
- AI 제안은 학생이 `적용` 또는 `저장`을 확인하기 전에는 기록을 바꾸지 않는다.
- 외부 사이트는 새 창 이동임을 표시하며, 외부 결과만으로 학교 승인·자격 취득·졸업 반영을
  자동 처리하지 않는다.

### 접근성·플랫폼

- 아이콘 단독 버튼에는 툴팁과 접근 가능한 이름을 둔다. 조작 대상은 최소 `24×24` CSS px
  이상을 목표로 하고, 포커스·호버·비활성·처리 중 상태를 정의한다.
- 키보드 탭 순서와 포커스 윤곽선을 유지하고, 125%·150%·200% DPI, 고대비, Web 200% 확대
  및 좁은 폭에서 기능·정보가 사라지지 않는지 확인한다.
- Windows/Web의 표준 창·단축키·브라우저 동작을 존중한다. macOS의 장점은 명확한 기본값,
  사용자 주도성, 긴 작업을 위한 밀도, 즉시 피드백으로 참고하되 시각 양식을 복제하지 않는다.

## 3. 설정 UX

설정은 현재 작업의 필터·정렬·기록 추가가 아니라 드물게 바꾸는 개인화·AI·접근성·계정
옵션을 위한 독립 본문 페이지다. 좌측 탐색 하단에 고정하고, 한 행에 제목·영향 설명·현재
값/제어 요소를 둔다. 범주는 `일반`, `AI와 데이터`, `알림`, `접근성`, `계정·정보`의 다섯
개 이하로 유지한다.

| 범주 | 허용 예 | 경계 |
| --- | --- | --- |
| 작업 공간 | AI 기본 열림, 패널 폭·마지막 메뉴 복원 | 기기 로컬 저장을 우선 검토, 기본 AI 닫힘 |
| 표시·접근성 | 시스템 테마 사용, 정보 밀도, 동작 줄이기 | OS 글꼴·고대비·테마를 복제하거나 무시하지 않음 |
| AI와 데이터 | 대화 이력 보존/삭제, 현재 기록 문맥 사용 | 공식 규정·Rule Engine 적용 범위를 바꾸지 못함 |
| 알림·외부 연계 | 실제 구현된 알림/연결 상태 | 권한·API 계약 전에는 토글을 노출하지 않음 |
| 계정·정보 | 도움말, 버전, 내보내기·삭제 요청 | 비밀번호·토큰·외부 API 키를 입력·표시하지 않음 |

가역 설정은 즉시 반영하고, 삭제·연결 해제·로그아웃은 대상·영향·확인 또는 복구 경로를
제공한다. 비활성 설정은 숨기지 말고 사용할 수 없는 이유를 설명한다.

## 4. 지원되지 않는 학교용 개인 기준

학교·학과가 지원되지 않아도 학생은 본인 전용 학교·학과·입학연도·교육과정과 규칙 세트를
구성할 수 있다. 이는 관리자 제보나 단순 메모가 아니라 개인용 학업 작업 공간이다.

1. 학교명·학과·입학연도·교육과정을 설정한다.
2. 최소 학점, 전공/교양, 필수과목, 졸업인증 같은 개인 규칙을 항목별로 추가한다.
3. 수강·활동·경험·자격·성과를 직접 기록해 개인 규칙의 현재 값으로 연결한다.
4. 결정론적 **개인 기준 계산**으로 충족·미충족·확인 필요를 표시한다.

개인 기준 결과에는 항상 `개인 기준 계산 · 학교 공식 판정 아님`을 표시한다. 공식 학교
기준이 생기면 공식 Rule Engine 판정을 우선하고, 개인 원본 기록·개인 규칙은 삭제하지
않는다. 개인 규칙은 다른 학생, 공식 문서 RAG 근거, 학교 공식 규칙을 변경하지 않는다.

## 5. 현재 구현과 추가 권장

- 현재 목업의 창 크기, AI 도킹/분리, 반응형 전환, 표 스크롤 및 개인 기준 계산은 목업
  동작이며 영구 저장·API 연동을 약속하지 않는다.
- 추가 구현 전에는 개인 규칙 API, 비교 연산, 기록 매핑, 규칙 버전/계산 이력, 동기화·
  삭제 정책과 공식 기준 전환 정책을 합의한다.
- 파일 업로드는 형식·크기·공개 범위·민감정보 경고를 먼저 표시한다. 실제 영구 저장 위치와
  삭제 정책은 백엔드·보안 설계가 확정된 뒤 정한다.

## 6. QA 체크리스트

| 시나리오 | 확인 기준 |
| --- | --- |
| Windows `1365×768`, `1440×900`, `1920×1080` | 좌측 탐색·본문·도킹 AI가 겹치지 않고 홈의 불필요한 세로 스크롤이 없음 |
| Web 좁은 폭·확대 | AI가 오버레이로 바뀌고 일반 콘텐츠는 재배치되며 행렬 표만 가로 스크롤 |
| AI·분리 창 | 닫기·전면화·최대화 복귀·포커스 복귀가 일관되고 창이 본문을 가리지 않음 |
| 폼·상태 | 라벨·오류·저장 결과·재시도가 보이고 작성 값이 보존됨 |
| 개인 기준 | 직접 입력이 개인 계산에만 쓰이며 공식 졸업 판정·RAG 근거와 혼동되지 않음 |
