# UniversityPath 제품 UX 기준

이 문서는 Flutter Web과 Windows 학생 화면의 **공통 UX 기준 단일 원본**이다. 메뉴별 화면의
현재 구현·목업 경계·후속 계약은 [프론트엔드 기능 문서](frontend/README.md)를 따른다. API,
Rule Engine, RAG의 책임을 바꾸지 않으며, **현재 구현된 정책**과 **추가 권장 사항**을 구분한다.

## 1. 공통 원칙과 작업 공간

- 목업 관련 화면 안내·배지·문구는 표시하지 않는다. 예외는 사이드바 `목업용` 데이터 표시 제어와 로그인 샘플 진입 영역이다. 제어가 사용하는 fixture·기존 동작은 유지하고, 기기 로컬 보관·공식 판정과의 구분처럼 실제 데이터 성격을 설명하는 문구는 유지한다. 실제 인증·서버 저장 여부는 기능 문서의 계약 경계로 관리한다.

- 제품 테마는 크림·브라운(기본), 밝은 파랑, 다크 오렌지 세 가지이며 설정에서 기기별 선택을 저장한다. 개발 시안 비교 제어는 제공하지 않는다. 삭제 버튼은 흰 글자와 채워진 붉은 배경을 사용하며 기존 확인·권한 검증을 유지한다. 다크 입력 오류는 선명한 빨강과 오류 문구를 함께 표시한다. 제목표시줄은 밝은 테마에서 본문보다 진하게, 다크에서 밝게 구분한다.

- 화면 물리 해상도가 아닌 앱 창의 가용 폭을 기준으로 재배치한다. 큰 창에서는 정보가
  늘어나고, 작은 창에서는 겹침·잘림 없이 재배치·숨김·오버레이로 전환한다.
- 일반 본문·목록·표는 줄바꿈과 유동 폭을 우선한다. 비교 축이 많은 교육과정 행렬만
  하나의 가로 스크롤 컨테이너 안에 그룹 헤더·열·데이터 행을 함께 둔다.
- 창을 좁힐 때는 좌측 메뉴 아이콘화가 가로 스크롤보다 먼저다. `900px` 미만이거나 펼친
  메뉴·본문 여백·열린 AI 도킹 폭을 제외한 공간이 현재 화면의 최소 폭보다 작으면 메뉴를
  접는다. 홈 주간표와 졸업요건 교육과정 행렬에 적용하며, 아이콘 메뉴에서도 부족할
  때만 해당 표에 가로 스크롤바를 표시한다. 일반 본문은 계속 재배치한다.
- AI는 기록·탐색·문서 설명을 돕는 보조 영역이다. 학점·필수과목·승인 여부의 충족
  판정은 Rule Engine 결과로만 보인다. RAG/LLM은 근거와 설명을 제공하며 판정을 바꾸지
  않는다.
- 한 화면에는 가장 중요한 행동 하나를 주 행동으로 둔다. 버튼은 `활동 추가`, `공식 문서
  열기`처럼 동사와 대상을 명시하고, 색만으로 상태를 전달하지 않는다.

| 대상 | 현재 기준 | 의도 |
| --- | --- | --- |
| Windows 메인 창 | 기본 `1440×900`, 최소 `480×520` | 시작 시 현재 모니터 작업 영역보다 크면 여백 안으로 줄이고, 좁은 폭은 재배치·스크롤 fallback을 사용 |
| 우측 AI 도킹 패널 | 가용 폭 `1180px` 이상, 폭 `300–480px` | 본문을 가리지 않는 보조 대화 영역 |
| 좁은 Web 창 | `1180px` 미만에서 채팅 아이콘·AI 전용 보기 | 본문과 AI를 전환 |
| 분리 AI 창 | Windows만, 최소 `300×520` | 메인과 겹치지 않는 보조 OS 창 |
| AI 기본 상태 | 닫힘 | 필요할 때만 열어 현재 과업 집중 유지 |

### AI 패널과 창

- Windows 메인 제목표시줄은 앱 상단과 통합한다. 왼쪽 뒤로/앞으로·사이드바 축소/펼치기 제어, 오른쪽 최소화·최대화/복원·닫기를 제공하며 빈 영역 드래그/더블클릭을 유지한다. Web에는 OS 창 제어를 표시하지 않는다.
- 분리 채팅은 작업 영역 안의 메인 오른쪽에 비겹침 공간이 있을 때만 배치한다. 공간 부족 시 사용자의 메인 창을 이동·축소하지 않고 내부 패널로 전환한다. 메인 창 위치/크기는 기기 선호로 복원하되 사라진 모니터의 좌표는 현재 작업 영역 안으로 보정한다.

- 도킹 패널은 폭 조절 가능하되 본문을 먼저 침해하지 않는다.
- 가용 폭 1180px 미만에서 AI를 열면 작업 공간 전체를 사용하는 전용 보기로 전환한다. 본문은 상태를 유지한 채 숨기며 포커스·접근성 탐색에서 제외한다. 돌아가기 버튼·닫기·Esc로 복귀하고 AI 열기 버튼에 포커스를 돌려준다. Tab/Shift+Tab은 전용 보기 안에서 순환한다. 도킹 전환·닫기/재열기에도 작성 중 학교 정보와 질문을 유지한다.
- 독립 창이 열려 있으면 메인의 채팅 아이콘은 새 창 대신 해당 창을 전면화한다.
- Windows 채팅 열기의 기본값은 내부 패널이다. 기존 열기 설정도 한 번 내부 패널로 이전하며
  이후 사용자가 고른 분리 창 선호는 유지한다. 분리 창을 닫으면 같은 대화의 내부 패널로 복귀한다.
  메인 창이 대화·작성 중 질문·요청을 소유하므로 응답 중 전환에서도 요청을 다시 보내지 않는다.
  IPC 실패 시 미전달 초안을 유지하고 재연결을 제공한다. 앱 종료 뒤 대화 복원은 제공하지 않는다.
- 메인을 최대화하면 분리 창을 닫고 도킹 패널로 복귀하며, 최대화 중에는 분리 명령을
  노출하지 않는다. Web 팝업이 차단되면 도킹/오버레이를 대체 수단으로 제공한다.
- AI를 닫으면 원래 제어 요소로 포커스를 되돌리고, 좁은 창의 오버레이는 `Esc`로 닫을 수
  있게 한다. 대화 실패·근거 부족은 토스트만 쓰지 말고 재시도 가능한 인라인 상태로 남긴다.
- 학교 질의는 사용자가 확인한 학교 문맥과 질문만 전송한다. 응답 대기 중에는 중복 전송을
  막고 실패·추가 입력 요구 시 작성한 질문을 보존한다. 다시 질문하면 같은 대화 항목을 갱신한다.
  질문 제출 시 최신 항목으로 이동하며, 이전 근거를 읽는 중인 사용자의 스크롤은 응답 완료만으로
  이동시키지 않는다. 공식 근거 부족과 졸업감사 필요를 별도 안내하며 고정 AI 답변을 표시하지 않는다.
- 설정과 채팅은 저장에 성공한 학교·학과·입학연도·이수경로를 공유한다. 채팅의 학교 정보 폼은
  채팅 내부 스크롤 영역에서 열며 질문 입력은 하단에 유지한다. 작성 중인 값은 외부 프로필
  변경으로 덮어쓰지 않는다. 학교 정보 저장 중에는 질문 전송·재시도와 패널 닫기·분리를 막는다.
- Windows 분리 창의 학교 정보는 메인 창이 읽고 저장한다. 읽기 실패는 안내와 재시도를
  제공한다. 학교 정보와 일정의 동시 저장은 순서대로 처리해 기존 일정·계획 옵션을 보존한다.

## 2. 레이아웃·입력·접근성

### 메뉴 제목과 헤더

- 기록·일정·설정·졸업 요건 및 하위 작업 화면은 공통 `PageHeader`를 사용한다.
  장식용 영어 라벨과 제목의 번역 반복은 넣지 않는다. 한글 제목 → 필요한 문맥 → 기존 설명
  순서로 표시하며, 문맥·설명은 필요할 때만 사용한다. 학교·학과·적용 연도·개인/예시 상태 같은
  실제 정보는 유지하지만 데이터가 없을 때 임의로 생성하지 않는다.
- 제목은 공통 26px, 설명 14px, 문맥 13px 스타일과 시스템 글자 확대를 따른다. 선택 문구 사이
  간격은 8px, 헤더 뒤 본문 간격은 16px이며 없는 문구의 공간은 예약하지 않는다.
- 작업 공간이 외부 여백을 소유한다. 헤더·탭·설명·본문은 왼쪽 시작선을 공유하며, 읽기 폭 제한은
  왼쪽 정렬한다. 포트폴리오·개인 졸업 작업 공간은 탭 아래 12px 간격으로 현재 단계 제목을 표시한다.
  카드 내부 콘텐츠는 기존 카드 여백을 유지한다.
- 기존 헤더 버튼은 넓은 폭에서 제목 옆, 헤더 가용 폭 600px 미만 또는 본문 글자 배율이 1.2를
  넘으면 제목 아래 행에 배치한다. 문구는 자연스럽게 줄바꿈하며 고정 높이·말줄임으로 숨기지 않는다.
  제목은 접근성 heading 의미를 갖고 읽기 대기·실패에도 표시한다.
- 홈은 날짜·제목·일정 추가·상태 요약을 간결한 헤더에 표시한다. 주간 일정과 다음 행동을 먼저 보이게 하고 준비 목록·기록 링크의 강조를 낮춘다.

### 정보 밀도와 표

- 모든 메뉴의 세로 본문은 `ContentScrollView`로 끝 방향 16px 스크롤바 공간을 예약한다.
  읽기 대기·실패 및 읽기 전용 초안 미리보기도 같은 여백을 사용한다. 중첩 세로 스크롤은
  만들지 않으며, 주간표·교육과정 행렬의 가로 스크롤은 별도 축으로 유지한다.
  본문의 최소 폭 계산에는 이 여백을 포함해 메뉴 아이콘화가 표 스크롤보다 먼저 일어나게 한다.

- 같은 행의 관련 카드는 공통 `EqualHeightRow`로 실제 줄바꿈된 내용의 최대 높이를 측정해
  상단·하단선을 맞춘다. 고정 높이로 내용을 자르거나 intrinsic 추정으로 긴 글을 숨기지 않는다.
  좁은 폭에서는 세로로 쌓고 각 카드의 자연 높이를 유지한다. 새 메뉴도 같은 공통 위젯을 사용한다.
  주간표의 날짜 칸처럼 비교 축이나 역할이 다른 영역은 자동으로 동일 높이를 강제하지 않는다.
  수강의 교육과정 확인은 주 기록과 역할이 다른 보조 안내이므로 목록 아래 펼치기 영역에 둔다.

- 홈은 일반 데스크톱 높이에서 핵심 행동과 상태를 한 화면에 보이게 한다. 좁아질 때는
  장식·보조 설명·여백 순서로 줄이고 핵심 행동은 유지한다.
- 활동·경험·자격·포트폴리오·성과는 같은 카드 밀도와 그리드를 사용한다. 넓은 화면의
  여백은 읽기 길이·보조 영역에 사용하고 의미 없는 빈 공간으로 남기지 않는다.
- 일반 표는 열 폭을 재배분하고 긴 텍스트를 줄바꿈한다. 교육과정 행렬만 최소 셀 폭과
  가로 스크롤을 유지한다.
- 주간 일정표는 7일의 순서를 유지하며 각 칸 최소 폭 92를 제공한다. 가로 공간이 부족하면
  스크롤바를 표시한다. 기록·졸업요건 화면은 제목과 안내도 본문과 함께 세로 스크롤한다.
- 주간표·교육과정 행렬은 공통 `HorizontalScrollArea`로 14px 하단 스크롤 여백과 손잡이·
  가로 휠/트랙패드·마우스 드래그를 제공한다. 맞던 표가 폭 축소 뒤 넘치게 되는 경우에도
  실제 스크롤 범위가 확정된 뒤 제스처를 갱신한다. 새 비교 표도 같은 위젯을 사용한다.

### 입력과 상태

- 새 다중 필드 등록·수정은 `showInputDialog`와 `InputDialog`를 함께 사용한다.
  모달 최대 폭은 640px, 화면 여백은 24px이다. 본문만 스크롤하며 제목·저장/취소는 유지한다.
  스크롤은 `ContentScrollView`가 소유하고 끝 방향 16px 여백을 확보해 입력 테두리와 겹치지 않는다.
- 채팅 내부의 학교 정보 폼은 이 모달 배치의 예외다. 채팅을 유지하며 정보를 보완하는
  용도로 내부 스크롤을 사용하고 저장 실패 시 입력 보존·중복 저장 방지 원칙은 동일하게 적용한다.
- 새 폼이 비어 있으면 바깥 클릭으로 닫는다. 공백과 자동 기본값만 있으면 빈 상태다.
  입력·선택·순서·첨부가 있거나 기존 기록 수정 중이면 바깥 클릭으로 닫지 않고 명시적 취소를 요구한다.
  저장 중에는 닫기·중복 저장을 막고, 실패 시 입력을 유지한다. 단일 선택·날짜 선택·삭제 확인은
  이 입력 보호 규칙과 구분한다. 새 기능도 공통 틀을 사용하고 기본값을 제외한 작성 상태를 제공한다.
- 명시적 취소는 새 폼의 기본값을 제외한 작성 내용 또는 수정 원본 대비 변경이 있으면
  `작성한 내용을 폐기할까요?`를 확인한다. `계속 작성`에 기본 포커스를 두며 입력·선택·순서·
  포커스를 보존하고, `내용 폐기`만 폼을 닫는다. 확인창의 Esc·바깥 클릭은 폐기하지 않는다.
  빈 신규 폼·변경 없는 수정 폼은 확인 없이 취소한다. 채팅 내부 학교 정보 폼도 같은 확인을 사용한다.
- 다른 메뉴에서 `추가`를 누르면 해당 메뉴와 입력창을 한 번에 연다. 공통 `PendingUiAction`을
  준비된 목적 화면이 한 번만 소비하며, 일반 메뉴 이동·날짜 선택·새로고침은 자동 추가와 구분한다.

- 글자는 공통 테마의 네 단계(페이지 제목 26, 섹션 제목 18, 본문/제어 14, 보조문 13 logical px)를
  사용한다. 줄높이는 제목 1.3–1.35, 본문/보조문 1.5이며 시스템 글자 확대를 유지한다.
- 단일 선택 메뉴는 필드 아래 시작선에 붙이고, 공간이 부족할 때 Flutter 메뉴 배치가 화면 안으로
  반전·보정한다. 선택·Esc 뒤에는 트리거로 포커스를 되돌린다. 여러 필드 입력과 날짜/시간 선택은
  중앙 모달 대화상자로 구분하며, 일반 입력 대화상자는 최대 폭 640으로 제한한다.

- 입력에는 항상 라벨, 형식/예시, 필수 여부를 표시한다. 오류는 문제 필드·이유·수정
  방법을 텍스트로 보여 주고, 실패해도 작성 값은 보존한다.
- 저장·임시저장·동기화 대기·성공·오류는 같은 영역에서 현재 상태와 다음 행동을 보여 준다.
- AI 제안은 학생이 `적용` 또는 `저장`을 확인하기 전에는 기록을 바꾸지 않는다.
- 외부 사이트는 새 창 이동임을 표시하며, 외부 결과만으로 학교 승인·자격 취득·졸업 반영을
  자동 처리하지 않는다.

### 접근성·플랫폼

- 아이콘 단독 버튼에는 툴팁과 접근 가능한 이름을 둔다. 조작 대상은 최소 `24×24` CSS px
  이상을 목표로 하고, 포커스·호버·비활성·처리 중 상태를 정의한다.
- 키보드 탭 순서와 포커스 윤곽선을 유지하고, 125%·150%·200% DPI, 고대비, Web 200% 확대
  및 좁은 폭에서 기능·정보가 사라지지 않는지 확인한다.
- Windows/Web의 표준 창·단축키·브라우저 동작을 존중한다. macOS의 장점은 명확한 기본값,
  사용자 주도성, 긴 작업을 위한 밀도, 즉시 피드백으로 참고하되 시각 양식을 복제하지 않는다.

## 3. 설정 UX

설정은 현재 작업의 필터·정렬·기록 추가가 아니라 드물게 바꾸는 개인화·AI·접근성·계정
옵션을 위한 독립 본문 페이지다. 좌측 탐색 하단에 고정하고, 한 행에 제목·영향 설명·현재
값/제어 요소를 둔다. 범주는 `일반`, `AI와 데이터`, `알림`, `접근성`, `계정·정보`의 다섯
개 이하로 유지한다.

| 범주 | 허용 예 | 경계 |
| --- | --- | --- |
| 작업 공간 | AI 기본 열림, 패널 폭·마지막 메뉴 복원 | 기기 로컬 저장을 우선 검토, 기본 AI 닫힘 |
| 표시·접근성 | 시스템 테마 사용, 정보 밀도, 동작 줄이기 | OS 글꼴·고대비·테마를 복제하거나 무시하지 않음 |
| AI와 데이터 | 대화 이력 보존/삭제, 현재 기록 문맥 사용 | 공식 규정·Rule Engine 적용 범위를 바꾸지 못함 |
| 알림·외부 연계 | 실제 구현된 알림/연결 상태 | 권한·API 계약 전에는 토글을 노출하지 않음 |
| 계정·정보 | 도움말, 버전, 내보내기·삭제 요청 | 비밀번호·토큰·외부 API 키를 입력·표시하지 않음 |

가역 설정은 즉시 반영하고, 삭제·연결 해제·로그아웃은 대상·영향·확인 또는 복구 경로를
제공한다. 비활성 설정은 숨기지 말고 사용할 수 없는 이유를 설명한다.

## 4. 지원되지 않는 학교용 개인 기준

학교·학과가 지원되지 않아도 학생은 본인 전용 학교·학과·입학연도·교육과정과 규칙 세트를
구성할 수 있다. 이는 관리자 제보나 단순 메모가 아니라 개인용 학업 작업 공간이다.

1. 학교명·학과·입학연도·교육과정을 설정한다.
2. 최소 학점, 전공/교양, 필수과목, 졸업인증 같은 개인 규칙을 항목별로 추가한다.
3. 수강·활동·경험·자격·성과를 직접 기록해 개인 규칙의 현재 값으로 연결한다.
4. 판정 API 연결 뒤 결정론적 **개인 기준 계산** 결과로 충족·미충족·확인 필요를 표시한다.
   현재는 교육과정·과목·규칙과 기록 연결을 기기에 저장하며, 서버 결과가 없으므로 판정은 표시하지 않는다.

개인 기준 결과에는 항상 `개인 기준 계산 · 학교 공식 판정 아님`을 표시한다. 공식 학교
기준이 생기면 공식 Rule Engine 판정을 우선하고, 개인 원본 기록·개인 규칙은 삭제하지
않는다. 개인 규칙은 다른 학생, 공식 문서 RAG 근거, 학교 공식 규칙을 변경하지 않는다.

## 5. 현재 구현과 추가 권장

- 현재 창 크기, AI 도킹/분리, 반응형 전환과 표 스크롤은 클라이언트 동작이다. 설정의 학업과 계획,
  개인 일정·기록·교육과정·규칙은 기기 로컬에 보관하며 서버 동기화나 판정 API 연동은 없다.
  졸업 표 예시는 목업이며 개인 규칙 입력을 계산 결과로 취급하지 않는다.
- 추가 구현 전에는 개인 규칙 API, 비교 연산, 기록 매핑, 규칙 버전/계산 이력, 동기화·
  삭제 정책과 공식 기준 전환 정책을 합의한다.
- 파일 업로드는 형식·크기·공개 범위·민감정보 경고를 먼저 표시한다. 실제 영구 저장 위치와
  삭제 정책은 백엔드·보안 설계가 확정된 뒤 정한다.

## 관리자 작업 공간의 현재 탐색 규칙

- 두 관리자 역할이 같은 셸을 사용하며 슈퍼관리자에게만 관리자 관리 메뉴를 표시한다.
- 가용 폭 760px 이상·본문 배율 1.5 미만에서는 글자 메뉴를 표시하고, 좁은 폭·확대 또는 사용자의 축소 선택에서는 아이콘 탐색을 유지한다. 메뉴를 완전히 숨기지 않는다. 현재 경로를 시각/접근성 선택 상태로 표시한다.
- 학교 문맥과 실제 상세 대상은 일치해야 한다. 상세에서 학교를 바꾸면 새 학교의 메뉴 목록으로
  이동하며 이전 검색/상태 필터를 초기화한다. 직접 상세 진입은 읽기 가능한 대상의 학교를 표시한다.
- 현황의 초안·최근 변경과 목록 검색은 현재 계정이 읽을 수 있는 자료만 표시한다. 상세 작업도
  목록과 같은 최신 권한·버전 조건을 사용한다. 실제 서버 권한 검증을 대신하는 UI 규칙은 아니다.
- 필드 그룹은 실제 입력만 나누며 공통 저장 실패 입력 유지·폐기 확인을 유지한다.

## 키보드 탐색 순서

- Tab은 왼쪽 메뉴 → 본문 → AI 패널(열린 경우) → 상단 순서이며 Shift+Tab은 역순이다. 상단은 뒤로·앞으로·사이드바 축소/펼치기·Windows 창 제어 순서다.
- 반응형 2열은 왼쪽 작업 영역을 모두 마친 뒤 오른쪽으로 이동하고 1열 전환 후에도 같은 순서를 유지한다. 비활성 제어·숨겨진 방문 페이지는 건너뛴다. 모달은 내부 입력 → 취소 → 저장으로 순환하고 종료 후 열었던 제어로 복귀한다.
- 드롭다운은 표준 메뉴 키보드 동작을 사용하며 포커스 이동 시 스크롤 영역이 대상을 보여준다. AI 패널을 닫으면 다시 표시된 AI 열기 버튼으로 포커스를 돌린다.
