## 발표 대본

슬라이드 11장을 읽는 데 약 3분 50초가 걸립니다(공백 포함 분당 약 330자 기준). 슬라이드 순서만 받은 PPT를 따랐고, 말할 내용은 실제 서비스에 맞춰 새로 썼습니다. ○○○은 발표자 이름으로 바꿉니다.

### 1. 표지 (10초)

안녕하세요. 6조 ○○○입니다. 대학 생활의 기록을 졸업과 취업 준비로 이어 주는 서비스, UniPath를 소개하겠습니다.

### 2. 목차 (6초)

배경, 기능, 구성, 설계 원칙 순서로 설명하고 바로 시연하겠습니다.

### 3. 배경과 목표 (37초)

학생의 기록은 흩어져 있습니다. 수강 내역은 학교 포털에, 자격증과 활동은 각자의 파일에, 프로젝트는 깃허브에 있습니다. 졸업 요건은 규정을 읽고 직접 계산해야 하고, 채용공고는 공고마다 요구 조건이 달라 내가 무엇이 부족한지 알기 어렵습니다. UniPath는 이 기록을 한곳에 모아, 졸업까지 남은 것과 목표 직무까지 남은 것을 내 기록을 근거로 보여 줍니다.

### 4. 핵심 기능 (41초)

기능은 네 가지입니다. 첫째, 수강·활동·자격·경험 기록과 포트폴리오 파일을 계정에 모아 둡니다. 둘째, 학교가 등록한 교육과정과 졸업 규칙으로 졸업 요건과 학점표를 계산합니다. 셋째, 목표 직무의 실제 채용공고를 모아 공통 요건과 내 기록을 비교하고, 내 자료에 맞는 공고를 순서대로 보여 줍니다. 넷째, 부족한 요건에 맞는 활동과 자격증을 추천하고, 공고에 맞춘 자기소개서와 포트폴리오 초안을 씁니다.

### 5. 이용 흐름 (19초)

학생은 학기마다 수업과 활동을 기록하고 목표 직무를 정합니다. 그러면 공고 요건과 내 기록을 비교해 준비된 것과 부족한 것을 나눠 보여 주고, 부족한 것은 일정과 준비 계획으로 이어집니다.

### 6. 시스템 구성 (34초)

화면은 Flutter로 만들어 웹과 윈도우 앱으로 배포했습니다. 서버는 FastAPI, 데이터베이스는 PostgreSQL과 pgvector입니다. 졸업 요건은 규칙 엔진이 계산하고, 학사 자료는 BM25로 검색합니다. 채용공고는 고용24와 사람인에서 모으고, 비교와 글쓰기는 Google Vertex AI의 Gemini가 맡습니다.

### 7. 설계 의사결정 (34초)

설계 원칙은 세 가지입니다. 첫째, 졸업 판정은 AI가 아니라 규칙으로 계산하고, 자료가 부족한 칸은 추측하지 않고 확인 필요로 둡니다. 둘째, AI는 내 기록에 있는 사실만 근거로 쓰고, 예정이거나 진행 중인 일은 완료한 것처럼 쓰지 않습니다. 셋째, 개인 기록을 외부 AI로 보내기 전에 무엇을 보내는지 보여 주고 동의를 받습니다.

### 8. 역할 분담 (9초)

프론트엔드와 UX는 홍요아, AI와 데이터는 신우철, 백엔드와 통합은 이어진이 맡았습니다.

### 9. 결과·확장 방향 (18초)

지금은 스테이징 서버에서 웹과 윈도우 앱으로 모든 기능을 쓸 수 있습니다. 다음 단계는 운영 서버로 옮기고, 학교 관리자 화면으로 다른 학과와 학교의 교육과정을 늘려 가는 것입니다.

### 10. 시연 졸업 학점표 (5초)

학점표는 시연에서 실제 화면으로 보여 드리겠습니다.

### 11. 시연 시나리오 (20초)

시연은 백엔드 개발자를 준비하는 졸업예정 학생 계정으로 합니다. 먼저 활동, 자격증, 자료, 학사의 기록을 보고, 그 기록으로 채용공고 분석과 자기소개서, 포트폴리오까지 이어지는 흐름을 보여 드리겠습니다.

## 시연 시나리오와 대본

시연은 장면 10개(0~9), 5분 30초입니다. 장면 1~4는 학생이 쌓아 둔 기록(활동·자격증·자료·학사)이고, 장면 5~8은 그 기록을 근거로 쓰는 기능(채용공고 분석·자기소개서·포트폴리오)입니다. 목표 직무 분석, 내 자료로 공고 찾기, 자기소개서, 포트폴리오는 11월 25일에 같은 계정으로 실제로 실행해 저장한 결과를 엽니다. 저장 결과는 바뀌지 않으므로 대본에 실제 값을 적었습니다. 자격증 추천만 그 자리에서 실제 AI를 부릅니다.

### 장면 0. 전환과 홈 (3:50, 20초)

**조작:** PPT에서 미리 로그인해 둔 브라우저로 넘깁니다(홈 화면). 목표 직무와 다가오는 일정을 가리킵니다.

**말:** 지금부터 실제 서비스로 시연하겠습니다. 경동대 컴퓨터공학과 2019학번, 백엔드 개발자를 준비하는 졸업예정 학생입니다. 홈에는 목표 직무와 일정, 이번 주 할 일이 모입니다. 먼저 쌓아 둔 기록부터 보겠습니다.

### 장면 1. 활동 (4:10, 30초)

**조작:** ‘자료’ 메뉴 → ‘내 자료’ 탭. 위쪽 요약(활동 3 · 경험 2 · 자격증 3 · 자료 4 · 기록 시간 108시간)을 가리키고, ‘활동 5’ 칩을 눌러 카드 5개를 차례로 가리킵니다.

**말:** 내 자료에는 활동, 자격증, 포트폴리오 같은 자료를 한곳에 기록하고, 위쪽 칩으로 종류별로 봅니다. 먼저 활동입니다. 동아리, 대회, 봉사 같은 활동과 프로젝트 경험을 기록합니다. 백엔드 스터디 60시간, 교내 해커톤, 코딩 교육 봉사, 그리고 RouteOn과 졸업작품 UniPath 프로젝트가 있습니다. 기간과 역할, 한 일을 적어 두면 뒤에서 볼 공고 비교와 자기소개서의 근거가 됩니다.

### 장면 2. 자격증 – 자격증 추천 실시간 (4:40, 45초)

**조작:**

1. 내 자료의 ‘자격증 3’ 칩. 카드 3개(정보처리기사·SQLD 취득, 리눅스마스터 2급 1차 합격·2차 준비 중)를 가리킵니다.
2. ‘자격증’ 메뉴 → ‘자격증 추천’ 탭. 현재 학년에 학업 프로필의 ‘졸업예정’이 채워져 있습니다. ‘자격증 추천 받기’
3. ‘외부 전송’ 대화상자를 잠깐 보여 주고 ‘이번만 허용’(약 10초)
4. 추천 카드의 준비 시기와 시험 일정을 가리킵니다.

**말:** 자격증도 내 자료에 취득한 것과 준비 중인 것을 함께 기록합니다. 정보처리기사와 SQLD는 취득했고, 리눅스마스터 2급은 2차를 준비 중입니다. 이 기록과 목표 직무로 자격증 메뉴에서 자격증 추천을 그 자리에서 받아 보겠습니다. 개인 기록이 외부 AI로 가기 때문에, 보내기 전에 무엇을 보내는지 보여 주고 동의를 받습니다. 추천은 이미 가진 자격을 빼고, 준비 중인 자격은 보유로 치지 않습니다. 각 자격에는 준비 시기와 공식 자료 기준 시험 일정이 붙습니다.

### 장면 3. 자료 (5:25, 25초)

**조작:** 다시 ‘자료’ 메뉴 → ‘내 자료’ 탭 → ‘자료 4’ 칩. 자료 4개를 가리키고, ‘백엔드 포트폴리오 요약’의 ‘PDF 보기’를 눌러 첫 쪽을 보여 준 뒤 닫습니다.

**말:** 자료 칩에는 포트폴리오 PDF, 이력서 요약, 깃허브 저장소 설명 같은 파일 자료가 있습니다. 올린 PDF는 바로 열어 볼 수 있고, 공고를 찾을 때 기록과 함께 비교할 자료로 고를 수 있습니다.

### 장면 4. 학사 – 학점표 (5:50, 35초)

**조작:** ‘학사’ 메뉴 → ‘졸업 요건’ 탭 → ‘학점표’ 칩

**말:** 학사 메뉴는 수강 기록으로 졸업 요건을 계산합니다. 학교가 등록한 2019학년도 컴퓨터공학과 교육과정과 수강 기록 58과목으로 만든 학점표입니다. 최소 졸업 학점 130학점 중 112학점을 취득해 18학점이 남았고, 수강 중인 20학점을 마치면 132학점이 됩니다. 이 계산은 AI가 아니라 규칙 엔진이 하고, 분류 자료가 없는 칸은 추측하지 않고 확인 필요로 둡니다.

### 장면 5. 채용공고 분석 – 목표 직무 분석, 저장된 결과 (6:25, 50초)

**조작:**

1. 왼쪽 메뉴 ‘채용공고 분석’ → 위쪽 ‘목표 직무 분석’ 탭
2. 왼쪽 아래 ‘저장된 결과’에서 별표가 붙은 ‘소프트웨어 · 백엔드’(11월 25일 15:03 · 준비 6 / 10)를 누릅니다.
3. 오른쪽 맨 위 ‘준비된 요건 6 / 10’ 막대와 요약을 가리킵니다.
4. 아래로 내려 초록 ‘Python 백엔드 개발 역량’ 카드의 내 기록 근거(RouteOn의 FastAPI API)를 보여 줍니다.
5. 주황 ‘AI 및 머신러닝 활용/개발 역량’ 카드의 준비 제안(오픈소스 AI API 연동 웹 서비스 개발 · 약 4주)에서 ‘일정에 추가’ → 달력에 잡힌 목표일 그대로 ‘확인’

**말:** 이제 이 기록으로 채용공고를 분석합니다. 목표 직무 분석은 고용24와 사람인에서 백엔드 공고를 최대 8건 모아, 공통 요구 조건과 제 기록 전체를 비교합니다. 40초쯤 걸려 미리 저장한 결과를 엽니다. 공통 요건 10개 중 6개가 준비됐고, Python 백엔드 요건은 활동에서 본 RouteOn의 FastAPI 기록이 근거입니다. AI 활용 역량은 일부 준비로 나와 준비 제안이 붙고, ‘일정에 추가’로 바로 일정에 넣습니다. 합격 판정이 아니라 요건과 기록의 비교입니다.

### 장면 6. 채용공고 분석 – 내 자료로 공고 찾기, 저장된 결과 (7:15, 50초)

**조작:**

1. 위쪽 ‘내 자료로 공고 찾기’ 탭. 왼쪽 입력 칸(직종·검색어, 근무 지역, 현재 학년, 함께 비교할 내 자료)을 짧게 가리킵니다.
2. 왼쪽 맨 아래 ‘저장된 결과’에서 별표가 붙은 ‘소프트웨어 · 백엔드 · 서울·경기’(11월 25일 15:47 · 공고 3건)를 누릅니다.
3. 1위 리더스시스템즈 카드의 ‘추천’, ‘준비 4 / 7 · 필수 2 / 2’, “필수 요건 2개를 모두 갖춰 추천했습니다.”를 가리킵니다.
4. 1위 카드의 ‘전체 요건과 비교 근거’를 펼쳐, ‘컴퓨터 계열 4년제 대학 졸업’의 근거 ‘학적 정보: 공고 찾기에서 고른 학년’을 보여 줍니다.
5. 2위 빅앤딥 ‘조건 확인 필요’(필수 1 / 3)와 3위 한국디지탈콘트롤 ‘필수 요건 미충족’(필수 0 / 1)의 판정 이유를 가리킵니다.

### 저장 결과를 만들 때 쓴 값

시연에서는 입력하지 않습니다. 저장 결과를 다시 만들 때 같은 값을 씁니다.

- 내 자료로 공고 찾기: 직종과 검색어는 목표 직무에서 자동으로 채워집니다(연구 및 공학기술 › 소프트웨어, 백엔드). 근무 지역은 서울·경기, 현재 학년은 졸업예정을 고르고, 함께 비교할 내 자료에서 ‘백엔드 포트폴리오 요약’을 체크합니다.
- 자기소개서: 공고 찾기 1위 카드의 ‘자기소개서 쓰기’로 들어가 문항 “지원 동기와 지원 직무 관련 경험을 적어 주세요.”, 글자 수 800자.
- 포트폴리오: 같은 화면에서 ‘포트폴리오’로 바꾸고 ‘이 공고 요건 순으로 구성’을 누른 뒤 ‘초안 만들기’.

### 데이터 스크립트

스크립트 위치는 [scripts/demo/seed_demo_student.py](../../scripts/demo/seed_demo_student.py)입니다. `--live`를 붙이면 라이브 서버에서, 빼면 스테이징 서버에서 실행합니다. 계정 정보는 서버 쪽 폴더(라이브 `~/.config/unipath-live-demo/`, 스테이징 `~/.config/unipath-staging-demo/`)에서 읽습니다. 학생은 `account.json`, 학교 관리자는 `admin.json`에 있습니다. 계정 파일에 적힌 서버 주소가 고른 서버와 다르면 아무것도 바꾸지 않고 멈춥니다.

```bash
python3 scripts/demo/seed_demo_student.py --live --reset   # 리허설 흔적을 지우고 처음 상태로 (약 20초)
python3 scripts/demo/seed_demo_student.py --live --status  # 지금 들어 있는 것만 확인(고정한 결과에 '고정' 표시)
python3 scripts/demo/seed_demo_student.py --live --pin     # 앱에서 새로 만든 최신 결과·문서를 시연용으로 고정
python3 scripts/demo/seed_demo_student.py --live --clear   # 시연 뒤 정리(고정도 풂)
```

`--reset`은 고정한 저장 결과 2개(목표 직무 분석·공고 찾기)와 저장 문서 2개(자기소개서·포트폴리오)를 남기고, 그 밖의 분석 결과와 문서를 지웁니다. 리허설 중 추가한 일정·기록도 지운 뒤, 위 표의 스크립트 데이터를 다시 넣습니다. 수강 기록, 원래 있던 자료, 고정한 결과가 인용하는 기록은 지우지 않습니다. 그래서 리셋한 뒤에도 저장 결과의 근거가 그대로 맞습니다. 일정은 실행한 날을 기준으로 다시 만들어집니다. 그래서 시연 당일 아침에 한 번 실행합니다.

`--pin`은 앱에서 저장된 가장 최근의 목표 직무 분석·공고 찾기 결과와 가장 최근의 자기소개서·포트폴리오 문서를 시연용으로 고정합니다. 분석 결과에는 별표를 붙여 목록 맨 위에 두고, 지금 있는 경험·활동·자격·내 자료도 함께 남깁니다. 저장 결과를 새로 만들고 싶으면 앱에서 다시 실행해 저장한 뒤 `--pin`을 다시 실행합니다.

시연이 끝나면 `--clear`로 스크립트와 리허설에서 생긴 데이터와 고정한 결과·문서를 지우고, 목표 직무를 처음 값으로 되돌립니다. 넣기, 리셋, 정리는 확인용 계정에서, 고정과 고정 후 리셋은 시연 계정에서 미리 시험했습니다.

학교 관리자는 초기화하지 않습니다. `--reset`과 기본 실행 때 그 서버의 API 컨테이너 안에서 경동대학교 학교 관리자인지만 확인합니다(로그인하지 않음). 없을 때만 승인과 같은 방식으로 만듭니다. 승인은 슈퍼관리자만 할 수 있기 때문입니다. 그러면 학교 관리 권한과 감사 기록이 함께 남고, 부여자는 기존 슈퍼관리자로 기록됩니다. 이미 있는 계정의 비밀번호와 역할은 바꾸지 않습니다.

어떤 모드도 계정을 지우지 않습니다. 슈퍼관리자 계정은 만들지도, 바꾸지도, 지우지도 않습니다. 학생 계정 자리에 관리자나 슈퍼관리자 계정이 설정돼 있으면 아무것도 바꾸지 않고 멈춥니다.

## 리허설 측정과 비상 대처

11월 25일 시연 계정으로 잰 AI 응답 시간입니다. 1분 가까이 걸리는 기능은 저장한 결과를 엽니다.

| 기능 | 응답 시간 | 시연에서 |
| --- | --- | --- |
| 내 자료로 공고 찾기 | 약 100초(포트폴리오 PDF 포함) | 저장된 결과를 엶 |
| 목표 직무 분석 | 38초 | 저장된 결과를 엶 |
| 자기소개서 초안 | 약 40초 | 저장한 문서를 엶 |
| 포트폴리오 초안 | 약 70초(공고 요건 순 구성) | 저장한 문서를 엶 |
| 자격증 추천 | 10초 | 그 자리에서 실행 |
| 활동 추천 | 13초 | 예비 장면(시간이 남을 때) |

### 비상 대처

- **저장된 결과나 문서가 목록에 없을 때:** 누군가 별표를 풀고 지웠을 수 있습니다. 서버에서 `--live --status`로 ‘고정’이 붙은 결과와 문서가 있는지 확인합니다. 시연 중이라면 그 자리에서 실행합니다(목표 직무 분석 약 40초, 공고 찾기 약 1분 40초). 기다리는 동안 활동이나 자료 화면에서 근거가 될 기록을 설명합니다.
- **자격증 추천에서 오류가 날 때:** 한 번만 다시 실행합니다. 다시 실패하면 장면 2의 1에서 본 내 자료 ‘자격증’ 카드로 설명하고 넘어갑니다.
- **인터넷이 끊길 때:** 휴대폰 핫스팟으로 바꿉니다. 바꿔도 안 되면 PPT의 시연 시나리오 슬라이드로 돌아가 흐름만 설명합니다.
