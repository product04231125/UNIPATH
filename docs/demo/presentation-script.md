## 발표 대본

슬라이드 11장을 읽는 데 약 3분 50초가 걸립니다(공백 포함 분당 약 330자 기준). 슬라이드 순서만 받은 PPT를 따랐고, 말할 내용은 실제 서비스에 맞춰 새로 썼습니다. ○○○은 발표자 이름으로 바꿉니다.

### 1. 표지 (10초)

안녕하세요. 6조 ○○○입니다. 대학 생활의 기록을 졸업과 취업 준비로 이어 주는 서비스, UniPath를 소개하겠습니다.

### 2. 목차 (6초)

배경, 기능, 구성, 설계 원칙 순서로 설명하고 바로 시연하겠습니다.

### 3. 배경과 목표 (37초)

학생의 기록은 흩어져 있습니다. 수강 내역은 학교 포털에, 자격증과 활동은 각자의 파일에, 프로젝트는 깃허브에 있습니다. 졸업 요건은 규정을 읽고 직접 계산해야 하고, 채용공고는 공고마다 요구 조건이 달라 내가 무엇이 부족한지 알기 어렵습니다. UniPath는 이 기록을 한곳에 모아, 졸업까지 남은 것과 목표 직무까지 남은 것을 내 기록을 근거로 보여 줍니다.

### 4. 핵심 기능 (41초)

기능은 네 가지입니다. 첫째, 수강·활동·자격·경험 기록과 포트폴리오 파일을 계정에 모아 둡니다. 둘째, 학교가 등록한 교육과정과 졸업 규칙으로 졸업 요건과 학점표를 계산합니다. 셋째, 목표 직무의 실제 채용공고를 모아 공통 요건과 내 기록을 비교하고, 내 자료에 맞는 공고를 순서대로 보여 줍니다. 넷째, 부족한 요건에 맞는 활동과 자격증을 추천하고, 공고에 맞춘 자기소개서와 포트폴리오 초안을 씁니다.

### 5. 이용 흐름 (19초)

학생은 학기마다 수업과 활동을 기록하고 목표 직무를 정합니다. 그러면 공고 요건과 내 기록을 비교해 준비된 것과 부족한 것을 나눠 보여 주고, 부족한 것은 일정과 준비 계획으로 이어집니다.

### 6. 시스템 구성 (34초)

화면은 Flutter로 만들어 웹과 윈도우 앱으로 배포했습니다. 서버는 FastAPI, 데이터베이스는 PostgreSQL과 pgvector입니다. 졸업 요건은 규칙 엔진이 계산하고, 학사 자료는 BM25로 검색합니다. 채용공고는 고용24와 사람인에서 모으고, 비교와 글쓰기는 Google Vertex AI의 Gemini가 맡습니다.

### 7. 설계 의사결정 (34초)

설계 원칙은 세 가지입니다. 첫째, 졸업 판정은 AI가 아니라 규칙으로 계산하고, 자료가 부족한 칸은 추측하지 않고 확인 필요로 둡니다. 둘째, AI는 내 기록에 있는 사실만 근거로 쓰고, 예정이거나 진행 중인 일은 완료한 것처럼 쓰지 않습니다. 셋째, 개인 기록을 외부 AI로 보내기 전에 무엇을 보내는지 보여 주고 동의를 받습니다.

### 8. 역할 분담 (9초)

프론트엔드와 UX는 홍요아, AI와 데이터는 신우철, 백엔드와 통합은 이어진이 맡았습니다.

### 9. 결과·확장 방향 (18초)

지금은 스테이징 서버에서 웹과 윈도우 앱으로 모든 기능을 쓸 수 있습니다. 다음 단계는 운영 서버로 옮기고, 학교 관리자 화면으로 다른 학과와 학교의 교육과정을 늘려 가는 것입니다.

### 10. 시연 졸업 학점표 (5초)

학점표는 시연에서 실제 화면으로 보여 드리겠습니다.

### 11. 시연 시나리오 (17초)

시연은 백엔드 개발자를 준비하는 4학년 학생 계정으로 합니다. 목표 직무 분석, 내 자료로 공고 찾기, 그 공고에 맞춘 자기소개서까지 실제 AI 호출로 보여 드리겠습니다.

## 시연 시나리오와 대본

시연은 장면 9개, 6분 20초입니다. AI는 모두 그 자리에서 실제로 부릅니다. 공고는 그때그때 모으므로 결과가 매번 조금씩 달라집니다. 대본의 ○는 화면에 나온 값을 읽으면 됩니다. 괄호 안의 예시는 11월 25일 리허설 결과입니다.

### 장면 0. 전환 (3:50, 10초)

**조작:** PPT에서 미리 로그인해 둔 브라우저로 넘깁니다(홈 화면).

**말:** 지금부터 실제 서비스로 시연하겠습니다. 경동대 컴퓨터공학과 4학년, 백엔드 개발자를 준비하는 학생 계정입니다.

### 장면 1. 홈 (4:00, 30초)

**조작:** 화면을 그대로 두고 목표 직무, 다가오는 일정, 이번 주 할 일을 차례로 가리킵니다.

**말:** 로그인하면 홈에서 목표 직무와 이번 주 할 일을 먼저 봅니다. 목표 직무는 소프트웨어 분야의 백엔드로 정해 두었습니다. 다가오는 일정과 인턴 지원 마감은 남은 날짜가 함께 보입니다. 이번 주 할 일은 체크하면 진행률에 바로 반영됩니다.

### 장면 2. 목표 직무 분석 실행 (4:30, 20초)

**조작:**

1. 왼쪽 메뉴 ‘채용공고 분석’ → 위쪽 ‘목표 직무 분석’ 탭
2. ‘분석 실행’
3. ‘목표 직무 분석 외부 전송’ 대화상자를 잠깐 보여 주고 ‘이번만 허용’

**말:** 목표 직무 분석은 고용24와 사람인에서 백엔드 공고를 최대 8건 모아, 공고들이 공통으로 요구하는 조건과 제 기록 전체를 비교합니다. 개인 기록이 외부 AI로 가기 때문에, 실행 전에 무엇을 보내는지 보여 주고 동의를 받습니다.

### 장면 3. AI를 기다리는 동안 학점표 (4:50, 45초)

**조작:** ‘학사’ 메뉴 → ‘졸업 요건’ 탭 → ‘학점표’ 칩

**말:** 분석에 40초쯤 걸려서, 그동안 학사 화면을 보겠습니다. 학교가 등록한 2019학년도 컴퓨터공학과 교육과정과 제 수강 기록 58과목으로 계산한 학점표입니다. 최소 졸업 학점 130학점 중 112학점을 취득해 18학점이 남았고, 이번 학기 수강 중인 20학점을 마치면 132학점이 됩니다. 이 계산은 AI가 아니라 규칙 엔진이 하고, 과목 분류 자료가 없는 칸은 추측하지 않고 확인 필요로 표시합니다.

### 장면 4. 목표 직무 분석 결과 (5:35, 60초)

**조작:**

1. ‘채용공고 분석’ 메뉴로 돌아옵니다. 결과가 이미 나와 있습니다.
2. 맨 위 ‘준비된 요건’ 막대와 요약을 가리킵니다.
3. 빨간 ‘준비 필요’ 카드 하나와 초록 ‘준비됨’ 카드의 ‘내 기록 근거’를 보여 줍니다.
4. 빨간 카드의 준비 제안에서 ‘일정에 추가’ → 달력에 잡힌 목표일 그대로 ‘확인’

**말:** 공고 8건에서 공통 요건 ○개를 뽑았고, 그중 ○개가 준비됐습니다(예: 7/9, 6/10). 초록은 준비됨, 주황은 일부 준비됨, 빨강은 준비 필요입니다. 준비된 요건에는 어떤 기록이 근거인지 붙습니다. 예를 들어 Python 백엔드 요건은 RouteOn 프로젝트의 FastAPI 기록이 근거입니다. 부족한 요건에는 준비 제안과 기간이 붙고, ‘일정에 추가’를 누르면 목표일을 골라 바로 일정에 넣습니다. 이 결과는 합격 판정이 아니라 공고 요건과 기록의 비교입니다.

### 장면 5. 내 자료로 공고 찾기 실행 (6:35, 20초)

**조작:**

1. 위쪽 ‘내 자료로 공고 찾기’ 탭. 직종과 검색어가 목표 직무로 채워져 있습니다.
2. 근무 지역 ‘서울’, ‘경기’ → 현재 학년 ‘졸업예정’
3. 아래로 내려 ‘함께 비교할 내 자료’에서 ‘백엔드 포트폴리오 요약’ 체크
4. ‘분석 실행’

**말:** 이번에는 실제로 지원할 공고를 찾겠습니다. 직종과 검색어는 목표 직무에서 채워지고, 지역과 학년만 고릅니다. 기록에 더해 올려 둔 포트폴리오 PDF도 함께 비교합니다. 공고를 모아 하나씩 비교하느라 1분 남짓 걸립니다.

### 장면 6. AI를 기다리는 동안 자격증 추천 (6:55, 60초)

**조작:**

1. ‘자격’ 메뉴. ‘내 자격’ 탭의 카드 3개를 가리킵니다.
2. 위쪽 ‘자격증 추천’ 탭 → ‘자격증 추천 받기’(약 10초)
3. 추천 카드의 준비 시기와 시험 일정을 가리킵니다.

**말:** 기다리는 동안 자격 메뉴를 보겠습니다. 정보처리기사와 SQLD는 취득했고, 리눅스마스터 2급은 1차 합격 후 2차를 준비 중입니다. 추천을 받으면 이미 가진 자격은 빼고 목표 직무에 맞는 자격을 고릅니다. 준비 중인 자격은 보유로 치지 않습니다. 각 자격에는 언제 준비하면 좋은지와 공식 자료 기준 시험 일정이 붙습니다(예: AWS SAA, 리눅스마스터, 정보보안기사, ADsP).

### 장면 7. 공고 찾기 결과 (7:55, 55초)

**조작:**

1. ‘채용공고 분석’ 메뉴로 돌아옵니다. 결과가 이미 나와 있습니다.
2. 1위 공고 카드의 순위, 판정, 준비 막대, 준비 안내를 가리킵니다.
3. ‘필수 요건 미충족’ 카드가 있으면 나란히 비교합니다.
4. 1위 공고의 ‘자기소개서 쓰기’

**말:** 공고마다 요건을 제 기록과 비교해서, 필수 요건이 확인된 공고를 먼저 보여 줍니다. 1위 공고는 요건 ○개 중 ○개가 준비돼 추천으로 표시됐습니다(예: 3/4). 옆의 ‘필수 요건 미충족’ 공고는 필수 요건이 확인되지 않아 추천에서 뺐습니다. 공고마다 먼저 준비할 항목을 안내하고, 마감은 원 공고 링크로 확인합니다. 이 공고로 바로 자기소개서를 써 보겠습니다.

### 장면 8. 공고에 맞춘 자기소개서 (8:50, 60초)

**조작:**

1. ‘자기소개서·포트폴리오’ 화면이 열립니다. 지원처와 공고 카드(요건 ○개·준비 ○개)가 채워져 있습니다.
2. ‘문항 1’에 문항을 넣고 ‘문항별 글자 수’에 800을 넣습니다.
3. ‘초안 만들기’(약 25초)
4. 문단 아래 ‘근거 ○개 보기’를 하나 펼칩니다.
5. ‘Word로 받기’·‘PDF로 받기’ 버튼 위치만 가리킵니다.

**말(기다리는 동안):** 공고를 고르고 들어오면 지원처와 공고 요건이 함께 연결됩니다. 초안은 제 기록에 있는 사실만 쓰고, 공고가 요구하는 조건에 맞는 경험을 골라 문단을 구성합니다.

**말(결과):** 800자 안에서 동아리 스터디, RouteOn, 졸업작품 경험으로 문단을 만들었습니다. 근거 보기를 누르면 문장이 어떤 기록에서 왔는지 확인할 수 있습니다. 위쪽에는 더 구체적으로 쓰려면 어떤 내용을 기록에 보태야 하는지 묻습니다. 다듬은 뒤에는 Word나 PDF로 받습니다.

### 장면 9. 홈으로 마무리 (9:50, 30초)

**조작:** ‘홈’ 메뉴 → ‘준비도’ 카드를 가리킵니다.

**말:** 홈으로 돌아오면 방금 분석한 준비도와 먼저 준비할 조건이 요약돼 있고, 추가한 준비 계획은 일정에 들어갑니다. 이렇게 기록을 한 번 남기면 졸업 확인, 공고 비교, 지원서 초안까지 이어집니다. 이상으로 시연을 마치겠습니다.

## 시연 계정과 데이터

### 시연 중 직접 고르거나 입력할 값

- 내 자료로 공고 찾기: 직종과 검색어는 목표 직무에서 자동으로 채워집니다(연구 및 공학기술 › 소프트웨어, 백엔드). 근무 지역은 서울·경기, 현재 학년은 졸업예정을 고르고, 함께 비교할 내 자료에서 ‘백엔드 포트폴리오 요약’을 체크합니다.
- 자기소개서 문항: “지원 동기와 지원 직무 관련 경험을 적어 주세요.” 글자 수 800자.

### 데이터 스크립트

스크립트 위치는 [scripts/demo/seed_demo_student.py](../../scripts/demo/seed_demo_student.py)입니다. 계정 정보는 서버 쪽 폴더(`~/.config/unipath-staging-demo-final/`)에서 읽습니다. 학생은 `account.json`, 학교 관리자는 `admin.json`에 있습니다.

```bash
python3 scripts/demo/seed_demo_student.py --reset   # 리허설 흔적을 지우고 처음 상태로 (약 5초)
python3 scripts/demo/seed_demo_student.py --status  # 지금 들어 있는 것만 확인
python3 scripts/demo/seed_demo_student.py --clear   # 시연 뒤 정리
```

`--reset`은 저장된 분석 결과와 자기소개서·포트폴리오 문서를 모두 지웁니다. 리허설 중 추가한 일정·기록도 지운 뒤, 위 표의 스크립트 데이터를 다시 넣습니다. 수강 기록과 원래 있던 자료는 지우지 않습니다. 일정은 실행한 날을 기준으로 만들어집니다. 그래서 시연 당일 아침에 한 번 실행합니다.

시연이 끝나면 `--clear`로 스크립트와 리허설에서 생긴 데이터를 지우고, 목표 직무를 처음 값으로 되돌립니다. 넣기, 리셋, 정리는 확인용 계정에서 미리 시험했습니다.

학교 관리자는 `--reset`과 기본 실행 때 계정이 있는지만 확인하고, 없으면 만듭니다. 승인은 슈퍼관리자만 할 수 있어서, 이 서버의 스테이징 API 컨테이너 안에서 승인과 같은 방식으로 만듭니다. 그러면 경동대학교 관리 권한과 감사 기록이 함께 남고, 부여자는 기존 슈퍼관리자로 기록됩니다. 이미 있는 계정의 비밀번호는 바꾸지 않습니다.

어떤 모드도 계정을 지우지 않습니다. 슈퍼관리자 계정은 만들지도, 바꾸지도, 지우지도 않습니다. 학생 계정 자리에 관리자나 슈퍼관리자 계정이 설정돼 있으면 아무것도 바꾸지 않고 멈춥니다.

## 리허설 측정과 비상 대처

11월 25일 시연 계정으로 잰 AI 응답 시간입니다. 가장 긴 것은 공고 찾기로 약 75초였습니다. 메뉴를 옮겨도 분석이 계속되는 것을 화면에서 확인했습니다.

| 기능 | 응답 시간 | 시연에서 기다리는 방법 |
| --- | --- | --- |
| 내 자료로 공고 찾기 | 74초 | 자격 메뉴로 옮겨 자격증 추천을 보여 줌 |
| 목표 직무 분석 | 38초 | 학사 학점표를 보여 줌 |
| 자기소개서 초안 | 21~25초 | 화면에서 연결된 공고를 설명 |
| 활동 추천 | 13초 | 예비 장면(시간이 남을 때) |
| 자격증 추천 | 10초 | 그 자리에서 기다림 |

### 비상 대처

- **분석이 1분 30초를 넘길 때:** 다른 메뉴 설명을 이어 갑니다. 그래도 안 끝나면 같은 탭의 ‘저장된 결과’에서 당일 리허설 결과를 엽니다. 그리고 “방금과 같은 조건으로 오늘 오전에 돌린 결과입니다”라고 말합니다.
- **오류가 날 때:** 한 번만 다시 실행합니다. 다시 실패하면 저장된 결과로 넘어갑니다. 자기소개서는 ‘저장한 문서’에서 리허설 때 저장한 초안을 엽니다.
- **공고 카드에 ‘분석 미완료’가 보일 때:** 한 번에 비교하는 공고 수에 한도가 있어 일부를 비교하지 못한 것입니다. 역량이 부족하다는 뜻이 아니라고 짧게 말하고 넘어갑니다.
- **공고 찾기에 ‘추천’ 공고가 없을 때:** 필수 요건이 확인된 공고가 없으면 추천 대신 준비 안내만 보여 준다고 설명합니다. 그다음 1위 카드의 ‘자기소개서 쓰기’로 그대로 이어 갑니다. 모든 카드에 쓰기 버튼이 있습니다.
- **로그인 화면에 ‘시도 횟수가 많습니다’가 뜰 때:** 같은 이메일로 15분에 8번까지만 로그인됩니다. 성공한 로그인도 횟수에 들어갑니다. 미리 로그인해 둔 예비 창으로 바꿉니다.
- **인터넷이 끊길 때:** 휴대폰 핫스팟으로 바꿉니다. 바꿔도 안 되면 PPT의 시연 시나리오 슬라이드로 돌아가 흐름만 설명합니다.

## 시연 당일 점검 목록

아침에 데이터를 초기화하고 한 번 리허설합니다. 그 뒤로는 다시 초기화하지 않습니다. 리허설 결과를 비상용으로 남겨 두기 위해서입니다.

- [ ] 아침에 `python3 scripts/demo/seed_demo_student.py --reset`을 실행합니다. 일정 날짜가 그날 기준으로 다시 만들어집니다.
- [ ] 시연 순서대로 한 번 리허설합니다. 분석 결과는 자동 저장되고, 자기소개서 초안은 ‘저장’을 눌러 둡니다.
- [ ] 시연 PC에서 설정 › AI와 데이터를 맞춥니다. ‘목표 직무 분석’만 ‘전송 전 확인’으로 두고, 내 자료로 공고 찾기·자기소개서·포트폴리오 작성·자격증 추천은 켭니다. 동의 대화상자는 한 번만 보여 줍니다.
- [ ] 브라우저는 1920×1080, 확대 100%로 두고 시연 계정으로 로그인한 창을 두 개(하나는 예비) 띄웁니다.
- [ ] 시연 전 15분 동안에는 새로 로그인하지 않습니다. 다른 팀원도 같은 계정을 동시에 쓰지 않습니다.
- [ ] 발표장 와이파이와 휴대폰 핫스팟을 둘 다 준비합니다.
- [ ] 발표 대본의 ○○○에 발표자 이름을 넣습니다.
