# 학교별 교육과정 분류 API 요청

현재 OpenAPI에 없는 계약의 요청이다. 아래 논리 항목은 확정 DTO/경로가 아니며
프런트의 SchoolClassificationDrafts 직렬화를 서버 계약으로 사용하지 않는다.
서버 구현·API 이름·마이그레이션은 백엔드 담당자가 확정한다.

## 필요한 목록과 식별자

학교별 이수구분, 그 하위 세부분류, 필수/선택 구분, 이수 경로를 관리한다.
각 항목에는 서버가 자동 생성하는 안정 ID, 학교 ID, 분류 종류, 표시 이름·설명,
버전과 사용 상태가 필요하다. 세부분류는 같은 학교의 상위 이수구분 ID를 참조한다.
필수/선택은 기본 선택값으로 제공한다. 관리자가 이름을 등록하고 의미를 다시 고르게 하지 않는다.

이름·설명·표 제목·비고는 자유 입력이다. 이름이 같다는 이유로 연결하지 않으며
이름 수정으로 기존 ID 참조가 바뀌지 않아야 한다. 분류 코드 입력을 요구하지 않으며 DB에서도 별도 코드를 필수 조건으로 두지 않는다. 학교 공식 코드가 별도로 필요한 경우에만 선택 메타데이터로 취급한다.

## 현재 계약의 차이

| 기존 API | 현재 필드 | 필요한 확장 |
| --- | --- | --- |
| POST/PATCH `/admin/courses` 및 목록/상세 | name, institution_id, code, credits | 학교 분류 ID 연결과 저장 후 재조회. 학과 소속 요청과 구별 |
| POST/PATCH `/admin/curriculum-courses` 및 목록/상세 | curriculum_id, course_id, category(major/general/other), required | 세부분류·학교 분류·이수 경로 참조와 버전, 과목 기본값과 교육과정별 연결의 우선순위 |
| POST/PATCH `/admin/rules`, `/admin/rule-sets` 및 목록/상세 | 범위와 설명·기간·출처 등 | 학교 분류 ID 연결. 규정 문장·설명에서 분류를 추론하지 않음 |
| 학점표·인증 저장/학생 조회 | 미확정 | 기존 저장 계약 요청에 열/그룹의 분류 ID·필수 여부, 행의 경로 ID 포함 |
| GET `/catalog/courses`, `/catalog/curriculum-courses` 및 관련 학생 기준 조회 | 기존 과목/연결 ID와 category/required | 관리자와 동일한 분류 ID·표시값·필수 여부·기준 버전 반환 |
| POST/PATCH `/me/course-records` 및 재조회 | 제목·course_code·category 등 복사본 | 선택한 원본 course/curriculum-course ID와 기준 버전 보존. 현재 DTO에는 원본 참조나 required 필드가 없음 |

학교 분류 자체의 등록·목록·상세·수정·사용 중지/삭제 API도 필요하다.
경로를 클라이언트가 임의로 만들어 호출하지 않는다.

## 저장·조회·오류·권한

- 관리자는 자신의 활성 학교 범위에서 분류와 연결을 편집하고 학생은 공개된 기준만 읽는다.
  다른 학교 ID 연결과 접근은 거부한다. 슈퍼관리자의 학교별 작업도 같은 소속 검증을 거친다.
- 관리자 수정에는 기준 버전, 충돌/필드 오류, 목록 페이지네이션과 필터 계약을 제공한다.
  분류 목록과 과목/표/요건 연결을 다시 읽어 같은 ID·버전인지 확인할 수 있어야 한다.
- 연결된 분류의 삭제/사용 중지는 참조를 보호한다. 기존 이력과 비활성 기준의 표시·재선택 정책을 구분한다.
- 기존 category 문자열·필수 여부와 새 ID를 이전하는 정책을 명시한다. 표시 이름을 맞춰 자동 병합하지 않는다.
- 학생의 선택은 교육과정-과목 원본 참조에 연결한다. 과목·교육과정에 서로 다른 기본 분류가 있거나
  여러 교육과정에 속한 경우 어떤 기준을 사용할지 서버가 명확히 반환한다. 클라이언트가 마지막 행을 임의 선택하지 않는다.

## 수용 조건

1. 학교 A에 분류를 등록·수정하고 다른 세션에서 같은 ID로 읽는다. 학교 B는 같은 표시 이름을 써도 별도 ID이다.
2. 과목·학점표·요건에 분류 ID를 연결하고 다시 읽어도 같은 연결이다. 이름·설명·표 제목·비고 변경은 연결에 영향을 주지 않는다.
3. 학생이 과목을 고르면 관리자 기준의 이수구분·세부분류·필수 여부·이수 경로가 적용된다. 학생에게 같은 분류를 다시 입력받지 않는다.
4. 학생 수강 저장·재접속 후에도 원본 ID·기준 버전과 분류 연결을 유지한다. 동명 과목은 합쳐지지 않는다.
5. 다른 학교 참조, 삭제된 기준, 유효하지 않은 참조, 오래된 버전, 권한 상실은 확정 오류로 처리하고 실패 입력을 보존할 수 있다.

## 프런트의 현재 경계

관리자 화면은 ID를 가진 분류·연결 초안과 계정/학교별 임시저장만 제공한다. 공식 저장은
연결 전이며 초안을 학생의 확정 기준으로 사용하지 않는다. 기존 메타데이터 API에 새 필드를 보내지 않는다.
학생은 현재 교육과정-과목 API가 주는 category/required를 선택 시 자동 적용한다. 추가 분류와
원본 연결의 영속화는 이 계약 확정 이후 연결한다. 백엔드 코드는 이번 작업에서 수정하지 않았다.

## PR #54 입력 흐름과 필요한 후속 계약

현재 FE는 기존 POST/PATCH `/admin/courses`와 `/admin/curriculum-courses`를 한 과목 폼에서 순차 호출한다. 연결 이름은 과목명으로 초기화하며 사용자에게 별도 연결명 입력을 요구하지 않는다. 연결 저장만 실패하면 같은 폼에서 저장한 과목 ID를 유지해 재시도한다. 서버 원자적 통합 저장·멱등성 계약이 없어 네트워크 응답 유실 뒤 확정 저장 여부를 안전하게 조회하는 계약이 필요하다.

과목의 기본 태그와 교육과정별 변경 태그가 있다면 서버가 실제 적용 기준을 명확히 반환해야 한다. 학교별 분류 등록을 마쳤다고 실제 과목이 생성된 것으로 취급하지 않는다. 분류 관리와 교육과정 과목 소속 관계는 별개이며, 사용자에게 연결을 위해 동일 분류를 다시 입력하게 하지 않는다.
