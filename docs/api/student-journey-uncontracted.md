# 학생 여정 중 계약이 없는 항목

확인일: 2026-10-28. 기준: 이 체크아웃의 `docs/api/openapi.json`.

학생 여정 화면은 [student-journey.feature](../frontend/specs/student-journey.feature)를 따른다.
아래 항목은 OpenAPI에 경로가 없다. 프론트엔드는 화면, 목업 답변, 로컬 판정을 만들지 않는다.
계약이 생기면 이 문서의 입력·응답·오류를 화면 연결 조건으로 사용한다. 이 문서는 합의된 API가 아니다.

담당: 백엔드/AI. 프론트엔드는 계약이 확정된 뒤 입력 전송, 받은 결과 표시, 실패 시 작성 내용 보존만 연결한다.

## 이미 있는 계약

가입·로그인, 학생 조회 목록, 학업 프로필의 선택 `institution_id`·`department_id`·`curriculum_id`,
수강·활동·경험·자격, 개인 교육과정·규칙, `PATCH /planning-profile`, 공식 졸업감사, 이름 기반 학교 질의는
기존 문서와 OpenAPI를 따른다. 이 항목을 아래 미계약 기능으로 다시 만들지 않는다.

목록에 없는 학교를 학생이 공식 학교로 등록하는 API는 만들지 않는다. 개인 교육과정의 학교·학과·입학연도를
설정에 반영하는 동작은 기존 `PATCH /planning-profile`의 이름 필드와 ID null로 충분하다.

## 1. 학사 안내 템플릿

- 현재: `/api/v1`에 학사 안내 템플릿 목록·선택·답변 경로가 없다. 템플릿과 LLM 중 무엇을 쓸지도 확정되지 않았다.
- 프론트엔드가 연결할 때 필요한 입력: 로그인한 학생, 저장한 학교·학과·입학연도·이수 경로, 학생이 고른 안내 항목 또는 질문.
- 필요한 응답: 안내 본문. 근거가 있으면 문서 제목·페이지·원문·출처. 근거가 없으면 그 사실을 상태 값으로 알린다.
- 오류: 기존 `field_errors`와 안전한 `message`, `request_id`. 실패해도 작성한 질문을 지우지 않는다.
- 경계: 응답이 졸업 충족·미충족을 계산하거나 공식 감사 결과를 바꾸지 않는다. 학교 질의 `POST /api/v1/assistant/queries`의 이름 문맥을 템플릿 API로 바꾸지 않는다.

## 2. 취업 질문

- 현재: 학생용 취업·채용 분석 경로가 OpenAPI에 없다. 채용 분석은 별도 후속이며 학사 안내와 같은 API가 아니다.
- 프론트엔드가 연결할 때 필요한 입력: 학생이 확인한 질문 또는 공고 텍스트. 개인 기록은 학생이 고른 항목만 포함한다.
- 필요한 응답: 답변, 근거 또는 근거 부족, 불확실한 부분. 취업 확정·자격 취득·졸업 반영 상태는 포함하지 않는다.
- 오류: 학사 안내와 같은 필드 오류·작성 내용 보존.
- 경계: 정부24·Q-Net 연계, 개인 PDF 업로드, RAG 색인은 이 항목과 별도다.

## 3. 학교 질의의 UUID 문맥과 대화 저장

- 현재 학교 질의는 `institution`·`department` 이름을 받는다. 프로필 ID로 학교 UUID를 추론하지 않는다. UUID 문맥은 별도 합의다.
- `query_id`는 저장·재조회 ID가 아니다. 대화 이력 API가 없다.
- 프론트엔드는 저장한 프로필 이름을 기존 질의 문맥으로만 보낸다. ID 문맥이나 서버 대화 보관 화면은 계약 전에 만들지 않는다.
