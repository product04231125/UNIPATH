# 학생 여정의 기존 계약과 후속 연결

확인일: 2026-11-01. 기준: develop에 통합된 `docs/api/openapi.json`.

학생 여정 화면은 [student-journey.feature](../frontend/specs/student-journey.feature)를 따른다.
기존 계약과 아직 계약이 없는 일반 질의를 구분한다. 연결 전인 기능을 목업 답변이나
로컬 판정으로 대신하지 않는다. 아래 후속 입력·응답 제안은 합의된 새 API가 아니다.

담당: 백엔드/AI. 프론트엔드는 계약이 확정된 뒤 입력 전송, 받은 결과 표시, 실패 시 작성 내용 보존만 연결한다.

## 이미 있는 계약

가입·로그인, 학생 조회 목록, 학업 프로필의 선택 `institution_id`·`department_id`·`curriculum_id`,
수강·활동·경험·자격, 개인 교육과정·규칙, `PATCH /me/planning-profile`, 공식 졸업감사,
이름 기반 학교 질의와 UUID 기반 학교 검색·질의는 기존 문서와 OpenAPI를 따른다.
졸업 감사의 결과 안내와 선택한 개인 자료의 문맥 조립·채용 분석 최소 계약도 구현되어 있다.
이 항목을 아래 미계약 기능으로 다시 만들지 않는다.

목록에 없는 학교를 학생이 공식 학교로 등록하는 API는 만들지 않는다. 개인 교육과정의 학교·학과·입학연도를
설정에 반영하는 동작은 기존 `PATCH /me/planning-profile`의 이름 필드와 ID null을 사용한다.
개인 기준 적용은 기존 이름과 같아도 등록 학교·학과·교육과정 ID를 비운다.

## 1. 학사 안내 템플릿

- 현재: 기존 감사의 결정론적 결과 안내는 `GET /me/graduation-audits/{audit_id}/guidance`로 제공한다.
  [졸업 감사 계약](graduation-audits.md)을 재사용한다. 일반 학사 안내 템플릿의 목록·선택·답변은 후속이다.
- 프론트엔드가 연결할 때 필요한 입력: 로그인한 학생, 저장한 학교·학과·입학연도·이수 경로, 학생이 고른 안내 항목 또는 질문.
- 필요한 응답: 안내 본문. 근거가 있으면 문서 제목·페이지·원문·출처. 근거가 없으면 그 사실을 상태 값으로 알린다.
- 오류: 기존 `field_errors`와 안전한 `message`, `request_id`. 실패해도 작성한 질문을 지우지 않는다.
- 경계: 응답이 졸업 충족·미충족을 계산하거나 공식 감사 결과를 바꾸지 않는다. 학교 질의 `POST /api/v1/assistant/queries`의 이름 문맥을 템플릿 API로 바꾸지 않는다.

## 2. 취업 질문

- 현재: `POST /me/personalization-contexts`와 `POST /me/job-analyses`의
  [선택 자료·공고 원문 최소 계약](job-analysis.md)이 있다. 실제 분석기는 미연결이며
  기록을 선택한 요청에는 `not_configured`를 반환한다. 이 화면 연결과 실제 분석기 구현은 후속이다.
  공고와 분리된 자유 취업 질문의 계약은 아직 없다.
- 프론트엔드가 연결할 때 필요한 입력: 학생이 확인한 질문 또는 공고 텍스트. 개인 기록은 학생이 고른 항목만 포함한다.
- 필요한 응답: 답변, 근거 또는 근거 부족, 불확실한 부분. 취업 확정·자격 취득·졸업 반영 상태는 포함하지 않는다.
- 오류: 학사 안내와 같은 필드 오류·작성 내용 보존.
- 경계: 정부24·Q-Net 연계, 개인 PDF 업로드, RAG 색인은 이 항목과 별도다.

## 3. 학교 질의의 UUID 문맥과 대화 저장

- 기존 `/assistant/queries`는 `institution`·`department` 이름을 받는다.
  별도 `/me/school-searches`, `/me/school-queries`는 등록 UUID와 적용 문맥을 검증한다.
  [학교 지식 계약](school-knowledge.md)을 따른다. 현재 공통 채팅의 이름 기반 전송을
  자동으로 UUID 경로로 바꾸거나 자유 입력 이름으로 UUID를 추론하지 않는다.
- `query_id`는 저장·재조회 ID가 아니다. 대화 이력 API가 없다.
- 프론트엔드는 저장한 프로필 이름을 기존 질의 문맥으로만 보낸다. ID 문맥이나 서버 대화 보관 화면은 계약 전에 만들지 않는다.
