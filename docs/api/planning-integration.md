# 학업 프로필·일정 화면의 서버 연결

실제 일반 계정으로 로그인한 Web·Windows 작업 공간은 `RemotePlanningRepository`를 사용한다.
설정/홈/일정/메인·분리 채팅의 학교 정보가 같은 서버 프로필을 사용하며, 새 작업 공간에서
다시 조회한다. 관리자 화면과 debug 샘플 저장소는 기존 동작을 유지한다.
[수강·활동·경험·자격·성과·개인 교육과정/규칙·포트폴리오](personal-workspace-integration.md)도 별도 서버 저장소와 동의 이전을 연결했다.

## 저장·조회·충돌

- `/me/planning-profile`과 `/me/events`의 기존 DTO/CRUD를 사용한다. 일정은 cursor를 끝까지
  읽고 중복 cursor/ID는 실패로 처리한다. 읽기 실패 뒤 서버 쓰기를 막으며 로컬 저장으로
  바꾸지 않는다. 설정의 `서버 자료 다시 불러오기`로 다른 기기의 변경을 조회한다.
- 폼을 열었을 때의 버전을 PATCH/DELETE에 보낸다. 동시 변경은 409이며 작성 내용은 유지한다.
  프로필의 카탈로그 ID 등 화면 밖 필드는 PATCH에서 생략해 보존한다.
- 일정 생성은 폼을 여는 동안 유지하는 operation ID와 별도의 client UUID를 사용한다.
  응답 불명 시 같은 본문/UUID로 재시도한다. 불명 상태에서 내용을 바꾸면 새 생성 대신
  결과 재조회 안내를 표시한다. 정상 생성 재시도 정보는 실행 중 메모리에 보관한다.
- 일정 입력·표시는 기기 시간대이며 명시적인 UTC 시각으로 전송하고 새 일정의
  `time_zone`은 IANA `UTC`다. 기존 일정의 시간대 메타데이터는 수정 때 보존한다.
  학교 공식 일정·알림·반복 일정이나 공식 학적으로 취급하지 않는다.

## 계정 전환

`AuthApi.forOwner`는 로그인 세대와 사용자 UUID에 묶인 전송 객체다. 로그인/로그아웃/확인된
계정 변경 후 이전 객체의 새 요청과 지연 응답을 거부한다. 본인 자료 요청에 선택 헤더
`X-Unipath-Owner`를 보내며 서버는 인증된 실제 사용자와 비교한다. 다른 탭에서 쿠키가
바뀌어 앱의 다음 신원 확인 전이어도 불일치 요청은 403이다. 이 헤더는 인증 수단이나
다른 사용자를 선택하는 수단이 아니다. 헤더 없는 기존 클라이언트는 기존 계약을 유지한다.
변경 요청의 잠금 후 신원 재확인에도 같은 조건을 적용하며 CORS/OpenAPI에 반영했다.

## 기기 원본 이전

설정의 `기기 학업 정보·일정 이전`에서 자료 범위와 현재 기기 시간대를 확인하고 동의해야
`/me/personal-imports`를 호출한다. 로그인 계정의 namespace만 읽으며 익명/다른 계정 자료는
읽거나 귀속하지 않는다. 기존 서버 프로필은 생략하고, 서버 프로필이 없을 때만 초기화한다.
수강·활동 등 다른 컬렉션은 이 화면에서 이전하지 않는다.

원본에는 손대지 않고 이전 UUID·변환된 요청을 계정별 기기 journal에 먼저 기록한다.
응답 불명·재시작 후 같은 요청으로 재개하므로 중복 생성하지 않는다. 성공 표시는 서버
영수증 확인 후 기록하고, 이후 조회 실패를 이전 실패로 취급해 새 요청을 만들지 않는다.
저장 장치가 journal 쓰기를 거부하면 전송하지 않는다. 완료 뒤 같은 원본을 다시 이전하는
버튼은 숨긴다. 일정 100개 초과나 서버 검증 오류는 원본을 유지하고 안내한다.

원본의 offset 없는 시각은 사용자가 확인한 현재 기기 시간대로 해석한다. 작성 당시와
현재 시간대가 다르면 이전하지 않아야 한다. 임의의 학교 시간대를 추정하거나 Z를 붙이지
않는다. 다른 시간대 선택·100개 초과 분할은 후속이다. 다른 개인 자료 10종은 별도 동의 이전을 제공한다.

## 검증

`remote_planning_test.dart`는 재조회, UTC 변환, 버전 충돌, 응답 불명 재시도, 원본/익명 자료
보존, journal 재개, 계정 전환/지연 응답과 좁은 화면의 동의 모달을 검사한다.
`test/server_planning_http_test.dart`는 독립 합성 API에서 Flutter 전송→FastAPI→
PostgreSQL 저장/재조회/수정/삭제/이전 경로를 확인한다. 실제 서버 URL이나 학생 계정으로
실행하지 않는다. 서버 인증 테스트는 Bearer/쿠키의 계정 불일치 시 무저장을 검증한다.
