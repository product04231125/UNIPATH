# 개인 기록·구성·지원 문서의 서버 화면 연결

실제 일반 계정의 수강·활동·경험·자격·성과·개인 교육과정/과목/규칙과 포트폴리오 구성·지원
문서는 기존 `/me` API를 사용한다. 학업 프로필·일정은 [기존 연결](planning-integration.md)을
계속 사용한다. debug 샘플과 이전 전 기기 원본은 로컬 저장소에 남는다.
학생용 공식 카탈로그·공식 졸업 판정 화면 연결과 구분한다. [개인 계산 화면](personal-calculation-integration.md)은 별도 명시 조건을 사용한다.

## 저장소와 입력

- `PersonalRepositoryScope`는 한 작업 공간의 계정에 묶인 저장소 factory를 제공한다.
  기록 화면·개인 교육과정 선택기·포트폴리오 원본 조회는 같은 서버/계정을 사용한다.
  전역 사용자 변경으로 기존 폼의 저장소를 다시 선택하지 않는다. 종료된 작업 공간의
  대기 작업은 거부하며 전송은 기존 `AuthApi.forOwner`를 사용한다.
- `PersonalRecordCodec`는 UI의 8종 필드와 생성 DTO를 명시적으로 변환한다. 개인 이수 상태,
  필수 여부와 적용 범위는 계약 enum으로 변환하고 모르는 값은 거부한다. 원 성적·학교에서
  확인했다고 사용자가 적은 승인 상태·개인 조건/현재 값은 공식 검증값이나 실행 조건으로
  승격하지 않는다. 알 수 없는 필드를 조용히 버려서 이전하지 않는다.
- Decimal은 wire 문자열을 유지하며 화면에 불필요한 끝자리 0만 제거한다. 계산용 double로
  변환해 저장하지 않는다. 날짜는 날짜 문자열이고 일정의 시각/시간대 변환과 구분한다.
- 목록은 cursor를 끝까지 읽고 중복 cursor/ID는 오류다. 쓰기는 읽기 성공 뒤만 허용하며
  실패 시 기기 저장으로 전환하지 않는다. 명시적 다시 불러오기로 다른 기기의 변경을 읽는다.
- 수정/삭제는 폼이나 확인창에서 확인한 버전을 사용한다. 409이면 내용을 덮어쓰지 않는다.
  생성 폼의 client UUID는 실패 후 재시도에도 유지한다. 같은 UUID의 다른 생성 내용은
  기존 API의 충돌 정책을 따른다. 실패 시 작성 내용과 기존 목록은 유지한다.
- 서버 참조는 서버 UUID다. 포트폴리오 원본은 서버의 본인 성과/경험에서 조회하고 순서를
  보존한다. 다른 자료가 참조하는 기록의 삭제는 409로 거부하며 먼저 연결을 정리해야 한다.
  지원 문서 수정은 화면 밖의 서버 `detail`을 생략해 보존한다. 공개 검토/제출 검토는 사용
  의도이며 서버 저장으로 실제 온라인 게시·공유 권한·제출·AI 생성 기능이 생기지 않는다.

## 기존 기기 자료 이전

설정의 `기기 개인 기록 이전`은 위 10개 컬렉션을 별도 묶음으로 이전한다. 학업 프로필·일정은
이 요청에서 제외하므로 [프로필·일정 이전](planning-integration.md)을 반복하지 않는다.
사용자는 제목별 목록과 전송 범위(메모·작성 본문·날짜·수치·참조 포함)를 확인하고 동의한다.

로그인 계정 UUID의 기기 namespace만 읽고 익명·다른 계정 자료는 자동 귀속하지 않는다.
개인 교육과정→과목/규칙, 원본 성과/경험→구성/문서의 전체 참조를 함께 변환한다. 기존 로컬
UUID는 client UUID로 유지하고 예전 임의 식별자는 검토 요청의 UUID 대응으로 변환한다.
원본이 없거나 알 수 없는 값/필드가 있으면 전체 이전을 거부하며 삭제·자동 추정·부분 전송을
하지 않는다. 이러한 원본은 별도 검토/정리가 필요하다. 종류별 100개·총 500개·2 MiB 한도다.

동의한 요청·대응 UUID를 계정별 `personal_workspace_import.v1` 기기 journal에 먼저 기록한다.
journal 저장 실패 시 전송하지 않으며 응답 불명/재시작 뒤 같은 요청으로 재개한다. 새로
검토한 목록과 이전 요청의 식별자가 다르면 다시 동의를 받아야 한다. journal의 소유자·동의·
범위가 다르거나 프로필/일정이 섞여 있으면 전송하지 않는다. 서버 영수증을 확인한 뒤 완료
표시를 남기고, 열린 기록/초안 화면은 서버 자료를 다시 읽는다. 기기 원본은 지우지 않는다.
이미 저장된 서버 자료를 덮어쓰거나 삭제된 서버 자료를 재생성하지 않으며
[원자적 이전 API](personal-imports.md)의 재시도 계약을 따른다.

## 관리자 계정 전환

실제 관리자 작업 공간도 `AuthApi.forOwner`를 사용한다. 다른 탭에서 쿠키가 다른 관리자 계정으로
바뀌면 기존 화면의 생성·수정·삭제·적용 요청은 `X-Unipath-Owner` 조건으로 거부한다.
이 헤더는 권한을 부여하지 않으며 서버의 현재 역할·학교 범위 검증은 그대로 적용한다.

## 검증

- `personal_record_codec_test.dart`: 8종 전체 필드, 누락 수치, 알 수 없는 상태/필드/참조 처리.
- `personal_workspace_import_test.dart`: 무단 자동 이전 방지, journal 쓰기 실패, 원본/다른 계정
  보존, 끊긴 참조, 오래된 동의, 소유자/범위 위반, 넓은/좁은 동의 모달.
- `remote_personal_ui_test.dart`: 서버 저장소 선택, 넓은/좁은 창·200% 글자에서 버전 충돌 입력
  보존, 같은 서버의 졸업 기준 선택기와 자유 조건의 미실행.
- `server_personal_http_test.dart`: 독립 합성 PostgreSQL에 실제 Flutter HTTP로 8종 CRUD,
  구성/지원 문서 순서·관계·버전, 참조 삭제 거부, 10종 원자적 이전·응답 유실 재개를 검사한다.
  loopback 전용 환경 설정이 없는 일반 테스트에서는 제외한다.
- 관리자 UI 테스트는 실제 작업 공간의 변경 요청에 소유자 헤더가 있는지 확인하고 서버
  인증 테스트는 두 관리자 쿠키 전환 후 403/무저장과 올바른 수행자의 감사 기록을 검증한다.
