# 자격증·발급기관 마스터

모든 경로는 `/api/v1` 아래에 있다. 전역 마스터의 등록은 학생 자격증 보유나 학교 승인을
의미하지 않는다. 실제 기관·자격증을 자동 수집하거나 테스트 자료로 운영 DB에 넣지 않는다.

| 경로 | 기능·권한 |
| --- | --- |
| `/admin/certificate-providers` | 기관 목록/등록. 읽기는 관리자, 쓰기는 슈퍼관리자 |
| `/admin/certificates` | 자격증 목록/등록. 읽기는 관리자, 쓰기는 슈퍼관리자 |
| `/catalog/certificate-providers` | 로그인 사용자가 활성 기관 조회 |
| `/catalog/certificates` | 로그인 사용자가 활성 기관의 활성 자격증 조회 |

각 목록은 `GET`, 단건은 `GET /{id}`다. 관리자 목록은 `status`, `query`, `cursor`,
`limit`(1–100), 자격증 목록은 `provider_id`로 필터한다. 공개 목록에는 활성 자료만 나온다.

등록 `POST`는 `code`, `name`, `official_url`을 받으며 자격증은 `provider_id`도 필요하다.
코드는 기관별로 고유하며 기관 코드는 전역 고유다. 자격증의 발급기관과 코드는 바꾸지 않는다.
`PATCH /{id}`는 `expected_version`, `name`, `official_url`로 표시 정보를 교체한다.
URL은 HTTP(S)이고 사용자정보가 포함될 수 없다. 서버가 해당 URL에 접속하지 않는다.

`POST /{id}/activate`와 `/deactivate`는 `expected_version`을 요구한다. 현재 버전 불일치,
동일 상태 재적용은 409다. 비활성 기관에 자격증을 등록하거나 재활성화할 수 없다.
기관 비활성화 시 하위 자격증은 공개 조회에서 숨겨진다. 하위 자격증 상태 자체를 일괄 변경하지
않으며 기관 재활성화 후 각 자격증 상태에 따라 다시 노출한다. 물리 삭제는 제공하지 않는다.

승인된 [실행 규칙](rule-programs.md)에서 참조하는 자격증/기관은 비활성화할 수 없다.
먼저 연결된 실행본을 회수해야 한다. 과거 메타데이터에 연결된 승인본도 명시적으로 회수한다.
초안·회수 이력의 참조는 FK로 보존한다. 이름·URL 변경은 기존 승인 snapshot을 바꾸지 않는다.

관리자 `GET /{id}/references`는 승인 실행본 참조를 제공한다. 슈퍼관리자는 전체,
학교 관리자는 허용 학교의 ID·이름을 보고 다른 학교는 `protected_reference` 표시 하나만
받는다. 다른 학교의 이름·실행본 ID·개수 및 학생 개인 자료는 제공하지 않는다.

변경은 현재 신원·슈퍼관리자 권한을 transaction lock에서 확인하고 원문 대신 변경 행위와
마스터 ID를 감사 이력에 남긴다. 공통 오류 형식과 현재 DB 권한 검증은 다른 관리자 API와 같다.
