# 구현된 프런트엔드 기준 백엔드 API 요구 명세

확인일: 2026-10-19. 대상: 이 체크아웃의 Flutter Web·Windows 프런트엔드.

이 문서는 백엔드 계약 요청 명세다. **2026-10-18 인증·역할·계정 상태·학교 전체 범위 API를 구현했다.**
정확한 구현/DTO는 [인증 API](authentication.md)와 [OpenAPI](openapi.json)를 따른다.
관리자 학사 CRUD·검토 버전·감사·역할/범위 UI 연결은 [학사 API](academic.md)로 구현했다.
개인 자료 서버 API·학생용 카탈로그·비밀번호 변경과 전송 DTO/adapter도 구현했다. 정확한 계약은
[개인 자료](personal.md), [학생용 카탈로그](student-catalog.md)를 따른다. 기존 개인 화면은 로컬이다.
개인 자료와 명시적 조건의 [개인 계산/불변 이력 API](personal-evaluations.md)도 구현했으며
화면 계산 버튼 연결은 후속이다. 아래 표/요청 중 공식 판정·RAG 승인·하위 범위·미구현 필드는
제안이며 구현 문서가 우선한다.

## 1. 확인한 기존 API와 구현 경계

`docs/api/openapi.json`의 paths와 `backend/app/api/`, `backend/app/main.py`를 대조했다. 이 문서는 저장소의 계약을 기준으로 한다.

| 기존 계약                            | 저장소에서 확인한 용도          | 이번 요청에서 새로 만들 필요             |
| -------------------------------- | --------------------- | ---------------------------- |
| `GET /api/v1/health`             | 프로세스 상태 확인            | 없음                           |
| `GET /api/v1/health/ready`       | 의존성 준비 상태, 실패 시 503   | 없음                           |
| `POST /api/v1/assistant/queries` | 학교 질의, 상태·인용·입력 부족·오류 | 기존 계약 유지, 실제 근거/인증 연결은 별도 보완 |

Swagger는 `/api/v1/docs`, 계약 원본은 `/api/v1/openapi.json`이다. `/health` 호환 별칭은 OpenAPI에 포함하지 않는 인프라 확인 경로다.

- 일반 로그인·회원가입은 실제 계정·세션 API다. 관리자 샘플 진입은 debug 합성 역할이며 서버 권한을 주지 않는다.
- 계정/역할/정지·학교 전체 범위·학교 생성은 실제 API다. 학사 CRUD·검토 버전·감사 UI는 실제 API이며 debug 샘플만 FakeAdminRepository다.
- 학업 프로필·일정·수강·활동·경험·자격·성과·개인 교육과정/규칙·포트폴리오/지원 문서는 기기 로컬 저장이다. 서버 CRUD와 전송 adapter는 구현했으며 화면의 서버 전환·동의/이전/충돌 UI 연결이 필요하다.
- 인증·학교 관리 범위와 AI 학교 질의에 실제 HTTP adapter가 있다. 실행 중 대화/창 간 공유는 클라이언트 메모리·IPC이며 서버 대화 저장 API가 아니다.
- 공식 졸업 판정은 API 미연결 안내/예시 상태다. 개인 입력 수치 합계는 공식 판정이 아니다.

## 2. 기능별 계약 요청과 권장 순서

| 순서  | 프런트 기능             | 필요한 계약                     | 현재 상태/의존성                    |
| --- | ------------------ | -------------------------- | ---------------------------- |
| 1   | 로그인·관리자 진입         | 인증·세션·내 역할/계정 상태/관리 범위     | 서버 계정·세션·역할/학교 범위 구현         |
| 2   | 관리자 학교/학과·교육과정·과목  | 범위 제한 목록/상세·등록·수정·삭제/참조    | 실제 DB/API·관리자 UI 연결 완료         |
| 2   | 졸업요건·공식 문서·관리 이력   | 초안/적용/새 버전·관계·감사·범위 관리     | 공식 데이터 신뢰 기반                 |
| 3   | 설정·홈·일정            | 개인 프로필/일정 저장·재조회·충돌 처리     | 로컬 기능은 현재 독립 동작              |
| 3   | 개인 수강·활동·경험·자격·성과  | 본인 소유 CRUD·검증·출처 구분        | 로컬 CRUD, 공식 기록 아님            |
| 3   | 개인 교육과정/졸업 규칙      | 개인 자료 CRUD·관계/삭제 영향·명시 조건 계산 | 서버 CRUD/개인 계산 구현, 화면 연결 후속 |
| 3   | 포트폴리오 구성·지원 문서     | 초안 CRUD·선택 참조·순서·사용 의도     | 로컬 초안, 공개/제출 아님              |
| 4   | 공식 졸업요건 화면         | 학교 공식 읽기·Rule Engine 판정/근거 | 마스터·공식 수강 매핑·규칙 계약 필요        |
| 별도  | 기존 AI 질의           | 현 계약 유지, 승인 문서/생성기/인증 연계   | API 존재, 실제 생성·운영 승인과 구별      |
| 후속  | 파일 등록·관리자 가입 신청·공유 | 파일 보관/처리·신청 승인·공유 권한       | 메모/방향 단계, 현재 구현 API로 요구하지 않음 |

순서는 프런트 연결 준비 관점의 제안이다. 백엔드/AI 담당의 구현 일정·우선순위 확정은 별도다.

## 3. 신규 API 공통 합의 사항

아래는 모두 **제안**이다. 기존 학교 질의 계약의 필드/enum을 임의로 바꾸지 않는다.

- `/api/v1` 아래 JSON 계약, 서버 발급 불변 ID, 날짜 `YYYY-MM-DD`, 서버 시각 ISO 8601 및 시간대 정책을 명시한다. 클라이언트 로컬 UUID와 서버 ID의 매핑을 제공한다.
- 소유자·역할·승인자·감사 수행자는 세션에서 결정한다. 요청의 `user_id`, 역할 또는 `approved=true`를 믿고 권한을 부여하지 않는다.
- 목록: `query`, 필요한 소속/상태 필터, `cursor`, `limit`; 응답 `items`, `next_cursor`. `total`은 제공 여부를 합의한다. 서버 검색은 권한 필터를 먼저 적용한다. 일부 페이지를 받아 놓고 전체 검색 완료로 표시하지 않도록 adapter를 바꾼다.
- 상세/저장 응답: ID·내용·관계·출처·수정 가능 여부·버전/시각. 읽기 전용 데이터는 서버에서도 변경을 거부한다. `can_edit` 같은 UI 힌트가 API 권한 검증을 대신하지 않는다.
- 생성 201, 조회/수정 200, 삭제 204를 기본 후보로 한다. PATCH의 생략은 유지, 명시적 null은 값 제거로 구분한다. 필드별 null 허용 여부는 모델에서 정의한다.
- 동시 수정은 `version` 또는 ETag/If-Match 방식 중 하나를 확정한다. 충돌 시 최신 버전/안전한 식별자와 재조회 경로를 제공하고 조용히 덮어쓰지 않는다.
- 생성·적용·재시도의 중복 방지를 위해 idempotency 정책/키를 합의한다. 현재 OpenAPI에 없으므로 신규 계약과 CORS 허용/노출 헤더도 함께 정한다.
- 로그인 만료 401, 범위/상태 제한 403, 미존재 또는 정책상 숨긴 대상 404, 참조/중복/버전 충돌 409, 입력 오류 422, 처리 한도 429, 서버 장애 5xx를 구별하는 후보다. 존재 여부를 숨길 403/404 정책도 일관되게 정한다.
- 필드 오류는 기존 공통 형태를 재사용하는 방향이다: `error.code`, 안전한 `message`, `field_errors: [{field, reason}]`, `request_id`. 인증 구현으로 `UNAUTHENTICATED`, `FORBIDDEN`, `CONFLICT`, `RATE_LIMITED`가 추가됐다. 나머지 신규 enum은 OpenAPI 확정이 필요하다.
- 기존 `X-Request-ID`는 UUID로 전달/반환한다. 오류에는 비밀번호·토큰·질문/학생 기록 원문·내부 파일 경로를 넣지 않는다. 프런트는 오류를 해당 입력에 표시하고 실패한 작성 내용을 보존한다.

## 4. 인증·역할·세션

다음 인증 경로는 refresh를 제외하고 구현했다. 상세 정책은 [인증 API](authentication.md), prefix는 `/api/v1`이다.

| 메서드·경로 | 요청 | 필요한 응답/행동 |
| --- | --- | --- |
| `POST /auth/register` | 이름·이메일·비밀번호; 입력 길이/정책 합의 | 생성 계정 또는 확인 대기 상태. 일반 가입으로 관리자 역할을 받지 않음 |
| `POST /auth/login` | 이메일·비밀번호 | 세션 성립 및 사용자 ID/역할/계정 상태. 관리자 범위는 아래 me 조회와 함께 확보 |
| `GET /auth/me` | 인증된 세션 | 사용자 ID/표시 이름/역할/계정 상태/활성 관리 범위/권한 기준 버전 |
| `POST /auth/logout` | 현재 세션 | 서버 세션 무효화. 프런트 로컬 로그아웃만으로 대신하지 않음 |
| `POST /auth/refresh` | 선택한 갱신 방식의 증거 | 갱신 실패/만료 구분. 갱신 방식 채택 시에만 필요한 후보 |

- Web은 HttpOnly 세션 쿠키, Windows는 메모리 Bearer 토큰을 사용한다. Origin 검증·CORS·12시간 절대 만료·현재/전체 세션 로그아웃은 [인증 API](authentication.md)에 구현 정책을 명시했다. 비밀번호 확인은 UI에서만 검사하며 원문을 저장/로그하지 않는다. 자동 갱신과 학교 SSO는 후속이다.
- 구현한 역할은 `user`, `school_admin`, `super_admin`; 계정 상태 후보는 `active`, `suspended`. 현 OpenAPI/DB 계약이며 하위 관리 범위는 후속이다.
- 범위는 학교 필수, `institution/department/curriculum` 수준에 맞는 하위 ID·상태. 학과/교육과정의 학교 소속을 서버가 검증한다. 학교관리자에게 학교 생성·권한 부여·학생 개인 기록 접근을 자동으로 허용하지 않는다.
- 정지/범위 회수/세션 만료 후 다음 API 호출에서 즉시 또는 합의한 최대 지연 안에 차단한다. 오래된 화면/토큰을 믿고 계속 쓰게 하지 않는다.
- 최초 슈퍼관리자는 운영 초기화/신원 검증 계약으로 생성한다. 공개 회원가입에서 슈퍼관리자 선택을 제공하지 않는다.

## 5. 관리자 공식 데이터·범위·이력

### 5.1 자원별 CRUD 후보

아래 컬렉션에 `GET/POST`, 각 `/{id}`에 `GET/PATCH/DELETE`를 제안한다. 모든 경로에 `/api/v1` prefix를 붙이며 학교 생성은 슈퍼관리자만 허용한다. 관리자 사용자/범위는 별도 동작을 따른다.

| 컬렉션 | 현재 화면이 다루는 입력/관계 | 서버 검증/응답 요구 |
| --- | --- | --- |
| `/admin/institutions` | 이름, 국가 코드, 공식 HTTP(S) URL | 허용된 학교만 목록에 포함. 검색+단일 선택. ID·이름·읽기/쓰기 가능 범위 |
| `/admin/departments` | 이름, 학교 ID, 코드 | 학교 소속·코드 중복 정책, 범위 제한 |
| `/admin/curricula` | 이름, 학과 ID, 적용 연도 | 학과→학교 소속 일치, 연도/중복 정책 |
| `/admin/courses` | 이름, 학교 ID, 코드, 학점 | 유효 학점·같은 학교 코드·공식 마스터 출처 |
| `/admin/curriculum-courses` | 교육과정/과목 ID, 이수구분, 필수 여부 | 서로 같은 학교, 연결 중복·소속 관계·이수구분 정의 |
| `/admin/rule-sets` | 이름, 학교/학과/교육과정, 적용 기간 | 계층 일치·초안/적용·버전·기간 |
| `/admin/rules` | 이름, 규칙 묶음, 규칙 종류/정의 | 서버 규칙 타입/검증 가능한 조건 스키마를 확정. UI 문자열 정의를 곧바로 실행식으로 사용하지 않음 |
| `/admin/documents` | 이름, 출처 URL, 문서 종류, 범위, 규칙/묶음 연결, 기간 | 관계 일치·HTTP(S)·버전·초안/적용. 현재 UI는 파일 업로드가 아닌 문서 메타데이터/원문 링크 |

필드 원본은 [`admin_fields.dart`](../../frontend/lib/features/admin/admin_fields.dart)다. `Map<String,String>`은 합성 입력 모델이며 전송 DTO가 아니다. 숫자·boolean·날짜·관계 ID의 타입과 필수/null/길이를 Pydantic/OpenAPI로 합의한다.

`GET /admin/institutions?query=...`는 서버에서도 현재 계정의 허용 학교만 반환한다. 학교 전환 자체는 클라이언트의 현재 관리 대상 선택이고 권한 부여가 아니다. 이후 모든 학과/과목/문서 요청에서 선택 ID의 권한을 다시 검증한다. 검색 결과가 없어도 현재 학교를 임의 변경하지 않는다.

### 5.2 적용·새 버전·삭제 영향 후보

| 동작 | 제안 경로 | 요청/응답 및 불변 조건 |
| --- | --- | --- |
| 묶음 적용 | `POST /admin/rule-sets/{id}/apply` | 예상 버전·명시적 검토 의사. 묶음/하위 규칙을 원자적으로 적용, 적용자·시각·버전 반환 |
| 문서 적용 | `POST /admin/documents/{id}/apply` | 예상 버전·검토 의사. 권한·관계·출처/기간 검증 후 적용 |
| 새 초안 | `POST /admin/rule-sets/{id}/drafts`, `POST /admin/documents/{id}/drafts` | 적용본을 변경하지 않고 lineage에 속한 새 ID/버전/초안 생성 |
| 규칙 적용 단위 | 미확정 | 현재 화면/목업은 묶음 소속 규칙과 독립 규칙을 구분한다. 독립 규칙 허용 여부와 필요 시 `/admin/rules/{id}/apply`, `/{id}/drafts` 계약을 합의 |
| 삭제 영향 | `GET /admin/{resource}/{id}/references` | resource 허용 목록·권한 검증. 접근 가능한 참조의 종류/이름/ID 또는 안전한 요약만 반환 |

- `draft/applied`는 현재 설계 후보다. 적용된 내용의 직접 수정/삭제 금지, 새 초안 생성, 기존 적용 이력 보존을 서버 트랜잭션으로 보장한다.
- 삭제 영향 조회 후 참조가 생길 수 있으므로 DELETE 시에도 재검증한다. 참조 삭제를 자동 연쇄 처리하지 않고 409와 안전한 이유를 제공하는 방향이다.
- 문서 적용 상태와 RAG의 승인 근거 자격은 별도 계약이다. UI에서 적용했다고 파일/페이지를 자동 승인된 RAG 근거로 간주하지 않는다. 문서 버전·적용 기간·학교/교육과정·승인 상태 연결은 백엔드/AI 담당이 합의한다.

### 5.3 슈퍼관리자 운영 계약 후보

| 메서드·경로 | 요청 | 응답/조건 |
| --- | --- | --- |
| `GET /admin/users` | 검색/페이지 | 기존 계정의 최소 식별/역할/상태. 학생 개인 기록 원문을 포함하지 않음 |
| `PATCH /admin/users/{id}/status` | 활성/정지 상태, 사유, 예상 버전 | 변경 계정 상태·감사 식별자. 슈퍼관리자만 허용 |
| `GET/POST /admin/scopes` | 사용자/학교/하위 범위 필터 또는 부여 요청·사유 | 활성/회수 상태·부여자/시각/사유, 동일 활성 범위 중복 거부 |
| `PATCH /admin/scopes/{id}` | 범위 변경, 사유, 예상 버전 | 소속·중복·현재 계정 검증 |

| `GET /admin/audit-logs` | 학교/대상/수행자/기간/결과·페이지 | 수행자·행동·대상·학교 범위·결과·시각·request ID |

범위 부여와 `school_admin` 역할 변경의 원자성, 마지막 범위 회수 뒤 역할 처리, 마지막 슈퍼관리자 정지 제한, 자기 계정 관리 제한은 운영 정책으로 확정한다. 현재 UI의 기존 합성 사용자 범위 부여는 실제 계정 발급/초대를 의미하지 않는다.

감사 로그는 서버에서 생성하고 일반 수정/삭제 API를 제공하지 않는다. 학교관리자는 허용 학교/세부 범위 안의 안전한 메타데이터만 읽는다. 비밀번호·토큰·학생 개인 기록 원문·대화 원문을 감사 로그에 남기지 않는다.

## 6. 학생 개인 프로필·일정·기록의 서버 저장 계약

### 6.1 프로필/일정 후보

| 경로·메서드 | 입력 후보 | 필요한 응답/검증 |
| --- | --- | --- |
| `GET/PATCH /me/planning-profile` | 학교/학과 표시명, 입학연도, 이수경로, 개인 계획 학년 override, 주 시작 요일 | 저장된 값/버전. 본인 소유. 공식 학적과 별도 |
| `GET/POST /me/events`, `GET/PATCH/DELETE /me/events/{id}` | 제목, 시작/종료, 분류, 메모 | 기간 조회, 저장된 일정/버전. 종료>시작. 시간대·현지 날짜 경계 계약 필요 |

- 현재 프로필은 자유 입력 이름이다. 공식 `institution_id/department_id/curriculum_id` 연결은 명시적 선택/검증/마이그레이션 후 제공한다. 문자열이 같다는 이유로 학교 FK/공식 학적으로 자동 승격하지 않는다.
- 프로필 입학연도 UI는 1900~현재 연도+1, 기존 AI API는 JSON 정수 1000~9999를 받는다. 새 프로필 계약의 범위를 합의하되 기존 AI 계약을 이 문서만으로 변경하지 않는다.
- 요일은 현재 로컬 `sunday`~`saturday`, 일정 분류는 `academic/personal/activity/deadline`이다. 서버 enum/unknown 처리와 매핑을 확정한다. 현재 로컬 `DateTime` 문자열을 UTC 값으로 자동 해석하지 않는다.
- 프로필 수정과 일정 수정을 분리해 한쪽 저장으로 다른 쪽 자료를 덮어쓰지 않는다. 홈은 이 자료로 현재 목록/카운트를 만들 수 있으므로 별도 `/dashboard` API를 필수로 만들 필요는 없다.
- 채팅 열기 방식, 개발 팔레트/배치 시안, 창 너비/위치, 사이드바 토글은 기기 UI 상태다. 현재 요구에 서버 설정 API는 필요하지 않다.

### 6.2 개인 기록 컬렉션 후보

각 컬렉션에 `GET/POST`, 각 `/{id}`에 `GET/PATCH/DELETE`를 제안한다. 공통 제목/메모·owner·버전·생성/수정 시각을 포함하며 owner는 서버가 세션으로 결정한다.

| 컬렉션 | 현재 UI 입력 의미 | 공식 데이터와의 경계 |
| --- | --- | --- |
| `/me/course-records` | 학기, 이수구분, 학점, 분반/코드, 원 성적, 계획/수강/개인 이수 상태 | 개인 수강 메모. 공식 성적·확정 이수학점 아님 |
| `/me/activity-records` | 기관/기간/역할, 직접 입력 시간, 사용자가 확인한 승인 시간/상태/확인일 | 사용자가 관찰한 학교 상태이며 서버 승인 행위 아님 |
| `/me/experience-records` | 종류/기관/기간/역할/결과·기여/진행 상태 | 역량 자동 판정/Skill 연결 아님 |
| `/me/credential-records` | 기관/점수·등급/취득·만료/상태/증빙 URL | 자격 번호 수집 없음, 취득 진위/기관 검증 아님 |
| `/me/achievement-records` | 성과 종류/기간/역할/결과/링크, 논문 유형/개인 상태/원 성적/직접 확인한 승인일 | 학교 ThesisRecord 승인/성적 환산 아님 |

현재 키/필수값/선택값은 [`personal_record_fields.dart`](../../frontend/lib/features/records/personal_record_fields.dart)로 대조한다. 영문 로컬 키·한글 선택값·모든 값 문자열을 그대로 서버 DTO로 고정하지 않는다. 각 자원의 타입/검증/필수/null/길이를 확정한 모델로 매핑한다.

서버에서도 음수·비유한 숫자·0학점·잘못된 날짜/역전 기간·로그인 정보가 포함된 URL을 거부하는 계약이 필요하다. 봉사 승인 시간은 관찰 상태/확인일과 함께 검증한다. fixture를 생성 요청·집계·마이그레이션에 포함하지 않는다. 관리자 권한은 이 개인 기록 읽기 권한을 자동으로 주지 않는다.

### 6.3 개인 교육과정·규칙 후보

컬렉션은 `/me/personal-curricula`, `/me/personal-curriculum-courses`, `/me/personal-graduation-rules`; 동일한 목록/상세/생성/수정/삭제 동작을 제안한다.

- 교육과정: 제목/메모, 개인 학교·학과명, 입학/교육과정 연도, 출처 링크.
- 과목: 개인 교육과정 ID, 개인 과목 코드·이수구분·학점·필수 여부, 선택적 개인 수강 기록 ID.
- 규칙: 교육과정 ID, 선택적 연결 과목/개인 기록, 종류·범위·필요 값/직접 확인한 현재 값/단위·조건·기간·출처.
- 모든 관계는 같은 owner와 같은 개인 교육과정인지 검증한다. 삭제된 참조의 표시/차단/해제 방식을 합의하며 원본을 연쇄 삭제하지 않는다.
- 자유 입력 조건은 규칙 실행식이 아니다. CRUD 저장 API와 개인 Rule Engine 계산 API를 분리한다. 실제 계산을 제공할 때 타입·연산·성적/중복 기록 처리 계약을 별도로 확정한다.

### 6.4 포트폴리오 구성·지원 문서 후보

| 컬렉션 | 현재 입력/동작 | 보존 조건 |
| --- | --- | --- |
| `/me/portfolio-compositions` | 이름/소개, 선택한 성과의 순서 배열, 사용 의도, 검토 체크 | 순서 저장은 원자적. 구성 삭제/제외가 원 성과를 삭제하지 않음 |
| `/me/application-documents` | 이름/지원처/직무/문서 종류/본문, 참조 경험·성과 | 빈 본문 초안 허용. 원본 기록 변경으로 작성 본문을 자동 덮어쓰지 않음 |

각 컬렉션의 목록/상세/생성/수정/삭제를 제공하는 후보다. 참조는 `{kind, record_id}` 같은 구조로 같은 owner를 검증한다. 프런트의 `kind/id` 문자열과 로컬 UUID는 서버 FK로 간주하지 않는다.

`private/application/publicReview`는 현재 로컬 사용 의도다. 실제 공개/공유/제출 권한 enum으로 재사용하지 않는다. 검토 체크는 내용·선택·순서 변경 때 다시 확인하는 UI 기록이며 저작권/개인정보/학교 승인 인증이 아니다. 실제 게시/공유는 별도 계약이다.

## 7. 공식 읽기·졸업 판정·AI의 분리

### 공식 읽기와 판정 요청 후보

- `GET /catalog/institutions`, `/catalog/departments`, `/catalog/curricula`, `/catalog/curriculum-courses`, `/catalog/rule-sets`, `/catalog/documents`: 학생에게 공개/허용된 적용본만 읽기. 학교·학과·입학연도·교육과정/이수경로·기준일로 적용 버전을 찾는 계약을 확정한다. 관리자 초안을 학생에게 노출하지 않는다.
- 공식 성적/봉사/자격/논문 기록의 연동·매핑은 학교 시스템 계약이 필요하다. 현재 개인 CRUD 값으로 공식 이수 자료를 만들어내지 않는다. 읽기 전용 공식 기록과 개인 보조 기록은 출처/검증 상태로 구분한다.
- `POST /graduation-audits`, `GET /graduation-audits/{id}` 후보: 판정 대상과 합의한 기록 snapshot/교육과정/규칙 버전/기준일을 사용한다. owner는 세션으로 결정한다. 동기 결과인지 202 비동기 job인지 먼저 합의한다.
- 필요한 판정 응답: 개인/공식 구분, overall 상태, 요건별 상태/필요 값/현재 값/단위, 인정된 기록 참조, 미충족/자료 부족 이유, 규칙·문서 버전/근거, 판정 시각. 구체적인 enum/계산/반올림·중복 인정·선택 조건은 Rule Engine 팀 계약이다. 자료 부족을 충족/미충족으로 임의 환산하지 않는다.
- 졸업 가능 여부를 LLM 문자열로 대신하지 않는다. AI는 받은 판정/승인된 검색 근거를 설명한다.

### 기존 학교 질의 유지

기존 요청은 `question`, 선택적 `context.institution/department/admission_year/track`이다. 응답은 `query_id`, `status`, `reason`, `answer`, `citations`, `missing_fields`이며 `grounded/insufficient_evidence/needs_user_input/failed`를 구분한다. 정확한 길이·enum·인용은 [현재 계약](assistant.md) 및 OpenAPI를 따른다.

- `query_id`는 현재 저장/재조회 가능한 대화 ID가 아니다. 인증·공식 학교 ID를 추가할 때 기존 이름 기반 문맥과의 호환/검증을 명시한다. 프로필 이름만으로 승인 DB의 범위를 추론하지 않는다.
- 실제 `grounded` 답변은 승인 근거·생성기·인용 검증 연결이 필요하다. API 라우트가 있다는 이유로 운영 RAG/LLM 생성이 완료됐다고 표시하지 않는다.
- 서버 대화 이력이 제품 요구로 확정되면 대화/메시지 목록·생성·재조회·삭제/보존 계약을 별도 정의한다. 현재 실행 중 창간 공유에는 새 서버 API가 필수는 아니다. 개인정보·보존 기간·삭제 범위 확정이 선행한다.

## 8. 현재 구현 밖의 후속 계약

현재 화면과 섞지 않고 후속으로 분류한다.

- 파일 중심 포트폴리오/증빙: 업로드 시작·전송·완료, 파일 ID/종류/크기/보관 상태, 권한 있는 다운로드, 연결/참조 삭제 정책. URL을 등록했다고 업로드했다고 표시하지 않는다. Web/Windows 로컬 경로를 서버 경로로 보내지 않는다.
- PDF/CSV 처리: 백엔드/AI의 추출·검증/색인 job 상태·결과/오류 계약, 규칙/교육과정 연결. 업로드와 공식 문서 승인·RAG 사용 가능 상태를 분리한다.
- 학교관리자 가입 신청: 신원/학교 담당 확인 수단·요청 필드·승인 주체·대기/반려/재신청·역할/범위 부여. 현재 가입 신청 화면 자체는 미구현이고 신청만으로 권한을 부여하지 않는다.
- 실제 포트폴리오 게시/공유·문서 제출·서버 백업/복원·알림·계정 보안/정보 변경은 별도 제품 정책/계약이다.
- 1365·Q-Net·개인 증빙 URL 열기/복사는 현재 외부 링크 동작이다. 외부 로그인/자동 수집/기관 API를 현재 화면의 필수 백엔드 요구로 추가하지 않는다.
- 공개 홈페이지·Windows 제목표시줄·색/배치/호버·도킹 폭/창 배치는 프런트 작업이며 새 도메인 API를 요구하지 않는다.

## 9. 서버 전환과 인수 조건

- 기존 기기 로컬 자료의 전송 동의/owner 매핑·중복/충돌·로컬 UUID→서버 ID·관계/순서 보존·삭제 이력을 확정한다. fixture와 합성 관리자 데이터는 업로드하지 않는다.
- 프런트는 계약 확정 뒤 repository/adapter를 교체하고 미저장 입력·실패 재시도·만료/범위 회수 상태를 연결한다. 서버 저장 완료 전 UI 목록/프로필을 성공 상태로 갱신하지 않는다.
- 백엔드 납품 단위: Pydantic 요청/응답/오류 모델, 생성된 OpenAPI와 저장소 사본, 권한/소속/버전/원자성 테스트, 비밀값 없는 예제, 재현 가능한 로컬 서버/seed, 필요한 CORS/헤더와 마이그레이션 안내.
- 연결 인수: 정상/빈 결과/422 필드 오류/401 만료/403 범위 밖/404/409 충돌·참조/429/5xx·시간 초과·중복 재시도, 역할별 직접 ID 접근, 정지/회수 후 차단, 적용본 불변/새 초안 이력, 사용자 간 개인 기록 격리, 개인/공식 출처 경계를 API와 UI 양쪽에서 검사한다.
- 담당 확인 목록: 인증 방식, 역할/범위/신원 검증, typed DTO/enum, 학교 FK 매핑, 적용/승인/RAG 연결, 개인/공식 판정, 동기화/파일/삭제 정책. 합의 전에는 이 제안 경로를 실제 API처럼 호출하지 않는다.

## 부록: 합의용 응답 예시

아래는 모두 합성 **신규 제안 예시**다. 정확한 필드 이름과 DTO는 OpenAPI 확정 전이며 현재 서버가 반환하는 payload가 아니다.

`GET /api/v1/auth/me` 후보:

```json
{
  "user": {
    "id": "00000000-0000-4000-8000-000000000001",
    "display_name": "합성 담당자",
    "role": "school_admin",
    "account_status": "active"
  },
  "admin_scopes": [{
    "id": "00000000-0000-4000-8000-000000000002",
    "scope_type": "department",
    "institution_id": "00000000-0000-4000-8000-000000000010",
    "department_id": "00000000-0000-4000-8000-000000000020",
    "curriculum_id": null,
    "status": "active"
  }],
  "permission_version": "scope-revision-1"
}
```

`GET /api/v1/admin/institutions?query=합성` 후보는 현재 세션에 허용된 학교만 반환한다. 여러 항목을 받더라도 클라이언트 관리 대상은 하나다:

```json
{
  "items": [{
    "id": "00000000-0000-4000-8000-000000000010",
    "name": "합성 대학 A"
  }],
  "next_cursor": null
}
```

버전 필드 방식을 채택한 수정 충돌 응답 후보. 아래 `VERSION_CONFLICT`는 현재 서버 `ErrorCode`에 없는 **추가 합의 대상**이다:

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "다른 변경이 저장되었습니다. 최신 내용을 확인해 주세요.",
    "field_errors": [],
    "request_id": "00000000-0000-4000-8000-000000000099"
  }
}
```

일반 422 입력 오류는 같은 envelope의 `field_errors`에 OpenAPI 필드 경로와 수정 가능한 이유를 반환한다. 충돌 후 프런트는 작성 내용을 유지하고 최신 상세를 재조회한다. 서버가 자동으로 사용자 입력을 병합하거나 기존 적용 버전을 덮어쓰지 않는다.
