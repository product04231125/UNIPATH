# 개인 기준 계산 화면 연결

실제 일반 계정의 졸업 요건 → 내 학교·학과 기준 설정 → `개인 기준 계산·이력`은
[개인 계산 API](personal-evaluations.md)를 사용한다. debug/로컬 자료에 계산 버튼을
추가하지 않으며 기기 자료를 자동 업로드하지 않는다. 결과에는 항상
`개인 기준 계산 · 학교 공식 판정 아님`을 표시한다. 공식 학적·졸업감사·RAG/LLM과 별도다.

## 조건과 자료

교육과정을 선택하면 본인 서버의 과정·규칙·과목과 수강·활동·자격·성과를 cursor 끝까지 읽는다.
읽기 실패·중복 ID/cursor는 계산을 막으며 기기 자료로 대체하지 않는다. 초기 기준일은 UTC 오늘이고
직접 날짜를 지정한다. 서버는 해당 날짜에 활성인 모든 규칙을 계산하며 시작·종료일을 포함한다.
각 규칙의 초기 조건은 미지정이다. 종류 이름·자유 조건·필요/현재 값·문자 성적·상태 문구를
추정 실행하지 않는다. 미지정 활성 규칙도 확인 필요로 결과에 남는다.

- 최소 학점: 기준과 선택 분류, 불러온 연결 수강 전체 또는 직접 선택 목록을 명시한다.
  전체 선택도 읽은 수강 UUID 목록으로 고정한다. 빈 선택은 빈 목록이며 전체 기록이 아니다.
- 필수 과목: 교육과정 과목별 최소 학점·점수/비교 척도, 연결 수강의 점수/척도를 직접 입력한다.
  문자 성적을 숫자로 환산하지 않는다. 점수와 척도는 쌍이며 같은 수강의 상충 관찰은 거부한다.
- 봉사: 선택 활동의 직접 입력한 승인 시간·상태·관찰일을 서버가 해석한다. 보고 시간을 합산하지 않는다.
- 자격: 선택 자격의 보유·유효 여부를 직접 확인한다. 초기 관찰은 미확인/false다.
- 논문·작품: 유형·승인 필요 여부·허용 문자 성적과 선택 성과의 완료/승인 관찰을 입력한다.
  유형 없는 성과는 선택하지 못하며, 상태 문구를 관찰 값으로 자동 승격하지 않는다.

수치는 double 변환 없이 문자열로 유지하고 0~1,000,000·소수 여섯 자리와 날짜를 검사한다.
선택 개수·상충 관찰 등 최종 계약 검증은 서버가 수행하며 422에서 입력을 보존한다.
화면에서 읽은 교육과정·활성 규칙과 선택해 사용하는 과목·기록의 버전을 요청에 고정한다.
선택하지 않는 수강 연결은 봉사 등 다른 조건의 계산을 막지 않는다.

## 요청·이력 수명

현재 작업 공간의 `PersonalCalculationController`는 처음 전송한 요청과 client UUID를 보관한다.
응답 유실·충돌 뒤 같은 요청으로 재시도하며 전송 후 편집/교육과정 재선택을 막는다.
이력 확인 후 `새 계산 준비`를 확인하면 별도 요청을 작성할 수 있고, 자료 다시 읽기도
기존 조건을 비우기 전에 확인한다. 기존 원본/저장 결과는 삭제하지 않는다.
계산 초안은 작업 공간의 메모리에 있어 메뉴 이동 후 유지되지만 앱 종료/로그아웃 후에는
남지 않는다. 재시작 후 응답이 불명확했다면 서버 이력을 먼저 확인해야 한다.

계정 UUID·로그인 세대에 묶인 공통 전송과 X-Unipath-Owner를 그대로 사용한다.
종료한 작업 공간의 새 전송은 차단하며 다른 계정으로 조건을 재사용하지 않는다.

이력은 서버 순서로 20개씩 읽고 더 보기/재조회를 제공한다. 중복 ID/cursor는 오류이며
이전 목록을 보존한다. 상세는 저장 당시 제목·조건·기준일·요건 결과·자료 ID/버전이다.
현재 제목으로 역사적 식별자를 덮어쓰지 않는다. 원본 과정 삭제 후에도 이력을 조회한다.
결과 삭제는 확인한 버전으로 수행하고 성공 뒤만 목록에서 제거하며 원본 기록은 보존한다.

## 검증 범위

`personal_calculation_test.dart`는 다섯 조건, 비추정 입력, 버전 고정, 활성 기간 경계,
응답 유실 재시도, 읽기/버전/소유자 오류, 이력 삭제·페이지 반복과 1440×900/480×520·
200% 글자 확대를 검증한다. 별도 loopback 합성 PostgreSQL HTTP 검증과 Web Release
브라우저 확인을 추가로 수행한다. 실제 Windows DPI·접근성 수동 검증은 별도다.
