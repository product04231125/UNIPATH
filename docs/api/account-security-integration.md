# 계정 보안 화면 연결

실제 학생·학교관리자·슈퍼관리자는 공통 제목표시줄의 `계정 보안`을 사용한다.
기존 관리 범위 전용 fallback 화면에만 연결하지 않는다. 일반 작업 공간·관리자 작업 공간을
그대로 유지한 채 공통 InputDialog를 열며 샘플/미로그인에는 진입점을 표시하지 않는다.
[기존 인증 API](authentication.md)의 비밀번호 변경·모든 세션 종료·본인 세션 확인을 사용한다.
서버 API·DB·새 인증 공급자 변경은 없다. 이메일 확인/비밀번호 찾기·학교 SSO와 구분한다.

## 입력과 종료

현재 비밀번호 1~128자, 새 비밀번호 15~128자와 재입력 일치를 검사한다. 길이는 Unicode
코드 포인트 기준이며 공백·원문을 자르거나 정규화하지 않는다. 같은 새 비밀번호를 거부한다.
세 필드는 기본 마스킹·명시적 표시/숨기기이며 자동 교정·추천 입력을 사용하지 않는다.
비밀번호 공백도 의미 있는 작성 내용이다. 공통 입력 보호에 따라 작성 후 바깥 클릭은 닫지
않고 명시적 닫기는 폐기를 확인한다. 저장 중 중복 전송/닫기를 막고 422/429는 입력을 보존한다.
종료/취소 후 메모리의 컨트롤러·대기 비밀번호 참조를 비우며 앱의 영속 저장·로그를 사용하지 않는다.

비밀번호 변경 성공과 모든 기기 로그아웃 성공은 현재 세션도 종료한다. 저장된 원본 자료는
유지하나 저장하지 않은 작업은 사라질 수 있음을 미리 안내한다. 전체 로그아웃은 별도 확인하고
비밀번호 변경 요청을 보내지 않는다. 204만 알려진 성공으로 표시하며 로그인 화면으로 이동한다.
성공 뒤 현재 계정의 메모리 토큰/세대를 폐기하고 오래된 전송 객체를 무효화한다.

## 응답 불명확·계정 전환

응답 유실/서버 오류는 성공으로 추정하지 않는다. 처음 전송한 작업 종류·비밀번호를 작업 공간의
메모리에 고정하고 추가 변경 요청을 막는다. `로그인 상태 확인`은 같은 계정의 GET만 전송한다.
세션이 유효하더라도 앞선 요청이 실행되지 않았다고 단정하지 않는다. 사용자가 명시적으로
같은 요청을 재시도하거나 닫은 뒤 로그인하여 확인한다. 원래 요청이 아직 처리 중일 수 있다.
앱 종료 뒤 자동 재개하지 않으며 이전 요청의 서버 처리를 취소한다고 표시하지 않는다.

401 또는 세션 확인의 expired는 현재 세션 종료만 증명한다. 비밀번호 변경/전체 기기 종료가
완료되었다는 메시지를 만들지 않는다. 서버의 요청별 한도·현재 비밀번호 재검증은 그대로 적용한다.

모든 작업/세션 확인에 소유자 헤더를 보내며 생성 당시 사용자 UUID·로그인 세대를 유지한다.
요청 전에 다른 탭의 쿠키가 바뀌면 서버가 403으로 거부한다. 오래된 응답은 클라이언트가 이미 관찰한 새 로그인/같은 계정의 새
세대 토큰을 지우지 않는다. 변경된 계정은 이전 폼을 정리하고 현재 신원을 다시 확인하며
새 계정을 로그아웃시키는 추가 POST를 보내지 않는다. 정기 신원 확인은 계속 유지한다.
정기 확인이 먼저 만료를 발견하거나 관리자 권한 버전 갱신으로 이전 페이지·모달이 교체되어도
확인된 세션 종료는 해당 계정의 로그인 전환과 안내로 반영한다. 모달의 이전 context가
살아 있어야 한다고 가정하지 않으며, 더 새 계정/로그인 세대에는 완료 안내를 덮어쓰지 않는다.

## 검증

`account_security_test.dart`는 원문 보존/길이/재입력, 세 역할의 실제 탐색, 미확정 응답의
수동 확인·동일 작업 재시도, 다른 계정/같은 계정 새 세대의 늦은 응답, 정기 만료/권한 버전 갱신과 204 경쟁,
전체 로그아웃 확인, 1440×900/480×520·200% 글자 확대와 마스킹을 검사한다.
`server_account_security_http_test.dart`는 독립 합성 loopback API가 지정된 경우만 실행한다.
실제 운영자·학생의 비밀번호/세션은 이 검증에 사용하지 않는다.
