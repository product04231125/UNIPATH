# 결정론적인 졸업요건 판정 코어

`backend/app/rules/`는 DB·HTTP·LLM과 독립적인 계산 모듈이다. 인증 방식이나 임베딩
공급자 없이 단위 테스트와 로컬 실행이 가능하다. 개인 기록 DB는
[개인 계산 API](api/personal-evaluations.md)로 연결했다. [공식 실행 규칙 API](api/rule-programs.md)는
승인 실행본의 등록·선택과 내부 코어 어댑터를 제공한다. 학교 확정 기록 어댑터·공식 졸업감사
API는 후속이며 학교 질의 API의 `rule_engine_required` 안내도 유지한다.

## 구현 범위

| `kind` | 계산 | 필요한 정보 |
|---|---|---|
| `minimum_credits` | 완료한 과목의 학점 합계, 선택적으로 분류별 합계 | 이수 상태·취득 학점·과목 ID, 분류별 규칙이면 분류 |
| `required_courses` | 모든 필수과목과 선택적인 최소 학점·성적 | 과목 ID·완료 상태, 성적 조건이면 점수와 동일한 척도 |
| `minimum_volunteer_hours` | 승인된 봉사 시간 합계 | 승인 상태와 승인 시간 |
| `any_certificate` | 명시한 자격증 중 유효한 하나 | 자격증 ID·확인 상태·유효성 확인·만료일 |
| `thesis` | 논문/캡스톤 종류별 완료, 필요 시 승인과 허용 성적 | 종류·완료·승인, 규칙에 명시한 허용 성적 |
| `manual_review` | 조건 미확정 요건을 확인 필요로 유지 | 공식 실행본의 custom 요건, 개인 계산 API에서는 직접 지정하지 않음 |

실제 학교 기준이나 성적 환산표는 내장하지 않는다. 테스트와 `--demo`의 기준·문서·기록은
모두 합성 예시다. 자유로운 계산식이나 Python 표현식을 실행하지 않고 허용한 다섯 종류만
Pydantic 판별 union으로 검증한다. 학점·시간·성적 비교는 `Decimal`을 사용한다.
입력 수치는 소수점 6자리·전체 18자리·최대 1,000,000으로 제한하고 계산용 정밀도는
호출자의 Decimal 설정과 분리한다. 이 제한은 내부 데이터 계약이며 학교 기준을 뜻하지 않는다.

## 데이터와 결과

내부 입력은 `RuleSet`, `Snapshot`, `AcademicContext`; 결과는 `Evaluation`이다.
DB 모델이나 공개 API 스키마와는 별개다. UUID 식별자·snake_case·명시적 상태를 사용하고
알 수 없는 필드·음수·NaN·무한대·중복 기록 ID·범위가 잘못된 규칙을 거부한다.
입력은 불변이며 함수는 기록을 수정하거나 질문·답변·개인정보를 저장하지 않는다.

- 기록 목록 `null`은 자료가 없는 상태, `[]`는 비어 있음을 확인한 목록이다. 제공하는 목록은
  해당 종류의 전체 기록 스냅샷이어야 한다. 부분 조회만 가능하면 자료 미확인으로 전달한다.
- 알려진 합계만으로 최소값을 충족하면 `satisfied`; 자료가 완전하고 부족하면
  `not_satisfied`; 불명확한 정보 때문에 계산할 수 없으면 `needs_review`다.
- 알 수 없는 자료를 포함한 합계는 확인된 하한값이다. 이때 부족량은 추정하지 않고
  `deficit=null`로 표시한다. 충족/미충족이 확정된 경우에만 부족량을 계산한다.
- 같은 과목의 완료 기록이 여러 개면 학점 합계에서 제외하고 미확인으로 처리한다.
  어느 재수강 기록의 학점을 반영할지는 학교 정책을 아는 기록 어댑터에서 정규화해야 한다.
  필수과목은 조건을 충족한 이수 시도가 하나라도 있는지 검사한다.
- 성적 척도가 다르면 임의로 환산하지 않는다. `minimum_grade_points`와
  `comparison_grade_scale`은 함께 지정한다.
- 봉사는 `approved` 시간만 합산한다. 대기·검토 중 승인이나 승인 시간 누락은
  확인 필요다. `rejected` 시간은 합산하지 않는다.
- 자격증의 만료일은 해당 날짜까지 유효하다. `validity_known=true`와 `expires_on=null`은
  만료일이 없음을 확인한 경우다. 유효성을 확인하지 못한 자격증은 충족 근거로 쓰지 않는다.
- 논문/캡스톤 완료 여부 `is_completed=null`은 미확인이며 미완료로 바꾸지 않는다. 승인이
  필요한 조건의 명시적 반려 외에는 확인 필요로 유지한다. 다른 확인된 완료 기록이 조건을
  충족하면 그 기록을 근거로 충족할 수 있다.
- 최종 상태는 확정 미충족 요건이 있으면 `not_satisfied`, 그 외에 확인 필요가 있으면
  `needs_review`, 모두 충족하면 `satisfied`다. 세부 결과와 근거 기록 ID를 함께 반환한다.

## 공식 기준과 개인 기준의 경계

`evaluate_personal()`은 개인 규칙만 허용한다. 결과는 항상 `official=false`와
`개인 기준 계산 · 학교 공식 판정 아님`을 포함한다. `evaluate_personal_sources()`는
요건별로 별도의 선택 자료 snapshot을 받아 같은 집계 정책을 적용하며 공식 규칙 입력을
거부한다. 개인 DB 어댑터는 먼저 소유권·버전을 검증하고 결과·조건·계산 입력을 불변 이력으로
저장한다. 개인 규칙은 공식 규칙·공용 RAG 문서를 변경하지 않는다.

`evaluate_official()`은 앞으로 승인된 DB 어댑터가 호출할 내부 함수다. 이 함수가 관리자
신원·공식 URL·승인 권한을 검증하는 것은 아니다. 호출자가 검증된 공식 규칙과 기록을
제공해야 한다. 승인 실행 규칙의 DB 어댑터는 구현했으나 학교 확정 기록 공급자와
공식 판정 공개 HTTP 경로는 아직 없다. 실행본 선택 API의 `catalog_complete`는 항상 false다.
학교 검토 기록의 내부 DB 어댑터는 본인·전체 적용 문맥·동일 기준일의 완전한 승인 자료만
Snapshot으로 전달한다. 원본 철회·회수·무결성/마스터 변경·부분 자료는 미확인 입력이다.
[학교 검토 기록 계약](api/official-student-records.md)을 따르며 이 어댑터는 개인 입력을
공식 기록으로 승격하거나 규정 목록의 완전성을 선언하지 않는다.

- `origin=official`, `approval_status=approved`, 활성·유효기간 조건을 만족한 규칙만 선택한다.
  승인된 공식 규칙의 내부 계약에는 문서 UUID·제목·URL·페이지 근거가 필수다.
- 학교·학과·교육과정 계층에서 적용 가능한 규칙을 **함께** 평가한다. 학교 공통 요건만
  통과했다고 학과·교육과정 요건을 생략하지 않는다.
- 학교/학과/교육과정 ID, 입학연도 구간, 이수경로를 명시한 범위를 대조한다. 알려진 값이
  다른 규칙은 제외하고, 필요한 값이 없으면 `academic_scope_required`와 누락 필드를 반환한다.
- 적용 기간은 시작일·종료일을 모두 포함한다. 같은 범위·코드의 활성 버전이 겹치면
  최신 버전을 임의 선택하지 않고 `ambiguous_rule_set_versions`로 확인을 요구한다.
- 사용한 규칙 묶음 ID·버전·계층·문서 근거를 결과에 보존한다.
- 적용 가능한 공식 규칙이 없으면 `not_applicable`; 규칙 목록의 완전성이 확인되지 않으면
  전체 `needs_review`다. `catalog_complete`는 기본 `false`이고 신뢰할 DB 어댑터만 설정한다.

`official=true`는 내부 계산의 입력 계층을 표시한다. 현재 서비스에 실제 학교의 공식
졸업 판정이 개통되었다는 의미는 아니다. RAG/LLM은 이 계산에 참여하지 않는다.

## 이어진의 독립 실행

`backend/`에서 실행한다.

```bash
uv run --frozen python -m app.rules --demo
uv run --frozen pytest tests/test_rules.py -q
```

개인 입력 파일에는 `rule_sets`, `snapshot`, `evaluated_on`을 넣는다. 실제 값은 저장소 밖의
비공개 디렉터리에서 관리한다. 학생 입력을
팀 예제·테스트 파일에 넣지 않는다. JSON 입력은 최대 256 KiB이고 공식 승인 입력은 거부한다.

```bash
uv run --frozen python -m app.rules --input /비공개/개인기준.json
```

공식 규칙 DB 조회·승인·권한, 원본 성적의 학교별 환산, 재수강 정규화, 감사 저장과
프론트엔드 화면 연결은 별도 구현 단계다. 개인 이력의 물리 DB 스키마는
`0005_personal_evaluations`와 [개인 계산 계약](api/personal-evaluations.md)을 따른다.
