# 학생 직접 추가 학교 정보 UX 기준

이 문서는 학교·학과·교육과정의 공식 데이터가 아직 UniversityPath에 등록되지 않았거나,
학생이 자신의 화면에서 필요한 안내를 찾지 못했을 때 쓰는 **학생 보완 입력**의 UX 기준이다.
학생이 입력한 내용은 학교의 공식 데이터나 다른 학생의 화면을 자동으로 바꾸지 않는다.

## 1. 목표와 경계

- 학생이 서비스를 포기하지 않고 수강·활동·자격·성과 기록을 계속 관리할 수 있게 한다.
- 공식 출처가 있는 안내는 나중에 관리자가 검토할 수 있도록 제목, URL 또는 파일, 페이지,
  적용 범위를 함께 남긴다.
- 개인 메모와 학교 공식 기준을 시각·문구·데이터 상태로 구분한다.
- 졸업요건의 충족·미충족은 공식 학교 데이터가 적용된 Rule Engine만 계산한다. 학생
  입력이나 AI 요약은 그 결과를 변경하거나 대체하지 않는다.

## 2. 학생에게 보이는 입력 상태

| 상태 | 의미 | 화면과 계산에 미치는 영향 |
| --- | --- | --- |
| `개인 참고` | 출처 없이 학생이 적은 계획·메모 또는 본인 기록 | 본인 화면과 AI 문맥에만 사용한다. 공식 기준·졸업 판정에는 사용하지 않는다. |
| `출처 정보 입력됨` | 학생이 학교 공지·규정의 제목과 링크/파일, 범위를 함께 적은 정보 | 본인 참고와 검토 후보로만 보인다. 관리자 확인 전에는 RAG의 공식 근거나 판정에 사용하지 않는다. |
| `검토 요청됨` | 제품에 관리자 검토 흐름이 구현된 경우, 학생이 검토를 요청한 상태 | 요청 이력만 보이며 결과는 여전히 바뀌지 않는다. |
| `공식 반영됨` | 권한 있는 관리자가 원문과 적용 범위를 검증해 학교 데이터로 등록한 상태 | 이후 공식 데이터 파이프라인에서만 사용한다. 학생이 이 상태를 직접 선택할 수 없다. |

상태 칩은 색만으로 구분하지 않고 위 상태명을 그대로 표시한다. `출처 정보 입력됨`을
`확인됨` 또는 `승인됨`처럼 표현하지 않는다.

## 3. 진입점과 기본 흐름

학교 제공 값이 없는 빈 상태에만 보조 행동 **`학교 정보 직접 추가`**를 제공한다. 주요
기록 추가나 학교 시스템 이동보다 더 강조하지 않는다. 이미 공식 데이터가 있으면 같은
행동은 `더보기` 또는 정보 관리 화면에 두어, 공식값을 덮어쓸 수 있다는 인상을 피한다.

입력 화면은 모달 또는 별도 상세 화면에서 다음 순서를 따른다.

1. **무엇이 없나요?** — 교육과정·과목 분류, 졸업 기준 안내, 활동 인정 안내, 학과/프로그램
   안내 중 선택한다. 현재 메뉴에 맞는 항목만 기본 선택한다.
2. **적용 범위** — 학교, 학과, 입학연도, 교육과정 연도를 학생 프로필로 미리 채우고,
   실제 문서의 범위와 다르면 수정하게 한다. 이 수정은 학생 프로필을 변경하지 않는다.
3. **내용** — 짧은 제목과 구조화할 수 있는 값, 원문 설명을 입력한다. AI가 내용을 요약해도
   저장 전 필드별 초안을 학생이 확인·수정한다.
4. **출처** — 문서명, 공식 URL 또는 업로드 파일, 페이지/조항, 게시일 또는 시행일을 받는다.
   출처가 없으면 `개인 참고로 저장`만 가능하고, 검토 요청 행동은 비활성화하며 이유를
   설명한다.
5. **검토 후 저장** — 상태와 영향 요약을 먼저 보인다. 예: “이 정보는 현재 졸업 판정에
   사용되지 않으며, 다른 학생에게 보이지 않습니다.” 저장·검토 요청·취소의 결과를
   명확히 구분한다.

공식 URL은 가능하면 학교 도메인 여부를 보조 안내로 보여 주되, URL 형태만으로 공식성을
확정하지 않는다. 파일은 형식·크기·개인정보 주의와 함께 업로드하고, 원문에 성적·학번 등
불필요한 개인정보가 포함되면 올리지 않도록 안내한다.

## 4. 목록·수정·AI 처리

- 각 입력에는 출처, 적용 범위, 마지막 수정일, 상태를 카드 또는 표에서 함께 보여 준다.
  출처가 없는 개인 참고 정보에는 `출처 없음`을 숨기지 않는다.
- 학생은 본인의 `개인 참고`와 `출처 정보 입력됨`을 수정·삭제할 수 있다. 검토 요청 뒤의
  수정은 요청을 새 버전으로 만들거나 철회 확인을 거치게 하여, 검토 대상이 조용히
  바뀌지 않게 한다.
- AI는 학생 입력을 “학생 제공 참고 정보”라고 표시한 뒤 요약·질문·다음 행동을 제안할 수
  있다. 이를 공식 규정으로 인용하거나 다른 학생에게 재사용하지 않는다.
- 시스템은 공식 데이터가 새로 적용돼도 학생 메모를 지우지 않는다. 공식값과 개인 참고가
  다르면 두 값을 나란히 보여 주고, 공식값이 졸업 판정에 쓰인다는 설명을 붙인다.

## 5. 문구와 오류 상태

권장 안내 문구는 다음과 같다.

> 학교 정보가 아직 준비되지 않았나요? 개인 참고용으로 직접 적을 수 있습니다. 이 입력은
> 학교의 공식 기준이나 졸업 판정을 바꾸지 않습니다.

> 학교 공지나 규정의 출처를 함께 남기면 검토 후보로 보관할 수 있습니다. 검토 전에는
> 공식 근거로 사용되지 않습니다.

필수 범위 또는 출처 정보가 빠졌을 때는 해당 필드에 오류 이유와 수정 방법을 표시하고,
이미 쓴 내용은 보존한다. 학교 데이터 자체가 없는 경우에도 졸업 가능 여부를 추정하지
않고 `공식 기준 미등록`과 다음 행동을 표시한다.

## 6. 구현 전 합의할 사항

- 학생 제출 문서의 보관 기간, 삭제·철회, 관리자 열람 권한과 저작권·개인정보 처리 기준
- 검토 요청 알림과 상태 변경 알림의 제공 여부
- 학생 제출을 어떤 관리자 검증 절차를 거쳐 학교 공식 데이터·RAG 인덱스·Rule Engine
  규칙으로 분리 반영할지
- API 도입 시 개인 참고, 제출 출처, 검토 상태, 공식 데이터의 모델·권한·감사 이력을
  분리할지

이 문서는 UX 정책이다. 실제 API·파일 저장·검토 워크플로·RAG 인덱싱 계약은 팀 합의와
권한·보안 설계 뒤에 별도로 확정한다.
