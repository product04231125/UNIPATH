# UniversityPath AI 특수 목적 AI 및 보조 도구 검토

> 상태: 아키텍처 제안 (도입 확정 아님)
>
> 목적: 일반 생성형 LLM만으로 해결하기보다 문서 처리, 검색, 개인정보 보호,
> 역량 정규화에 특화된 모델·도구를 적절한 경계에서 검토한다.

## 1. 배경

UniversityPath AI의 핵심 품질은 자연어 답변 자체보다 다음의 정확성과 재현성에 크게
좌우된다.

- 학교 공식 규정 문서에서 표·페이지·적용 범위를 보존해 검색하는가
- 사용자 질문과 공고를 한국어·영어 문서 전체에서 관련도 높게 검색하는가
- 학생의 개인정보를 외부 AI 서비스에 불필요하게 전송하지 않는가
- 공고의 표현과 학생 경험의 표현이 달라도 같은 직무 역량으로 비교할 수 있는가

따라서 생성형 LLM은 요건 추출과 근거 기반 설명에 사용하되, 아래 특수 목적 도구를
독립된 어댑터 또는 데이터 처리 단계로 검토한다.

## 2. 후보와 우선순위

| 우선순위 | 유형 | 적용 영역 | 권고 시점 |
| --- | --- | --- | --- |
| 높음 | 문서 파싱·OCR | 학교 규정 PDF·표·스캔 문서의 RAG 수집 | 공식 문서 수집 파이프라인 구현 시 |
| 높음 | 다국어 임베딩·리랭커 | 공식 문서 RAG와 여러 채용공고의 관련도 정렬 | 검색 품질 평가 단계 |
| 높음 | PII 탐지·비식별화 | 외부 AI 호출 전 입력 최소화 | 외부 모델 연동 전 |
| 높음 | NCS 기반 역량 분류체계 | 공고 요건·학사·경험의 스킬 정규화 | 채용 매칭 데이터 모델 구현 시 |
| 중간 | 전용 분류 모델 | 직무군·기술·경력·포트폴리오 요건의 반복 라벨링 | 검증된 라벨 데이터 축적 후 |
| 낮음·실험 | 결정형 AI | A/B 공고 우선 검토·판단 보류 신호 | 기본 매칭 품질 확보 후 |

## 3. 문서 파싱·OCR

학교 학사 규정에는 복잡한 표, 여러 페이지에 걸친 표, 이미지 기반 스캔 문서가 포함될
수 있다. 단순 텍스트 추출은 표의 행·열 관계, 문서 페이지, 조항 위치를 잃을 수 있어
RAG의 검색 품질과 출처 표시를 저하시킨다.

문서 파싱·OCR 도구는 PDF·이미지에서 텍스트, 표, 레이아웃 및 좌표를 추출하고
Markdown 또는 HTML처럼 후속 처리하기 쉬운 형태로 변환한다. 예를 들어 Upstage
Document Parse는 OCR 적용, 복잡한 표 처리, 여러 페이지 표 병합, Markdown/HTML
출력을 제공한다.

```text
공식 PDF 또는 스캔 문서
          ↓
문서 파싱·OCR (페이지·표·레이아웃 보존)
          ↓
정제·청킹·적용 범위 메타데이터 연결
          ↓
Document / DocumentChunk / 출처 정보 저장
          ↓
임베딩·검색·근거 반환
```

- 파싱 결과는 원본 문서와 페이지·좌표를 연결해 검수 가능해야 한다.
- OCR 또는 표 인식 오류는 규칙 데이터에 자동 반영하지 않고 사람 검수를 거친다.
- 졸업요건의 규칙화와 충족 판정은 여전히 `Academic Rule Engine`과 검수된 규칙
  데이터가 담당한다.
- 외부 문서 파싱 서비스를 쓸 경우 문서 저작권, 보관, 처리 위치 및 비용을 확인한다.

## 4. 다국어 임베딩과 리랭커

### 4.1 임베딩

임베딩 모델은 문서와 질의를 벡터로 변환한다. PostgreSQL과 pgvector는 이 벡터를
저장·검색하는 기반이며, 검색 품질은 임베딩 모델의 한국어 및 교차 언어 성능에
영향을 받는다. 후보는 다국어 지원, 문맥 길이, 비용, 자체 호스팅 가능 여부 및
개인정보 처리 조건을 기준으로 평가한다.

### 4.2 리랭커

리랭커는 초기 벡터 검색 결과 또는 공고 후보 목록을 질의와 함께 다시 평가해 더
관련성 높은 순으로 정렬한다. 다음 두 곳에서 활용할 수 있다.

- `School Knowledge RAG`: 후보 문서 청크 중 질문의 학교·학과·교육과정 범위와
  실제로 더 관련 있는 근거를 상단에 배치
- `Job Analysis Module`: 최소화한 후보자 프로필 요약을 기준으로 여러 공고의
  “더 살펴볼 공고” 순위를 정렬

리랭커의 점수는 검색·정렬 신호일 뿐이다. 졸업요건 충족 여부나 채용공고의 명시적
필수 요건 충족 여부를 판정하는 값으로 사용하지 않는다.

## 5. 개인정보 탐지·비식별화

사용자 경험, 프로젝트 설명, 자격증 증빙에는 이름, 연락처, 학번, 자격증 번호 등
개인정보가 포함될 수 있다. 외부 LLM, 임베딩, 리랭커, 문서 파싱 API를 호출하기 전
입력을 최소화하고, 필요하면 PII 탐지·비식별화 계층을 통과시킨다.

Microsoft Presidio는 텍스트·이미지·구조화 데이터의 PII 탐지와 비식별화를 위한
도구 모음이다. 실제 적용 시 한국어 이름, 학번, 학교 이메일, 자격증 번호 등의
인식 규칙을 추가하고, 합성 데이터로 누락·과차단을 검증한다.

```text
사용자 입력 또는 업로드 문서
          ↓
형식·크기·파일명 검증
          ↓
PII 탐지·마스킹 또는 최소 프로필 요약
          ↓
외부 AI 어댑터 호출
          ↓
원본 데이터와 분리한 결과 저장
```

비식별화 결과가 원본과 동일한 개인을 재식별할 수 있게 만드는 방식이거나, 복호화
정보를 로그·캐시·프롬프트에 포함해서는 안 된다.

## 6. NCS 기반 역량 정규화

국가직무능력표준(NCS)은 산업 현장의 직무 수행에 필요한 지식·기술·태도를 표준화한
체계다. 이를 공고와 사용자 데이터를 연결하는 기준 어휘로 활용할 수 있다.

예를 들어 공고의 “Spring Boot 기반 API 개발”과 경험의 “Java 서버 프로젝트”가
표현은 달라도 공통 기술·직무 역량 후보로 연결되도록 한다. 이 연결은 모델의 자유
추측이 아니라, 버전이 있는 직무·역량 사전과 검수된 매핑 규칙을 바탕으로 수행한다.

- NCS 원문·버전·출처와 프로젝트 내부 매핑을 분리해 보존한다.
- 자동 매핑이 모호하면 `needs_review` 또는 사용자 확인 항목으로 반환한다.
- NCS는 채용 합격 가능성을 예측하는 근거가 아니라, 설명 가능한 요건·경험 비교를
  돕는 분류체계다.

## 7. 전용 분류 모델과 결정형 AI

### 7.1 분류 모델

공고의 직무군, 경력 구간, 기술 분야, 포트폴리오 요구 여부처럼 반복되는 라벨은
전용 분류 모델로 대량 처리할 수 있다. Mistral Classifiers API나 Hugging Face의
텍스트·제로샷 분류 모델 및 관리형 엔드포인트가 후보가 될 수 있다.

이 방식은 라벨 정의와 검증 데이터가 축적된 뒤에 도입한다. 학습 데이터가 부족하거나
라벨 경계가 모호하면 생성형 LLM의 스키마 기반 추출과 사람 검수가 더 적절하다.

### 7.2 결정형 AI

JEV와 같은 결정형 API는 상태와 정의된 질문을 입력받아 제한된 선택지, 확률,
신뢰도를 반환한다. 규칙 기반 필수 요건 결과가 비슷한 공고 A/B 중 어느 것을 먼저
검토할지, 또는 사람 검토가 필요한지를 보조하는 데만 검토한다.

결정형 AI는 필수 요건 판정, 졸업 판정, 합격 예측, 자유 형식 설명의 최종 권한을
갖지 않는다. 자세한 채용공고 비교 적용 방안은
[`job-matching-decision-layer-proposal.md`](job-matching-decision-layer-proposal.md)를
따른다.

## 8. 단계별 권고와 공통 검증

1차 MVP에서는 검수 가능한 공식 문서 수집, 학사·자격증 RAG, 결정론적 졸업요건
판정과 개인정보 보호 경계를 우선 완성한다. 이 과정에서 문서 형식이 복잡하거나
스캔 품질이 낮다면 문서 파싱·OCR을 우선 도입한다.

2차 MVP에서는 구조화된 공고 요건, 규칙 기반 매칭, 근거 포함 설명을 도입한다.

3차 MVP 이후에는 한국어 공식 문서 질의와 공고·프로필 쌍으로 임베딩·리랭커를 평가한다.
검색 품질 개선이 확인된 경우에만 채택하고, A/B 비교의 모호한 우대 조건 문제가
남아 있을 때 결정형 AI를 별도 PoC로 비교한다. 전용 분류 모델은 라벨링 데이터와
운영 이점이 충분한 경우에만 검토한다.

모든 후보는 다음을 만족해야 한다.

- 외부 의존성은 FastAPI의 어댑터·설정 계층 뒤에 둔다.
- 장애, 낮은 신뢰도, 입력 부족 시에도 결정론적 결과와 명시적 상태를 반환한다.
- 실제 학생 개인정보 대신 합성 데이터를 사용해 정확도·지연시간·비용·보안 경계를
  검증한다.
- 공급자·모델·비용·약관은 도입 당시 공식 문서로 재확인하며, 특정 공급자를
  핵심 도메인 로직에 고정하지 않는다.
