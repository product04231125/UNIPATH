# 포트폴리오·성과 UX/UI 기준

## 목적

프로젝트, 논문, 수상, 발표, 산출물을 **설명·역할·결과·증빙**으로 묶고 지원 목적에
맞게 재구성하는 메뉴다. 파일 저장소만 되거나, 파일 없이 추상적 성과 문구만 남는 것을
피한다.

## 권장 구성

- 항목은 제목, 유형, 한 문장 요약, 본인 역할, 결과/성과, 기간, 공개 범위, 자료 상태를
  기본으로 가진다. 프로젝트와 수상은 서로 다른 유형이지만 같은 탐색 구조를 쓴다.
- 상세 화면에는 `무엇을 만들었는지`, `내가 한 일`, `결과`, `사용 기술/방법`, `링크·
  첨부`, `공개 가능한 설명`을 구분한다. 파일은 설명을 보강하는 증빙이지 설명의 대체물이
  아니다.
- 목록은 최신순 기본 보기와 유형·공개 여부·목적(채용/학업/개인 정리) 필터를 제공할 수
  있다. 지원 목적별 순서는 원본 기록을 바꾸지 않는 별도 구성으로 저장한다.
- AI는 원본 설명을 바탕으로 요약·자기소개서 문장·포트폴리오 순서를 제안할 수 있으나,
  공개 범위 변경·파일 업로드·항목 추가는 사용자의 확인 뒤에만 반영한다.

## 상태와 상호작용

| 상태 | 표시 방식 |
| --- | --- |
| 초안 | 설명 또는 역할·결과가 부족한 항목임을 표시하고 다음 입력 행동을 제시한다. |
| 자료 필요 | 파일/링크가 없어도 원본 설명은 유지하고, 필요한 증빙 유형을 안내한다. |
| 기록됨 | 원본 항목이 저장된 상태다. 외부 공개 또는 제출 완료와 혼동하지 않는다. |
| 공개 제한 | 비공개 코드·개인정보·계약 자료가 포함될 수 있음을 표시하고 공개용 요약을 분리한다. |

## 학교 제공 정보가 없을 때

- 캡스톤, 논문, 교내 수상, 전시·발표의 제출 형식이나 일정 정보가 없으면 학생은 해당
  공지·양식의 출처와 적용 범위를 포트폴리오 항목에 보조 정보로 추가할 수 있다.
- 학교 안내는 산출물의 공개 가능 여부, 수상·제출 완료, 저작권 허락을 자동으로
  확정하지 않는다. 학생의 설명·증빙과 학교 안내를 별도 영역에 둔다.
- 출처 없는 내용은 개인 체크리스트로만 보이고, 외부 공개 포트폴리오나 공식 경력으로
  자동 내보내지 않는다. 공통 흐름은
  [`../student-contributed-school-information-ux.md`](../student-contributed-school-information-ux.md)를 따른다.

## UI 검토 기준

- 파일 업로드 전 허용 형식·크기·저장 위치·공개 범위를 명확히 안내한다. 파일 하나씩
  추가할 수 있게 하고, 실패해도 항목 설명·다른 첨부를 잃지 않는다.
- 문서·이미지·링크는 미리보기 실패 상태와 외부 링크 이동을 구분한다. 접근 불가한
  링크를 포트폴리오 완료 상태로 보지 않는다.
- 결과는 수상명만 나열하지 않고 산출물, 역할, 검증 가능한 영향 또는 배운 점을 함께
  기록한다. 과장된 AI 표현보다 원본 사실을 우선한다.
