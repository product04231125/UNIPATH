# 경험 UX/UI 기준

## 목적

프로젝트, 인턴, 스터디, 동아리 경험을 취업·진로에 재사용할 수 있는 사실 기반 기록으로
정리하는 메뉴다. 포트폴리오 산출물이나 자격증 자체를 중복 저장하지 않는다.

## 권장 구성

- 경험 카드/상세는 `상황 또는 프로젝트`, `목표/과제`, `내 역할`, `실행`, `결과·배운
  점`, `기간`, `증빙 링크` 순서로 정리한다. 팀 성과와 본인 기여를 같은 문장에 섞지
  않는다.
- 기본 목록은 최신순 타임라인을 사용하고, 진행 중/정리 필요/기록됨 상태로 다음 행동을
  보여 준다. 직무·기술·경험 유형 필터는 기록이 많아진 뒤 제공한다.
- 상세 화면에는 이력서용 짧은 문장, 면접용 STAR/PAR 서술, 포트폴리오 연결을 별도의
  보기로 둔다. 하나의 원본 사실 기록에서 여러 표현을 만들되 원본을 덮어쓰지 않는다.
- AI는 누락된 역할·결과·수치 질문을 제안하고 문장 초안을 만들 수 있다. 사용자의 확인
  전에는 경험 원본이나 이력 문장을 저장하지 않는다.

## 상태와 상호작용

| 상태 | 표시 방식 |
| --- | --- |
| 정리 필요 | 역할·행동·결과 중 빠진 정보와 작성 시작 행동을 표시한다. |
| 진행 중 | 현재 역할과 다음 기록 시점을 보여 주며 성과를 확정하지 않는다. |
| 기록됨 | 사실 원본이 저장된 상태이며, 이력서/면접 문장이 완성됐음을 뜻하지 않는다. |
| 공개 제한 | 비공개 자료·회사 정보가 있는 경우 공개용 서술과 원본 증빙을 분리한다. |

## 학교 제공 정보가 없을 때

- 학생은 학교 연동 여부와 무관하게 경험명, 기간, 역할, 결과, 증빙을 직접 기록한다.
- 경험은 개인 진로·포트폴리오와 AI 문맥에 쓰며, 학교 프로그램 참여나 성과를 자동으로
  인증하지 않는다.
- 학교 안내와 학생의 실제 경험 원본은 별도 필드로 유지한다. 공통 흐름은
  [`../student-contributed-school-information-ux.md`](../student-contributed-school-information-ux.md)를 따른다.

## UI 검토 기준

- 결과를 수치화할 수 없을 때 억지로 숫자를 요구하지 않고, 산출물·피드백·변화처럼
  검증 가능한 대안을 안내한다.
- 이력서용 문장은 능동형·구체적·짧은 형식을 권장하되, AI가 경험을 과장하지 않도록
  원본 사실과 나란히 비교할 수 있게 한다.
- 긴 서술 입력에는 임시저장과 이탈 경고를 제공한다.

## 참고
